## 1. 文档分类体系与权威短名

### 1.1 分类标准（唯一，覆盖全部文档）

所有文档必须落在下列 6 类之一，**不存在「未分类」文档**；类别同时决定目录位置与权威级别：

| 类别 | 目录 | 回答什么问题 | 权威级别 |
|---|---|---|---|
| **需求** | `docs/需求/` | 要做成什么样、验收口径（FR0–FR10） | 低于领域规范 |
| **规范** | `docs/规范/` | 某领域的**可编码契约**（字段、阈值、状态、失败语义） | **最高** |
| **设计** | `docs/设计/` | 结构视图、流程视图、界面结构与交互规格 | 低于规范 |
| **计划** | `docs/计划/` | 何时做、谁做、做到什么程度算完成 | 低于设计 |
| **记录** | `docs/记录/` | 某次实测得到什么（事实与命令输出） | 事实基线，可推翻需求/设计中的假设 |
| **治理** | `docs/治理/` | 元规则：术语、映射、分类、版本与变更流程 | 约束所有文档的写法 |

**判定规则（按顺序命中即止）**：
1. 描述「用户要什么 + 验收标准」→ 需求；
2. 描述「字段/阈值/状态/失败语义等可实现契约」→ 规范；
3. 描述「结构/流程/界面长什么样」→ 设计；
4. 描述「排期与完成判据」→ 计划；
5. 记录「某次实测得到什么」→ 记录；
6. 约束「文档与版本本身怎么写」→ 治理。

**一致性要求**：每份文档头部必须带 `> 分类：<类别> ｜ 目录：<路径>`；新增文档未登记到 §1.2 视为「文档未完成」。

### 1.3 优先级与冲突裁决

1. **技术契约冲突**：规范 > 需求 > 设计 > 计划；

3. **事实冲突**：记录类（`转换路线验证.md`）的实测结论可以推翻需求/设计中的假设，但**必须同步修改被推翻的文档**，不能只留记录；
4. 任何冲突的修复都必须同时更新本文与 `CHANGELOG.md`。

## 2. 术语表

### 2.1 编排与状态

| 术语 | 定义 | 出处 |
|---|---|---|
| **阶段（Stage）** | 8 个固定执行单元：`Prepare`/`Fetch`/`Convert`/`Slim`/`Optimize`/`Integrate`/`Unattend`/`Output` | 编排 §2 |
| **阶段别名（禁用）** | `DetectInput`→`Prepare.probe`、`PrepareImage`→`Prepare.materialize|extract`、`Validate`→`Output.verify`，**三者不再是阶段** | 编排 §2.1 |
| **子步骤（Substep）** | 阶段内部的执行单元，完成即写检查点（如 `Convert.aggregate`） | 编排 §3 |
| **检查点（Checkpoint）** | `work\<task>\checkpoint.json`，记录阶段/子步骤状态与产物哈希 | 编排 §5 |
| **任务记录（TaskRecord）** | `tasks\<taskId>.json` = `TaskConfig` + `runtime` 段；保留最近 50 个 | 编排 §10 |
| **runtime 段** | 任务记录中的运行态：`status`/`startedAt`/`finishedAt`/`result`/`artifactsSummary`/`output_dir`/`staging_dir`/`log_files[]`/`audit_files[]`/`resumed` | 编排 §10 |
| **起始阶段（startStage）** | 用户选择的业务起点，取值 ∈ 8 阶段名，且 ≥ 输入支持的最早阶段；**不取消 `Prepare`** | 输入 §6、配置 §3.2 |
| **配置指纹** | `sha256(canonical_json)`，排除 `meta`/路径/代理，用于判断"同一套业务选项" | 配置 §8.2 |
| **输入指纹** | 输入映像 SHA256 或清单总哈希，变化则从 `Prepare` 重做 | 编排 §6 |
| **settings.defaults** | 全局设置里的「新任务默认值」（严格未知字段/严格上下文/严格失败/卡死阈值）；运行时以 TaskConfig 为准 | 配置 §3.5、GUI-设置 §2.5 |

### 2.2 状态取值（唯一写法）

| 对象 | 取值 |
|---|---|
| 任务 | `draft` / `queued` / `running` / `succeeded` / `failed` / `cancelled` / `interrupted` |
| 阶段 | `pending` / `running` / `succeeded` / `failed` / `skipped` / `cancelled` |
| 子步骤 | `pending` / `running` / `done` / `failed` / `skipped` |
| 下载文件 | `pending` / `downloading` / `downloaded` / `verified` / `failed` |
| 日志级别 | `DEBUG` / `INFO` / `WARN` / `ERROR` / `AUDIT` |

> 禁止同义词（如 `success`、`complete`、`error`、`paused`、`partial` 作为状态值），事件名中的 `result=success|failed|partial` 除外。
> **不存在 `paused`**（本期不支持暂停/继续），也**不存在「部分成功」状态**（= 阶段 `succeeded` + 失败明细 + 退出码 1）。

### 2.3 产物与目录

| 术语 | 定义 |
|---|---|
| **中间产物** | 下载文件、解包树、`install.wim`、挂载展开目录等，位于 `{程序目录}\work\<taskId>\` |
| **暂存区（staging）** | `{输出目录}\.uup2iso-tmp\<taskId>\`，与发布点同卷 |
| **发布点** | 输出目录中的最终文件名，只在校验通过后出现 |
| **伴生文件** | `<name>.iso.sha256` / `<name>.readme.txt` / 可选 `<name>.manifest.json` |
| **媒体骨架** | ISO 中的 `boot\`、`efi\`、`bootmgr`、`setup.exe` 等文件树 |
| **install 映像** | `sources\install.wim|esd`，或工作区 `image\install.wim` |

### 2.4 映像与集成

| 术语 | 定义 |
|---|---|
| **WIM / ESD / SWM** | Windows 映像格式 / 高压缩（LZMS）映像 / 多卷拆分映像 |
| **LP / LIP / FOD** | 语言包 / 语言界面包 / 按需功能 |
| **LCU / SSU** | 累积更新 / 服务堆栈更新（SSU 须先于 LCU） |
| **聚合** | 以基础映像为落点，按映射规则顺序应用 CBS 组件增量，产出 `install.wim` |
| **转换器** | `uup-converter-wimlib`，路线 A 中唯一负责聚合的外部组件（版本锁定） |
| **保守模式** | 工具版本未知时禁用高风险能力（`--ref`、LZMS、引导刷新、未登记 DISM 参数） |
| **能力探测** | 读取工具版本并对照 `rules/engine_caps.yaml` 判定可用能力 |
| **引擎路由** | 按操作查静态表决定主/备引擎（不由运行时能力随机选择） |

### 2.5 规则与工具链

| 术语 | 定义 |
|---|---|
| **规则（rule）** | 一条带 `id`/`level`/`actions`/`verify` 的最小执行单元 |
| **规则库 / 规则包** | `rules/*.json`；`schemaVersion` 描述结构，`packVersion` 描述内容批次 |
| **规则类预设** | `kind=slim|optimize`，`items` = `{ruleIds[], params{}}` |
| **配置类预设** | `kind=integrate|unattend`，`items` = 对应 `TaskConfig` 片段的深拷贝 |
| **执行上下文** | `offline`（挂载映像）/ `firstBoot`（首次登录）/ `online`（本工具不支持，一律跳过） |
| **依赖矩阵** | 包/能力/功能的必需关系（手写硬约束 + 实测观测），含 `blockedCombos` |
| **可逆性（reversible）** | 规则执行后能否仅靠丢弃挂载还原；不可逆项必须写 `recovery` |
| **锁定清单** | `tools\tools.lock.json`，唯一哈希信任根，随包发布；`identitySha256` 按「置空该字段后序列化」计算 |
| **版本对齐** | 原「工具自动更新」：把本地工具对齐到清单登记的版本，**不追上游新版** |
| **四信号看门狗** | 无输出 + CPU 静默 + 进程读写静默 + （网络类工具）网络静默，持续 `hang_warn_minutes` 才告警 |

## 4. 交叉引用校验

### 4.1 扫描口径（三类引用，缺一不可）

| 类型 | 形式 | 解析规则 | 本次数量 |
|---|---|---|---|
| 文件名型 | `日志规范.md` 后接 §编号 | 目标 = 该文件 | 56 |
| 短名型 | `日志`／`引擎`／`规则` 等短名后接 §编号（含 `§3–§8`、`§3/§9` 组合） | 目标 = 本文的短名表 | 697 |
| 同文件型 | 只写 §编号，不带文档名 | 目标 = 当前文件 | 82 |

- 同行的组合写法按「离它最近的文档名」归属，同一段内多个编号依次归属同一目标。
- 判定：目标文件的 `##`–`####` 标题集合中必须存在该编号；缺一即「失效」。
- 说明：本节的示例用「§编号」指代，不写具体数字，避免把示例本身算作引用。

  **837 处（文件名 57 / 短名 697 / 同文件 83），失效 0**（上条 835 为 v1.2 基线值，保留作历史对照）。
