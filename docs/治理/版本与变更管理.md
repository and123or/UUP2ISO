# 版本与变更管理

> 版本：v0.5 ｜ 分类：治理（约定与流程） ｜ 目录：`docs/治理/`

本文档为 `pyproject.toml` 中「版本与变更（强制）」约定的详细说明。

## 1. 版本规则

- 软件版本从 `0.0.1` 起。
- **每一次修改都必须递增版本号**（不接受“内容变更但版本不变”）。
- **版本线现状（避免歧义）**：`0.0.x` 是「只有文档、没有代码」的阶段；文档基线发布沿用 `0.1.x` 序号（如 `0.1.0` = 文档基线 v1.0，`0.1.1` = 本次一致性修复），**它表示基线发布，不代表已有可运行程序**。M1（最小 CLI 可跑通入口 A）发布时才推进到 `0.2.0`。此前「0.1.0 留给 M1」的写法作废——它和已经发出的 `0.1.0` 文档基线冲突。

## 2. 运行环境（强制）

- 本仓库**所有脚本（开发、测试、构建、打包、自动化代理）一律在工作空间根目录的虚拟环境 `.venv` 中运行**，禁止使用系统 Python 主环境。
- 解释器版本：**Python 3.12–3.13（x64）**，`pyproject.toml` 的 `requires-python` 为 `>=3.12,<3.14`。
  3.14 当前不可用（PySide6 无 3.14 wheel），解压即用的判断口径是「`pip install` 能装齐依赖栈」，而不是版本号高低。
- 首选一键脚本（内部即执行下述步骤，并额外做环境自检与依赖快照）：

  ```
  powershell -ExecutionPolicy Bypass -File scripts\bootstrap.ps1
  powershell -ExecutionPolicy Bypass -File scripts\bootstrap.ps1 -NoUpgrade -SkipTests   # 环境已就绪时重跑
  ```

- 首次初始化（工作空间根目录）：

  ```
  python -m venv .venv
  ```

- 之后统一以 `.venv\Scripts\python` 执行一切命令，例如：

  ```
  .venv\Scripts\python -m pip install -e ".[dev]"
  .venv\Scripts\python -m pytest
  .venv\Scripts\python -m ruff check .
  .venv\Scripts\python -m PyInstaller uup2iso.spec
  ```

- 禁止任何不带 `.venv` 前缀的全局 `pip install` 或脚本运行；CI 与自动化代理同样必须先创建并使用工作空间 `.venv`。
- **PowerShell 脚本编码（实测坑，M0 已踩）**：`scripts/*.ps1` 必须保存为 **UTF-8 with BOM + CRLF**。
  Windows PowerShell 5.1 对无 BOM 的 `.ps1` 按系统 ANSI（cp936）解码，中文注释变乱码后**直接破坏语法**
  （实测报 `引用运算符后面缺少属性名称`）。改脚本后用
  `python -c "import pathlib;p=pathlib.Path('scripts/x.ps1');p.write_text(p.read_text(encoding='utf-8-sig'),encoding='utf-8-sig',newline='\r\n')"`
  复核 BOM。

## 3. 必须同步修改的位置

修改版本号时，以下三处必须同时更新，否则视为不合规：

| 位置 | 字段 |
|---|---|
| `pyproject.toml` | `[project] version` |
| `src/uup2iso/__init__.py` | `__version__` 常量 |
| `tests/test_version.py` | 版本断言（与 `pyproject.toml` 一致） |

> **适用前提**：这三处随 M0 脚手架一起建立。在此之前（纯文档阶段）版本同步只落 `CHANGELOG.md`；M0 建好后，本节规则立即生效，且 CI 应校验三处一致。
> 注：发布产物（PyInstaller exe）的文件/产品版本在打包时从 `pyproject.toml` 读取，无需单独维护。
>
> **改版本后必须重装一次**：editable 安装的版本元数据在安装时写入 `*.dist-info`，只改 `pyproject.toml`
> 不会自动刷新。递增版本后需执行 `.venv\Scripts\python -m pip install -e . --no-deps`，
> 否则 `tests/test_version.py::test_installed_metadata_matches` 会以「安装态 0.1.x ≠ 期望 0.1.y」失败
> （M0 实测踩到，`scripts/check.ps1` 会拦下）。

## 4. 变更记录（CHANGELOG.md）

- 仓库根目录 `CHANGELOG.md` 为唯一变更记录入口。
- 每次修改必须新增一条版本记录，内容按以下小节归类：
  - **新增**：新增能力/文件/接口。
  - **变更**：行为或默认值调整。
  - **修复**：缺陷修复。
  - **已知限制**：本期未实现或受限的能力（避免读者误判为可用）。
- 记录使用中性、可核对的事实描述，不夸大完成度。

## 5. 与阶段计划的关系

- 版本记录应与 `docs/计划/项目计划.md` 的里程碑（M0–M4）对应，注明处于哪个里程碑。
- 阶段未完成时，`已知限制` 必须写明“对应阶段明确失败，不静默成功”。

## 6. 自动化代理要求

自动化代理（含 AI Agent）在本仓库内做任何代码或文档修改时：

1. 先递增版本号（第 3 节的三处）。
2. 再在 `CHANGELOG.md` 顶部新增记录。
3. 最后在**工作空间 `.venv` 虚拟环境**内执行 `python -m pytest`（以及 `ruff check`、`mypy`）验证；不得在系统 Python 主环境中执行。
