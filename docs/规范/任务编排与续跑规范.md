# UUP2ISO 任务编排与续跑规范

> 版本：v0.3
> 分类：规范（领域规范） ｜ 目录：`docs/规范/`
> 依据：`需求分析.md` FR0（多入口与阶段）、FR9.1（任务配置与续跑）、FR9.2（最小 CLI）
> 配套：`预设与配置契约规范.md`（`TaskConfig`）、`输入识别与映像准备规范.md`（起始阶段）、`输出校验与原子性规范.md`（复用四条件）、`外部工具与进程执行规范.md`（取消与错误码）
> 优先级：本文与其它文档中关于「阶段怎么跑、失败怎么重、续跑从哪开始」的描述冲突时，**以本文为准**。

## 1. 目的

把「一个任务怎么从输入走到产物」定义成可执行、可中断、可续跑的状态机。本文回答五个问题：

1. 有哪些**阶段**、每个阶段的产物是什么；
2. 检查点记到多细（**决定崩溃后少做多少工作**）；
3. 哪些失败可以**自动重试**、重试几次；
4. 用户**取消**后留下什么；
5. **续跑**时怎么判断「哪些已完成、可以跳过」。

**核心原则**：任何阶段都必须能在**不确定的中间状态**下安全恢复——宁可重做，不可复用可疑产物。

## 2. 阶段模型（8 阶段）

| # | 阶段 | 输入 | 产物 | 前置条件 | 何时跳过 |
|---|---|---|---|---|---|
| P0 | `Prepare` | 输入路径（UUP 文件夹 / ISO / WIM / ESD） | `probe.json`、`image\`（解包或物化后的映像树） | 输入判定通过（输入规范 §2） | **永不整段跳过**；入口 B 且已下载完成时缩减为只读校验（`probe` + `selfcheck`） |
| P1 | `Fetch` | 清单 + 下载参数 | `uup\`（全部文件，SHA1 已验） | 入口 A/B 且清单有效 | 入口 C；或 `uup\` 全部 `verified` |
| P2 | `Convert` | `uup\` 或 ESD | `image\install.wim`（+ 骨架、`boot.wim`） | `Fetch` 完成（或入口 C 的 ESD 物化） | 输入已是可编辑 WIM 且无需转换 |
| P3 | `Slim` | `install.wim` | 精简后的 `install.wim` | `Convert` 完成或输入为 WIM | 未选任何精简项 |
| P4 | `Optimize` | `install.wim` | 优化后的 `install.wim` | `Slim` 完成（或跳过） | 未选任何优化项 |
| P5 | `Integrate` | `install.wim` + 集成项 | 集成后的 `install.wim` | `Optimize` 完成（或跳过） | 无更新/驱动/语言包 |
| P6 | `Unattend` | `install.wim` + 应答设置 | `install.wim`（注入）/ `autounattend.xml` | `Integrate` 完成（或跳过） | 未启用无人值守 |
| P7 | `Output` | 映像 + 媒体骨架 | 最终产物 + 伴生文件 | 上一阶段完成 | 不产出（dry-run） |

- 阶段顺序**固定**，不允许乱序；跳过的阶段记 `status=skipped` 并写原因（`reason=no_options|input_satisfied`）。
- 阶段与里程碑、规范的对应关系：P0→输入规范、P1→下载规范、P2→引擎规范、P3/P4→FR3-FR5、P7→输出规范。

### 2.1 阶段名的唯一性与历史别名（强制）

**8 个阶段名是唯一写法**，任何文档、日志字段、UI 阶段串、检查点都只能使用上表的名字。历史文档中出现过的三个名字**降级为子步骤动作或能力名**，不再作为阶段：

| 历史名 | 现归属 | 说明 |
|---|---|---|
| `DetectInput` | `Prepare.probe` 子步骤 | 输入类型嗅探与冲突判定（输入规范 §2） |
| `PrepareImage` | `Prepare.materialize` + `Prepare.extract` 子步骤 | ESD 物化 / ISO 解包 / 只读引用（输入规范 §7） |
| `Validate` | `Output.verify` 子步骤 | 产物分级校验（输出规范 §6） |

- 日志的阶段字段写 `stage=Prepare` / `stage=Output`，具体动作写 `substep=probe|materialize|extract|verify`；
- 「输出校验」不是独立阶段：它发生在 `Output.verify`，失败即 `Output` 阶段失败（退出码 2）。
- 新文档禁止再引入第 9 个阶段名；确有必要时，只能新增子步骤（本节同表登记）。

## 3. 子步骤检查点（已决策 D1）

阶段对外保持 8 个（UI 阶段串不膨胀），但**阶段内部按子步骤记检查点**，续跑时按子步骤跳过。

| 阶段 | 子步骤（顺序） | 幂等性 | 完成标志 |
|---|---|---|---|
| `Prepare` | `probe` → `materialize`（ESD→WIM）→ `extract`（ISO 解包）→ `selfcheck` | 幂等 | `probe.json` 存在且 `selfcheck=ok` |
| `Fetch` | `manifest` → `download` → `verify` | 幂等 | 全部文件 `verified` |
| `Convert` | `config` → `cab` → `aggregate` → `skeleton` → `bootwim` | `aggregate` 幂等（重跑覆盖 `install.wim`）；其余幂等 | `install.wim` 可读 + 骨架齐全 |
| `Slim` | `mount` → `apply` → `unmount` | **非幂等**（挂载有状态） | 映像已提交且无残留挂载 |
| `Optimize` | `mount` → `offline-reg` → `cleanup` → `unmount` | **非幂等** | 同上 |
| `Integrate` | `mount` → `updates` → `drivers` → `language` → `registry` → `verify` → `unmount` | **非幂等**（挂载有状态） | 同上 |
| `Unattend` | `generate` → `validate` → `mount`（仅注入时）→ `inject` → `unmount` | `generate`/`validate` 幂等；`inject` 非幂等（挂载） | XML 通过 XSD 校验；（若选择注入）已注入并卸载 |
| `Output` | `assemble` → `package` → `verify` → `commit` | `commit` 幂等（已提交则跳过） | 产物已落位 + 伴生完成 |

**规则**：

1. 子步骤**完成即写检查点**，不等阶段结束（避免 40 分钟的 `aggregate` 白做）。
2. 标「非幂等」的子步骤（`mount`/`unmount` 系列）：重跑前必须**检测并清理挂载残留**（引擎规范 §7）；检测失败则整个阶段重做。
3. 子步骤粒度不对外暴露，UI 只在阶段详情里展示；进度按子步骤加权到阶段百分比。

## 4. 状态机

### 4.1 任务态

取值与《术语表与文档映射》§2.2 完全一致（小写、唯一写法）：

```
draft → queued → running → succeeded
                    ├→ failed
                    ├→ cancelled（可 resume）
                    └→ interrupted（进程消失，可 resume）
```

- `draft`：向导进入即创建（`GUI交互规格-向导页.md` §1.6），不可执行；「开始」时转 `queued`。
- `queued`：已提交执行、等待单实例锁与阶段计划；本工具同一时刻仅一个任务在跑，因此 `queued` 通常只存在毫秒级。
- 终态：`succeeded` / `failed` / `cancelled`；`failed` 与 `cancelled` **允许**通过 `--resume` 转回 `running`（新进程、新 `run_*.log`）。
- `interrupted` 由下次启动检测：检查点 `status=running` 但无进程持有单实例锁 → 标 `interrupted`。
- **不存在 `paused` 状态**：本期不支持暂停/继续（见 §13 开放问题），暂停语义只能通过「取消 + 续跑」实现。

### 4.2 阶段态与子步骤态

| 层 | 取值 |
|---|---|
| 阶段 | `pending` / `running` / `succeeded` / `failed` / `skipped` / `cancelled` |
| 子步骤 | `pending` / `running` / `done` / `failed` / `skipped`（阶段内跳过） |

- 阶段失败时，已 `done` 的子步骤**保留**（续跑从这里继续）。
- 阶段被重试时，**从第一个非 `done` 的子步骤**开始；若上次失败在 `mount`，先清理残留。

## 5. 检查点文件

`{程序目录}\work\<task_id>\checkpoint.json`：

```json
{
  "schemaVersion": "1.0",
  "taskId": "7f3a1c02",
  "configFingerprint": "3f9c…",
  "inputFingerprint": "a71b…",
  "status": "running",
  "currentStage": "Convert",
  "startedAt": "2026-10-30T12:00:00+08:00",
  "updatedAt": "2026-10-30T12:26:13+08:00",
  "stages": {
    "Fetch":   { "status": "succeeded", "attempts": 1, "finishedAt": "…" },
    "Convert": { "status": "running", "attempts": 1,
                 "substeps": { "config": "done", "cab": "done", "aggregate": "running" } }
  },
  "artifacts": [
    { "stage": "Convert", "name": "install.wim", "path": "image\\install.wim",
      "size": 5123456789, "sha256": "…", "reusable": true }
  ]
}
```

- **原子写**：写 `checkpoint.json.tmp` → `os.replace`（与输出规范 §3 一致），避免断电产生半截 JSON。
- **写时机**：阶段开始/成功/失败、子步骤开始/完成、运行中每 60 秒心跳（`updatedAt`）。
- **唯一写者**：单实例保证同一时刻只有一个进程写检查点。

## 6. 幂等与复用判定

某阶段/子步骤的产物可复用，必须**同时**满足下列四条（**唯一定义在本节**，输出规范 §7.3 只是同一组条件的「产物视角」表述，不得另立标准）：

1. `configFingerprint` 与当前配置一致；
2. `inputFingerprint` 一致（输入映像的 SHA256 或清单总哈希）；
3. 检查点中该阶段/子步骤 `succeeded`/`done`；
4. 产物存在，且大小与 SHA256 与记录一致。

任一不满足 → **重做该阶段**。补充规则：

- `configFingerprint` 不一致 → **拒绝续跑**（提示「配置已变更，请新建任务或恢复原配置」），不允许混用两套配置的中间产物。
- `inputFingerprint` 不一致 → 从 `Prepare` 重做（输入变了，后续产物全部无效）。
- `.part`、`*.tmp`、未登记在 `artifacts` 的文件**永不参与复用**。

## 7. 重试策略（已决策 D2）

### 7.1 白名单

| 错误 | 层级 | 可重试 | 上限 | 退避 | 备注 |
|---|---|---|---|---|---|
| 网络超时/断流 | 子步骤 | ✅ | 3 | 2/4/8 s | 由 aria2c 或上层完成，见下载规范 |
| 文件被占用（共享冲突） | 子步骤 | ✅ | 3 | 5 s | 常见于杀软扫描、资源管理器预览 |
| 工具瞬时失败（已知可恢复错误类别） | 子步骤 | ✅ | 2 | 5/15 s | 可重试类别见引擎规范 §10（错误语义表）与进程规范 §9.1（内部错误类别） |
| 校验不通过（哈希/结构） | 子步骤 | ✅ | 2 | 0 | 重做该子步骤（如重新导出） |
| **阶段级兜底** | 阶段 | ✅ | **2** | 30 s | 子步骤重试耗尽后自动重试整阶段；每次记 `stage_retry` |
| 配置错误（`CONFIG_*`） | — | ❌ | — | — | 用户必须先改配置 |
| 输入问题（`INPUT_*`） | — | ❌ | — | — | 加密/多卷/损坏属确定性失败 |
| 磁盘空间不足（`DISK_FULL`） | — | ❌ | — | — | 清理后由用户重跑 |
| 跨卷（`OUTPUT_CROSS_VOLUME`） | — | ❌ | — | — | 需要改输出位置 |
| 转换器失败（非占用类） | — | ❌ | — | — | 输出不可解释，不做无意义重跑 |
| 用户取消 | — | ❌ | — | — | 由用户决定是否 `--resume` |

### 7.2 重试前的清理

- 重试阶段前，删除该阶段**未完成**的产物（保留 `done` 子步骤的产物），避免「脏产物被当成品」；
- 挂载类阶段重试前必须先 `Dism /Cleanup-Wim`（引擎规范 §7）；
- 每次重试记 `event=stage_retry stage=<s> attempt=<k> reason=<...>`。

## 8. 取消语义（已决策 D3：保留并提示）

1. 用户取消 → 当前工具进程按进程规范 §7.1 终止（Ctrl-Break → terminate → 强杀树）；
2. 阶段标 `cancelled`，子步骤保留 `done` 状态；
3. **中间产物一律保留**（下载文件、`install.wim`、解包树）；
4. 任务态 `Cancelled`，退出码 3；
5. 二次取消（正在取消中再按一次）→ 跳过等待，立即强杀，记 `WARN cancel_forced`。

**清理是显式动作**：GUI 在任务详情提供「清理本次中间产物」；CLI 不提供命令（保持最小命令集），用户可删 `work\<task_id>\` 目录。清理范围**只限该任务目录**，不触碰输出目录的最终产物。

## 9. 续跑流程

```
读 checkpoint.json
  ├─ 文件缺失            → 视为新任务，从 P0 开始
  ├─ 指纹不一致          → 拒绝续跑（CONFIG_CHANGED / INPUT_CHANGED）
  ├─ 状态 = succeeded    → 提示「已完成」，不重复执行
  ├─ 状态 = running      → 标记 interrupted，按中断处理
  └─ 否则                → 逐阶段校验复用条件
        ├─ 四条件全满足 → 复用（标 reused）
        └─ 任一不满足   → 从该阶段起点重做
```

- `--resume` 与 GUI「继续上次」等价；新进程、新 `run_*.log`、同一 `taskId`。
- 续跑前打印/展示「将复用 N 个产物、重做 M 个阶段」的清单（`--dry-run` 同样输出）。
- 续跑不得改变 `taskId` 与 `configFingerprint`；若用户改了配置，必须新建任务。

## 10. 任务记录与保留（已决策 D4：最近 50 个）

- 任务记录 = `TaskConfig` + `runtime` 段，存于 `tasks\<taskId>.json`。`runtime` 段必须包含：
  - 基本：`status`、`startedAt`、`finishedAt`、`result`、`artifactsSummary`；
  - 路径：`output_dir`、`staging_dir`（输出规范 §7.2 的残留检测依赖它们）；
  - 会话：`log_files[]`、`audit_files[]`、`resumed`（日志规范 §7.3 的诊断包按任务取日志依赖它们）。
- **保留策略**：按 `finishedAt`（未完成的按 `startedAt`）保留最近 **50** 个；超出时从最旧开始清理。
- 清理动作：删记录 + 删 `work\<taskId>\`（含检查点与中间产物）+ 清理该任务在输出目录的暂存残留（输出规范 §7）。
- **不清理**：用户输出目录中的最终产物与伴生文件。
- 清理记 `event=task_record_pruned task=<id> reason=retention`；正在运行的任务**永不**被清理。
- 用户可在任务列表手动删除单个任务记录（同样只删中间物，不删最终产物）。

## 12. 验收标准

1. **子步骤续跑**：在 `Convert.aggregate` 完成后强杀 → 续跑从 `skeleton` 开始，`aggregate` 标 `reused`，不再调用转换器。
2. **阶段级兜底重试**：让某阶段连续失败（可恢复错误）→ 自动重试 2 次后停下，日志有 2 条 `stage_retry`，退出码 2。
3. **不可重试直停**：配置错误 → 不重试、退出码 4，日志无 `stage_retry`。
4. **取消保留**：转换中取消 → `work\<task>\image\install.wim` 保留，任务态 `cancelled`，退出码 3；`--resume` 后跳过 `Convert`。
5. **指纹拒绝**：改配置后 `--resume` → `CONFIG_CHANGED` 拒绝，提示新建任务，不产生任何产物。
6. **输入变更**：替换输入 ISO（SHA256 变化）后 `--resume` → 从 `Prepare` 重做，日志有 `artifact_reused` 缺失。
7. **挂载残留**：在 `Slim.mount` 后强杀 → 续跑检测到残留并清理，再继续；清理失败则整阶段重做。
8. **检查点原子性**：在写检查点瞬间强杀（模拟）→ `checkpoint.json` 仍可解析（不出现半截 JSON）。
9. **任务记录保留**：构造 51 个已完成任务 → 最旧的记录与其 `work` 目录被清理，输出目录的产物**未**被删。
10. **跳过阶段**：不选任何精简项 → `Slim` 标 `skipped reason=no_options`，进度不含该阶段耗时。
11. **dry-run**：`--dry-run` 输出「将执行的阶段 + 将复用的产物」，不写检查点、不创建 `work` 目录。
12. **中断标记**：进程被任务管理器强杀 → 下次启动任务列表显示「已中断，可继续」。

## 13. 开放问题

- [ ] 是否支持「暂停/继续」（不杀进程、仅挂起），当前只支持取消后重跑。
- [ ] 阶段级自动重试 2 次是否需要可配置（当前固定，避免用户调成无限重试）。
- [ ] 检查点心跳 60 秒是否足够（对 40 分钟单步任务影响不大，但对秒级阶段偏密）。
- [ ] 任务记录 50 个上限是否需要在设置中可调。
- [ ] 是否提供「从产物重建任务记录」（用户手工保留 ISO 后想追溯当时配置）。
