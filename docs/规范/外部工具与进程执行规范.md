## 1. 目的与职责边界

`ProcessRunner` 是唯一允许创建外部进程的组件（FR3-FR5 §5.2），它只负责**执行与观测**，不负责业务判断。

| 属于 ProcessRunner | 不属于 ProcessRunner（归阶段/引擎） |
|---|---|
| 启动进程、注入参数、工作目录 | 决定调用哪个工具、传什么业务参数 |
| 双路读取输出、解码、行分类 | 判定操作是否成功（业务语义） |
| 上报进度事件、写 start/finish 日志 | 清理临时文件、回滚挂载点 |
| 取消、终止进程树、**多信号静默看门狗**（输出/CPU/磁盘/网络） | 重试策略（由阶段决定是否重跑） |
| 工具定位、版本与能力探测 | 决定缺失工具时是阻断还是降级 |

**硬约束**：任何模块不得直接 `subprocess` / `os.system` / `Popen`；违反即视为实现缺陷。

## 2. 工具清单与定位

### 2.1 定位优先级

```
程序目录\tools\<exe>  →  设置中的显式路径  →  系统 PATH  →  报错（不静默降级）
```

- 只接受**文件名白名单**内的可执行文件；白名单随包发布，配置中的自定义路径必须命中白名单且完成 SHA256 校验（若配置了期望值）。
- 定位结果与来源（`tools_dir` / `settings` / `path`）写入 start 日志的 `source=` 字段。

### 2.2 工具表

| 工具 | 用途 | 必需性 | 版本探测命令 | 备注 |
|---|---|---|---|---|
| `aria2c.exe` | 唯一内容下载器（FR2） | 入口 A 必需 | `aria2c --version` | 可自动获取（FR2.2），获取后 SHA256 校验 |
| `7z.exe` / `7za.exe` | CAB/ISO 解包 | 必需 | `7z i` | 仅解包；不用于 WIM/ESD |
| `wimlib-imagex.exe` | WIM/ESD 读写、导出、校验 | 必需 | `wimlib-imagex --version` | 支持 `apply/export/verify/info` |
| `Dism.exe` | 精简/优化/集成/组件清理 | 必需（系统内置） | `DISM /Version` | 需管理员；非管理员时明确拒绝而非失败重试 |
| `oscdimg.exe` | ISO 封装（FR3.7） | 可选，缺失时提示安装 ADK | **无版本参数** → 读 PE 版本资源（FileVersion） | 缺失不阻断启动，仅在 Output 阶段阻断 |

**IO 画像**（`io_profile`，供 §7.2 看门狗判定使用）：

| 工具 | io_profile | 说明 |
|---|---|---|
| `aria2c` | `network+disk` | 网络下载为主，落盘为辅 |
| `wimlib-imagex` | `disk` | 读源 WIM/ESD、写目标文件，CPU 占比低 |
| `7z` | `disk` | 解包为主 |
| `DISM` | `disk+cpu` | 组件操作重 IO，部分操作耗 CPU |
| `oscdimg` | `disk+cpu` | 读源目录、写 ISO |

### 2.3 版本与能力探测

- 启动自检时执行版本探测，**单次探测超时 10 秒**；超时或解析失败记 `WARN`，标记 `version=unknown`。
- 版本未知时进入**保守能力模式**：不启用依赖特定版本的增强能力（如 `--ref` 分片导出、`LZMS` 导出），但**不阻断启动**；必需工具完全缺失才阻断（FR10.3）。
- 能力探测结果缓存到 `{程序目录}\config\tool_caps.json`（键：工具名 + 版本 + 探测时间），工具文件 mtime/大小变化即失效重探。

### 2.4 权限

- `Dism.exe` 需要管理员：启动自检即检测令牌，非管理员时在任务开始前给出「请以管理员运行」并返回退出码 4，**不允许跑到一半才失败**。
- 其余工具不要求提权；若因权限失败（如访问 `System Volume Information`），按工具退出码映射为 `PERMISSION_DENIED` 并附原码。

## 3. 进程启动契约

| 项 | 规定 |
|---|---|
| 参数 | `args: list[str]`，**严禁 `shell=True`**；路径与含空格/中文参数由 Python 直接传递，不手工拼接引号 |
| 标准输入 | `stdin=DEVNULL`（杜绝工具等待输入导致挂起） |
| 标准输出 | `stdout=PIPE`、`stderr=PIPE`，**两路并发读取**（见 §4） |
| 窗口 | `CREATE_NO_WINDOW`（不弹黑框） |
| 进程组 | `CREATE_NEW_PROCESS_GROUP`（支持向整组发送 Ctrl-Break 与树终止） |
| 工作目录 | 显式传入；默认任务工作目录，禁止使用程序目录（防止工具在程序目录写垃圾） |
| 环境变量 | 继承系统环境；**代理、密钥等敏感值通过参数传递，不注入 env**（避免泄露到子进程与日志） |
| 并发上限 | 见 §8 |

## 4. 输出读取与解码

### 4.1 双路并发读取

- 用 `asyncio.create_subprocess_exec` 启动，`asyncio.create_task` 分别读取 stdout 与 stderr；每行立即处理，**不缓存整份输出**（避免大输出爆内存）。
- 事件按**到达时间**（毫秒）排序进入事件队列；同一毫秒内 stdout 优先。
- 每行带 `channel=stdout|stderr`（写入日志的 `line`/`result` 行与错误详情）。
- 超长行（> 64 KB，常见于无换行的二进制噪声）截断并标记 `truncated=true`、记录原始字节数。
- 流结束前若无换行的残留数据，作为最后一行上报（`partial=true`）。

### 4.2 编码与回退链

- 逐工具注册默认编码：`Dism` → `cp936`、`7z` → `cp936`、`aria2c` → `cp936`、`wimlib-imagex` → `utf-8`、`oscdimg` → `cp936`。
- 单行解码失败时按 **`utf-8` → `cp936` → `latin-1`** 顺序重试；使用成功的那一档，并在该行键值对记 `encoding=<实际编码>`；`latin-1` 为兜底（永不失败，但可能乱码，需在日志中可见）。
- 同一进程内若 `errors` 连续超过 20 行，记一条 `WARN decoding_fallback tool=<t> encoding=<e>`，便于发现编码配置错误。
- 原始字节不落盘（日志为纯文本），仅在错误详情中保留首 256 字节的十六进制转储（`hex=<...>`），用于定位非法字节。

## 5. 行分类：progress / line / result

### 5.1 三类定义

| 类别 | 含义 | 去向 |
|---|---|---|
| `progress` | 进度条、百分比、速度/ETA、重绘行 | **只更新进度模型**，不写日志（日志规范 §5.2） |
| `result` | 结果性语句：成功/失败总结、导出完成、包安装结果 | 写日志 + 可作为阶段结论依据 |
| `line` | 其余普通输出（含警告、诊断信息） | 写日志（受采样约束） |

### 5.2 判定顺序（正则表优先，严格兜底）

1. 命中**结果正则** → `result`；
2. 命中**进度正则** → `progress`；
3. 未命中且工具版本**已登记** → `line`；
4. 未命中且工具版本**未登记**（`version=unknown`）→ 严格兜底：**同时**满足「含 `%` 或含回车重绘特征」且「不含 `ERROR`/`Failed`/`失败`/`错误`」才判 `progress`，否则 `line`。

> 兜底必须「严格」：宁可把进度当普通行记进日志，也不能把错误行当进度丢掉（FR9.3 可定位性优先）。

### 5.3 正则表

- 存放在 `rules/process_patterns.yaml`，随包发布，按「工具 + 版本区间」组织；示例：

```yaml
aria2c:
  ">=1.36,<2":
    progress:
      - '^\[#\w{6}\s+[\d.]+[KMG]?iB/[\d.]+[KMG]?iB\(\d+%\)'
      - '\[DL:[\d.]+[KMG]?iB\]'
    result:
      - 'Download Results:'
      - 'Status Legend:'
dism:
  "*":
    progress:
      - '^\[\s*=+\s*\d+(\.\d+)?%\s*\]'
      - '^\s*\d+(\.\d+)?%\s*$'
    result:
      - 'The operation completed successfully'
      - '操作成功完成'
wimlib-imagex:
  "*":
    progress:
      - '^(Writing|Scanning|Archiving|Extracting)\b.*\b\d+%'
    result:
      - '^Successfully (exported|applied|captured)'
oscdimg:
  "*":
    progress:
      - '^\s*\d+%'
    result:
      - 'OSCDIMG 2\.\d+'
```

- 正则表变更必须有**输出夹具**（§10）配套，否则不允许合并。

> **落地状态（v0.4，M0 / WP0-T5）**：上述正则的 YAML 文件尚未引入——YAML 解析需要额外依赖，
> 而 `pyproject.toml` 的依赖清单（WP0-T2）未包含。当前实现把本节正则**内置为 Python 常量**
> （`infrastructure/process/classifier.py` 的 `DEFAULT_PATTERN_SOURCE`），并保留
> `LineClassifier.from_mapping()` 作为将来从规则文件加载的入口。
> 待规则库任务（WP0-T9 / WP11-T5）一并决定是否引入 YAML 依赖后，本节恢复为单一文件来源。
> 夹具已按本节正则编写（`tests/fixtures/process/`），可直接作为迁移后的回归基线。

## 6. 进度模型与上报

- 事件结构：`StageEvent{task, stage, tool, kind, percent, sub_percent, message, channel, ts}`。
- 进度**单调不减**：同一 `(task, stage, tool)` 内若新值小于旧值按旧值处理（工具重绘/回退不导致进度条倒退）；阶段切换时重置。
- 转换为阶段百分比：`stage_percent = base + weight × tool_percent`（权重由阶段定义），无进度信息的工具按「已耗时/预估耗时」估算，但**只在 GUI 显示**，不进日志。
- **节流**：对 UI 的上报不超过 5 次/秒（≥200 ms 间隔）；文件日志不记录进度，故无节流问题。
- 阶段完成时必须显式上报 `100%` 与 `result` 事件，避免进度条停在 97%。

## 7. 取消、终止与静默看门狗

### 7.1 取消流程（用户主动）

```
发送 CTRL_BREAK_EVENT（整组）
  → 等待 5 秒
  → 仍存活：terminate() 整组
  → 再等 2 秒
  → 仍存活：强制终止进程树（taskkill /T /F 或等价实现）
```

- **控制台前提（关键）**：`CTRL_BREAK_EVENT` 只能投递给「同一个控制台会话」内的进程。GUI 进程（`pythonw`/窗口子系统）默认**没有控制台**，且我们同时用 `CREATE_NO_WINDOW` 启动子进程，此时 `GenerateConsoleCtrlEvent` 会失败、第一步是空转。因此：
  - GUI/无控制台场景：**跳过第一步**，直接从 `terminate()` 开始（等待 2 秒后强杀），并把「是否具备控制台」写进 `cancel` 事件（`console=none`）；
  - 具备控制台时（CLI 从 cmd/PowerShell 启动）按上面的四步走；
  - 该分支必须在 M0 用真实 GUI 进程实测确认，不得默认第一步可用。
- 记录 `event=cancel tool=<t> stage=<s> elapsed=<..> console=<yes|none>`；返回内部码 `3`（用户取消）。
- 拉起的孙进程（如 aria2c fork 的校验进程）一并终止；终止后由阶段负责清理临时文件与卸载挂载点。
- 取消**不视为失败**：不写 ERROR，不阻断 `--resume`。

### 7.2 静默看门狗（疑似卡死）

**为什么不能只看 CPU**：本工具的主要耗时步骤是下载与映像读写，CPU 占用经常很低（DISM/wimlib 大量时间是 IO 等待，aria2c 是网络等待），只看 CPU 会把「正在搬数据」误判成「卡死」。因此判定采用**四信号联合**。

**判定条件**：连续 `hang_warn_minutes`（默认 **10 分钟**）内**同时**满足以下四条，才发 `event=suspected_hang`（`WARN`）：

| # | 信号 | 判「无活动」的阈值（默认） | 数据来源 |
|---|---|---|---|
| 1 | 标准输出 | 无任何 stdout/stderr 行（含无换行残留） | 读取任务 |
| 2 | CPU | 进程树累计 CPU 时间增量 < `cpu_idle_seconds`（**0.5 秒**/采样窗口） | `GetProcessTimes`（ctypes） |
| 3 | 磁盘读写 | 进程树读写字节增量 < `io_idle_bytes_per_s`（**256 KB/s**） | `GetProcessIoCounters`（ctypes） |
| 4 | 网络 | 仅当工具 `io_profile` 含 `network` 时校验：系统收发增量 < `net_idle_bytes_per_s`（**32 KB/s**） | `GetIfTable2`（ctypes，`iphlpapi`） |

- **任一条件不满足即重置计时器**：有任何输出、CPU 增长、磁盘读写、网络流量，都视为「仍在工作」。
- **采样**：每 `hang_sample_seconds`（默认 30 秒）采样一次，需连续 `ceil(hang_warn_minutes × 60 / hang_sample_seconds)` 个窗口全部无活动才告警——**窗口数由两个参数算出，不是常量**：默认 10 分钟 / 30 秒 = 20 个；若 `hang_warn_minutes=1` 则为 2 个，若采样间隔调到 300 秒则为 2 个。单次采样异常（API 失败）视为「有活动」，不累计。
- **IO 画像**（来自 §2.2 工具表）：`aria2c` = network+disk；`wimlib-imagex` / `7z` = disk；`DISM` / `oscdimg` = disk+cpu。网络项只对含 `network` 的工具校验。

**行为**：**不自动终止**。GUI 弹非模态提示三选一（继续等待 / 终止 / 查看日志），提示文案带证据；CLI 输出一条告警后继续等待。同一阶段内重复告警间隔 ≥ 10 分钟。

**告警证据**（写入事件，便于判断是真卡还是慢）：`cpu_delta=<秒> io_read=<MB> io_write=<MB> net_rx=<MB> net_tx=<MB> elapsed=<秒>`。

**为什么不按进程统计网络**：按进程统计网络字节需要 ETW，实现与权限代价过高；改用**系统级**网络计数，方向是**保守**的（其他程序有流量时不告警 → 宁可漏报也不误杀）。

**配置**（设置页「高级」，不在日志页）：`settings.process.hang_warn_minutes`（默认 10，允许 1–120）、`hang_sample_seconds`（默认 30，允许 10–300）、`cpu_idle_seconds`、`io_idle_bytes_per_s`、`net_idle_bytes_per_s`。
> 优先级：`settings.process.*` 只是**默认值**；任务配置 `TaskConfig.execution.hangWarnMinutes` 显式给出时以任务为准（配置规范 §3.5）。两者都不改代码内的安全下限。

> 依赖约束：三类信号全部用 **ctypes 调 Win32 API**，**不引入 psutil**；进程树终止仍用 `taskkill /T /F`（§7.1）。

## 8. 并发与互斥（固定值，不开放配置）

| 规则 | 值 | 说明 |
|---|---|---|
| 镜像类工具并发 | **固定 1** | `Dism` / `wimlib-imagex` / `7z` / `oscdimg` 同一时刻只允许 1 个进程（同一 wim、同一挂载点不可并发写）；不足以保证时宁可串行 |
| 下载并发 | **固定 1** | 同一时刻只允许 1 个 `aria2c` 进程；下载内部多连接/分片由 aria2c 自身参数控制（FR2.5），与进程并发无关 |
| 跨类并行 | 允许 | `aria2c` 与镜像类操作可同时进行（互不触碰同一文件） |
| 同工具串行 | 强制 | 任何工具不做并发调用，避免资源争用与日志交错 |
| 互斥实现 | 进程级 `asyncio.Lock`（资源名 `image` / `download`），跨阶段共享；锁等待超 60 秒记 `WARN lock_wait` | — |
| 可配置性 | **不提供** | 并发上限不出现在设置项、不出现在 `TaskConfig`；尝试通过配置文件注入时忽略并记 `WARN concurrency_ignored` |

## 9. 退出码与错误映射

### 9.1 内部错误类别（与 `GUI与框架设计.md` §5.6 的进程退出码解耦）

| 类别 | 触发 | 是否可重试 |
|---|---|---|
| `TOOL_MISSING` | 白名单工具找不到 | 否（需修复环境） |
| `TOOL_START_FAILED` | 创建进程失败（权限/路径） | 否 |
| `PERMISSION_DENIED` | 需要管理员或被系统拒绝 | 否（提示提权） |
| `TOOL_FAILED` | 工具返回非 0 | 由阶段决定 |
| `CANCELED` | 用户取消 | 是（`--resume`） |
| `DECODE_ERROR` | 编码回退后仍异常 | 否（记 WARN，不回退任务） |

### 9.2 必须保留的现场信息

每个失败事件必须含：`tool`、`exit`（原始返回码）、`duration`、`channel`、`hresult`（若输出中出现 `0x[0-9A-Fa-f]{8}` 则提取）、`last_lines`（最后 20 条 `line`/`result`，脱敏后）、`cmd`（脱敏命令）。

> 说明：`wimlib-imagex` 的 `exit 55`、`DISM` 的 `0x800f081f` 这类信息不能只放飞日志，必须进入错误对象，供 GUI 错误卡片与诊断包使用。

## 10. 日志联动（与 `日志规范.md` 一致）

- 每次调用只写两行关键事件：
  - `event=start`：`tool`、`cmd`（脱敏）、`cwd`、`source`（定位来源）、`file`（主输入）、`task`、`stage`；
  - `event=finish`：`tool`、`exit`、`duration`、`out`（产出文件）、`size`（若有）、`conclusion=success|failed`。
- `line`/`result` 行写日志，带 `channel`（必要时 `encoding`）；`progress` 行**不写**。
- 采样兜底：同一前缀连续 > 50 行时按「首 1 + 每 100 行 1 条 + 末 1」采样，追加 `sampled=true total=<n>`（与日志规范 §5.2 一致）。
- 脱敏：`cmd` 与 `line` 中的代理凭据、产品密钥、URL 签名按日志规范 §5.5 处理。

## 11. 可测试性（CI 不依赖真实镜像）

- 提供 `FakeProcessBackend`：按夹具回放 stdout/stderr（含进度行、错误行、无换行残留、编码异常字节）。
- 夹具目录：`tests/fixtures/process/<tool>/<case>.jsonl`，每行 `{"channel":"stdout","bytes":"..."}` 或 `{"delay_ms":...}`。
- 必须覆盖的用例：进度识别（含未登记版本）、错误行不被当进度、取消终止、看门狗触发、编码回退、超长行截断、退出码映射。
- 断言口径：进度事件序列单调、最终 100%、日志中**零**百分比行、`line` 数符合采样规则。

## 12. 验收标准

1. 中文 Windows 上 `DISM /Get-Packages` 输出无乱码，`line` 行含 `encoding=cp936`。
2. 一次 20 分钟 aria2c 下载：日志内**无**百分比/速度行；GUI 进度平滑（≥ 1 次/秒）；`event=start`/`event=finish` 各 1 条。
3. 转换中点击取消：5 秒内进程树消失、无残留挂载、返回码 3、日志无 ERROR。
4. **看门狗正例**：`timeout /t 700` 模拟静默（CPU、磁盘、网络均无活动）→ 10 分钟后出现 `suspected_hang`，进程未被自动杀死，证据字段四项齐全。
5. **看门狗反例（关键）**：大文件写入/解包期间无任何输出但磁盘写入持续 > 1 MB/s → **不**触发 `suspected_hang`（计时器被磁盘信号重置）；下载中无输出但网络持续 > 1 MB/s → 同样不触发。
6. **看门狗反例（其他程序活动）**：静默期间系统网络有其他程序流量 → 不触发（保守漏报），阶段结束后日志无 ERROR。
7. `wimlib-imagex` 返回 55：错误对象含 `exit=55`，并在 `last_lines` 中保留原始缺资源提示。
8. 未登记版本的伪造输出（含 `45%` 与 `ERROR:` 同行）：判为 `line` 并入库，不判 `progress`。
9. 夹具回放测试在 CI 通过（无真实镜像、无外网）。
10. 并发：同一阶段内两个镜像类工具不可能并行；`TaskConfig` 中写入 `concurrency: 4` 时被忽略并记 `WARN concurrency_ignored`，实际仍为镜像 1 / 下载 1。

## 13. 开放问题

- [ ] 三类阈值（CPU 0.5 s / 磁盘 256 KB/s / 网络 32 KB/s）需用真实慢盘、慢网、杀软扫描中等样本校准；当前取偏保守值。
- [ ] DISM 个别操作（如 `StartComponentCleanup`）是否存在「长时间低 CPU 低 IO」阶段，需实测样本决定是否需要按工具微调窗口。
- [ ] CLI 是否需要 `--verbose` 把 `line` 行直通终端（当前设计只进日志与 GUI 面板）。
