## 1. 目的与范围

本文定义「谁来做映像操作、做不到时怎么办、`install.wim` 怎么来」三件事，覆盖：

- 引擎职责与**按操作路由**（不按运行时能力随机选路）；
- 能力探测结果与**保守模式**的降级边界；
- **转换路线 A**：复用已验证转换器产出 `install.wim` 的集成方式与等价性校验；
- 工具**缺失自动获取**与**自动更新**（默认关闭）；
- 挂载/卸载契约、WIM/ESD 操作语义、错误语义。

不在本文范围：网络下载细节（见 FR2 与进程规范）、精简/优化/集成规则（见 `FR3-FR5详细需求.md`）、ISO 封装参数以外的输出命名（见 FR8）。

## 2. 已决策项（含推翻条件）

| 编号 | 决策 | 理由 | 推翻条件 |
|---|---|---|---|
| D1 | **按操作路由**：静态对照表决定默认引擎；备用引擎仅在主引擎缺失或明确不支持该参数时启用，且必须记 `capability_degraded` | 同一份配置在每台机器走同一条路，问题可复现；能力路由会让行为随环境漂移 | 若实测发现某操作在不同 Windows 版本必须换引擎且无法用静态表覆盖，则改为「表 + 版本分支」 |
| D2 | **能力探测失败进入保守模式**（§5），不阻断启动 | 探测失败不等于工具不可用；禁用「错了会报废产物」的能力，保留基础面 | 若保守模式导致主流环境无法完成转换（实测），放宽清单并补验收 |
| D3 | **转换路线 A**：`install.wim` 由已验证转换器聚合产出，不自研聚合算法 | 实测证明任何 ESD 都无法单独充当 `install.wim`，聚合映射规则未公开；自研风险与工期不可接受（项目计划 §10 禁止未验证自实现进入 MVP） | 转换器长期不可维护/许可变化，且自研聚合已有可靠样本与校验手段 |
| D4 | **工具哈希信任根 = 随包锁定清单**：不联网取清单、不读发布页哈希、不接受上游 `SHA256SUMS`；新版本哈希随程序发版进入清单 | 期望值必须来自与文件不同的信任通道；同源哈希在被篡改时会一起改，比对必然通过却无保护 | 若后续引入发布签名清单体系（可独立发布且由我方私钥签名），可放宽为「签名清单」而仍不信任上游 |

## 3. 引擎职责与路由表

### 3.1 引擎与角色

| 组件 | 角色 | 权限 | 说明 |
|---|---|---|---|
| `wimlib-imagex` | WIM/ESD 文件级读写、导出、校验 | 一般用户 | 快、免挂载、支持 ESD/LZMS |
| `DISM` | 映像服务：挂载、加包、删包、能力、驱动、组件清理 | **管理员** | Windows 内置，语义最全 |
| `oscdimg` | ISO 封装 | 一般用户 | ADK 提供，缺失只影响 Output |
| `7z` | CAB/ISO 解包 | 一般用户 | 不用于 WIM/ESD |
| **转换器**（`uup-converter-wimlib`） | **组件聚合 → `install.wim`** | 一般用户 | 路线 A，见 §6 |
| `reg.exe` | 离线注册表 | 一般用户（需权限提升） | 非镜像引擎，但同属映像层 |

### 3.2 路由表（按操作，静态）

| # | 操作 | 主引擎 | 备用 | 降级条件 | 备注 |
|---|---|---|---|---|---|
| R1 | 读取映像信息（索引/edition/压缩类型） | `wimlib info` | `DISM /Get-WimInfo` | wimlib 缺失或版本不支持该格式 | 主选因免管理员 |
| R2 | 导出/转换映像（含压缩类型） | `wimlib export` | `DISM /Export-Image` | wimlib 缺失，或目标压缩在主引擎保守模式下被禁 | 压缩映射见 §8.1 |
| R3 | 生成 ESD（LZMS） | `wimlib export --compress=LZMS` | `DISM /Export-Image /Compress:recovery` | 保守模式下禁用 LZMS → **不降级，直接拒绝**并说明 | 见 §5 |
| R4 | 拆分 WIM（SWM） | `DISM /Export-Image /FileSize:4096` | `wimlib split` | DISM 不可用 | 与 CV-08 一致；**本期不开放**（`output.type=swm` 被拒绝，见配置规范 §3.4） |
| R5 | 校验映像完整性 | `wimlib verify` | **无** | — | 缺 wimlib 即无法校验，属硬依赖 |
| R6 | 挂载/卸载映像 | `DISM /Mount-Image` | **无** | — | wimlib 无挂载语义 |
| R7 | 应用/移除包、启用功能、加驱动、组件清理 | `DISM` | **无** | — | FR4/FR5/FR6 的唯一路径 |
| R8 | 组件聚合 → `install.wim` | **转换器** | **无** | — | 路线 A，见 §6 |
| R9 | CAB/ISO 解包 | `7z` | `cabextract`（若随包） | 7z 缺失 | — |
| R10 | ISO 封装 | `oscdimg` | **无** | — | 缺失提示安装 ADK |
| R11 | 离线注册表读写 | `reg.exe load/unload` + `reg import` | `python-registry`（直编 hive） | 加载失败（权限/占用） | 备用方案不依赖提权 |

**路由规则**：

1. 命中主引擎即用主引擎，**不因「备用引擎看起来更快」而换路**；
2. 仅当主引擎**缺失**或**保守模式禁用该参数**时启用备用；
3. 启用备用必须写 `event=capability_degraded from=<主> to=<备> reason=<...>`，并在 GUI 阶段详情里可见；
4. 无备用且不可用的操作 → 明确失败（不静默跳过），错误类型见 §10。

## 4. 能力探测

| 探测项 | 方法 | 失败处理 |
|---|---|---|
| 工具存在与路径 | 按进程规范 §2.1 定位 | 缺失 → 必需工具阻断、可选工具降级 |
| 版本 | 进程规范 §2.2 版本命令（oscdimg 读 PE 版本资源） | 解析失败 → `version=unknown` → 保守模式 |
| 压缩能力 | 版本对照支持矩阵（§4.1） | 不确定 → 视为不支持 |
| ESD/LZMS 读写 | 版本 + `wimlib info` 冒烟（可选样本） | 不确定 → 保守模式禁用 LZMS |
| 分片引用导出（`--ref`） | 版本对照 | 不确定 → 禁用 |
| 挂载能力 | `DISM /Get-MountedImageInfo` 可执行 | 失败 → 判定 DISM 不可用（R6/R7 全断） |

### 4.1 支持矩阵（版本阈值待实测校准）

| 能力 | `wimlib-imagex` | `DISM` | 不确定时 |
|---|---|---|---|
| 读 ESD | 全版本 | 较新版本 | 用 wimlib |
| 写 LZMS | 需较新版本（阈值待测） | `/Compress:recovery` | **禁用** |
| `--ref` 分片引用导出 | 特定版本起 | 无 | **禁用** |
| 拆分 SWM | 支持 `split` | `/FileSize` | 用 DISM |
| 校验 | `verify` | 无 | 硬依赖 wimlib |
| `StartComponentCleanup` | 无 | Win10 1809+ | 失败即报错，不重试 |

> 阈值不允许凭印象写进代码：`rules/engine_caps.yaml` 保存「能力—最低版本—证据（实测日期/构建号）」，未登记的能力一律按「不确定」处理。

## 5. 保守模式：降级边界（已决策）

进入条件：`version=unknown` 或探测异常或工具为未登记版本。

| 处理 | 项 | 原因 |
|---|---|---|
| **禁用** | `wimlib export --ref`（分片引用） | 用错直接 `exit 55`，报错难懂 |
| **禁用** | `LZMS` / ESD 输出（`wim2esd`） | 老版本不支持，失败需重跑数十分钟；降级用 LZX |
| **禁用** | 引导文件自动刷新（新 UEFI CA，CV-14） | 不确定就用媒体骨架原文件 |
| **禁用** | DISM 的「新构建独有参数」（未登记项） | 不确定不加，宁可少做一步 |
| **禁用** | 虚拟 version 相关参数（CV-06/CV-P*） | 本身为实验性 |
| **保留** | `apply` / `export` / `info` / `capture` / `verify` | 全版本基础面 |
| **保留** | `DISM /Mount-Image` `/Add-Package` `/Remove-Package` `/Enable-Feature` `/Add-Driver` `/Cleanup-Image /StartComponentCleanup` | 全版本基础面 |
| **保留（记 WARN）** | `oscdimg` 标准参数 `-m -o -u2 -udfver102 -bootdata:2#...` | 十几年稳定接口，失败 1 分钟内暴露 |
| **保留（记 WARN）** | `XPRESS` / `LZX` 压缩 | 用错概率低，体积差异可接受 |

**可见性要求**：被禁项在 GUI 转换选项页**灰显并给出原因**（tooltip 引用 `capability_degraded` 事件）；CLI 在 `--dry-run` 输出中列出被降级项；不得静默去掉选项。

## 6. 转换路线 A：复用已验证转换器

### 6.1 职责切分（关键）

| 步骤 | 由谁做 | 依据 |
|---|---|---|
| 下载与校验 UUP 文件 | 我们（aria2c） | FR2 |
| 生成 `ConvertConfig.ini` | 我们（选项模型映射） | FR3-FR5 §6.1 |
| CAB 解包（按需）、PSF 差分（**仅当源含 `.psf`**） | 我们（7z / 按需能力） | 实测样本无 `.psf` |
| **组件聚合 → `install.wim`** | **转换器** | 本文 D3 |
| 媒体骨架（`boot\`、`efi\`、`bootmgr`） | **我们自己**：`wimlib apply <esd> <SetupMediaIndex> <dir>` | 实测 1.8 s，引导文件齐全；索引号由 `Name` 含 `Windows Setup Media` 判定，**不写死 1** |
| `sources\boot.wim` | **我们自己**：`wimlib export <esd> <BootIndex> --compress=LZX` | 实测 19.4 s，458 MB；`BootIndex` 取 `wimlib info` 的 `Boot Index` 字段，**不写死 2** |
| 精简/优化/集成/无人值守 | 我们（DISM + 规则库） | FR4–FR7 |
| ISO 封装 | 我们（oscdimg） | FR3.7 |

### 6.2 转换器契约

- **版本锁定**：转换器包以固定版本随包分发（`tools\converter\<version>\`），记录包级 SHA256 与内嵌工具版本；**不参与自动更新**（见 §9.4）。
- **调用方式**：`ProcessRunner` 启动其命令行入口，工作目录 = 任务工作目录，参数只来自生成好的 `ConvertConfig.ini`（不拼接额外开关）；退出码与输出按进程规范解析。
- **输入完整性前置**：转换前校验 `files` 清单（名称/大小/SHA1）全部通过；缺失或哈希不符直接失败（不进入转换）。
- **工作目录**：`{程序目录}\work\<task_id>\convert\`；转换器写出的中间目录保留到 Output 阶段结束（便于失败定位），成功后在清理阶段删除。

### 6.3 两种运行模式

| 模式 | 配置 | 产物 | 用途 |
|---|---|---|---|
| `wim_only`（**MVP 默认**） | `SkipISO=1` | `install.wim`/`esd`（+ 中间目录） | 我们接管骨架、boot.wim、精简、ISO |
| `full` | 转换器默认 | 完整 ISO | 「只要原味 ISO」的快捷路径，我们仅校验 |

- `wim_only` 下媒体骨架与 `boot.wim` 走 §6.1 的实测路径；若样本中不存在可用的媒体骨架映像（索引 1）→ **自动回退 `full`** 并记 `WARN converter_fallback_full`。
- `full` 模式下不再产出 `wim_only` 的中间件；若后续阶段需要 `install.wim`，从 ISO 内提取。

> ⚠ 待实测确认（M0 Spike）：`SkipISO=1` 时转换器是否仍保留媒体骨架目录、`install.wim` 的落盘路径是否固定。未确认前按「可能回退 `full`」实现，验收项 §12-2 覆盖。

### 6.4 产物盘点（转换完成后必须执行）

| 检查 | 判据 | 失败处理 |
|---|---|---|
| `install.wim` 存在且可读 | `wimlib info` 正常返回，`Image Count ≥ 1` | 阶段失败，`EXPORT_FAILED` |
| edition 列表 | 名称与预期（语言/版本）一致 | 不一致 → 失败并列出实际值 |
| 压缩类型 | 与 ConvertConfig 请求一致（`wim_only` 期望 LZX/XPRESS） | 不一致 → 失败 |
| `sources\boot.wim` | 存在且 `Image Count ≥ 1` | 缺失 → 按 `Boot Index` 从源 ESD 重建；源内无 `Boot Index` 或重建失败则终止 |
| 媒体骨架 | `boot\etfsboot.com`、`efi\microsoft\boot\efisys.bin`、`bootmgr`、`bootmgr.efi` 均存在 | 缺失 → `SKELETON_INCOMPLETE` |
| 磁盘余量 | 产物大小 + 20% 余量 | 不足 → 提前失败并提示 |

### 6.5 等价性校验（FR3 验收口径）

同一输入 + 同一 `ConvertConfig` 下，与「转换器原生跑批」的结果比对：

1. `Image Count` 与每个 index 的 `Name`/`Description` 一致；
2. 压缩类型一致；
3. `DISM /Get-Packages` 的包名**集合**一致（忽略顺序与空白差异）；
4. 文件总数允许 ±0.1% 差异（时间戳类文件），超出即判不等价。

比对结果写入日志 `event=equivalence_check result=pass|fail diff=<...>`，并作为 M1 验收证据。

## 7. 挂载/卸载契约

- 挂载根：`{程序目录}\work\<task_id>\mount\<index>`（便携目录内），必须是空目录；挂载前检查 `DISM /Get-MountedImageInfo`，若同目录已挂载 → 先卸载再挂。
- 只读检查用 `/ReadOnly`；只有需要写（FR4–FR6）才读写挂载。
- **成对保证**：`try/finally` 保证卸载；异常退出后下次启动检测残留挂载（`/Get-MountedImageInfo` 与工作目录比对），提示并提供「清理残留挂载」（`DISM /Cleanup-Wim`），**不自动删除用户数据目录之外的挂载**。
- 卸载语义：成功 → `/Commit`；失败 → `/Discard`（不把半成品提交进 wim）。
- 同一时刻仅允许一个挂载（进程规范 §8 镜像互斥），避免 wim 被并发写。

## 8. WIM/ESD 操作语义

### 8.1 压缩类型映射（与 CV-26 一致）

| 逻辑值 | `wimlib --compress` | `DISM /Compress:` | 保守模式 |
|---|---|---|---|
| none | `none` | `none` | 允许 |
| XPRESS | `XPRESS` | `fast` | 允许 |
| LZX | `LZX` | `max` | 允许（默认 WIM） |
| LZMS | `LZMS` | `recovery` | **禁用**（§5） |

### 8.2 拒绝规则（不尝试、不猜测）

| 输入 | 处理 |
|---|---|
| 加密 ESD | 明确拒绝，提示「暂不支持加密 ESD」，不尝试解密（CV-29 为实验性） |
| 多卷 SWM | 明确拒绝并说明「请先合并为单一 WIM」 |
| 非独立（分片）ESD | 先 `verify`；非独立 → 拒绝导出并提示改用可独立校验的映像或走组件聚合（实测见 `转换路线验证.md`） |
| 非 Windows 映像 | 拒绝并说明原因（FR0.5） |

## 9. 工具获取与自动更新

### 9.1 锁定清单（信任根：随包分发）

> **信任根决策（D4，已确认）**：哈希的期望值**只**来自随程序发布的 `tools\tools.lock.json`，**不联网获取清单、不读取发布页/Release 页自称的哈希、不接受上游 `SHA256SUMS`**。
> 原因：哈希只证明「文件与期望值一致」，期望值必须来自与文件**不同的**信任通道；下载页与二进制同源，被篡改时会一起改，比对必然通过却毫无保护。程序包本身由发布签名保护，因此清单随包即继承了可信性。
> 代价（已接受）：**工具新版本只能随程序发版进入**，详见 §9.3。

`tools\tools.lock.json` 随包发布，作为**唯一可信来源**：

```json
{
  "schemaVersion": "1.0",
  "generatedAt": "2026-10-22T00:00:00+08:00",
  "identitySha256": "<清单自身哈希，编译期写入程序常量>",
  "tools": [
    {
      "name": "aria2c",
      "channel": "official",
      "url": "https://github.com/aria2/aria2/releases/download/release-1.37.0/aria2-1.37.0-win-64bit-build1.zip",
      "sha256": "<该版本的内置锁定哈希>",
      "version": "1.37.0",
      "license": "GPL-2.0",
      "required": true
    }
  ]
}
```

- 只允许 HTTPS + 域名白名单（`github.com` / `objects.githubusercontent.com` / 各工具官网）——**白名单只解决「从哪里下」，不解决「信谁」**；
- **哈希只用于比对本清单登记的版本**：清单登记 `1.37.0` 的哈希，就只会去验 `1.37.0` 的文件；**不存在「拿旧哈希验新版本」**——新版本的新哈希随下一次程序发布一起写入清单；
- 运行时校验清单自身完整性：把 `identitySha256` 编译进程序常量，清单被手工改动即判定清单失效（`WARN manifest_tampered`），回退到程序内置的只读副本；
  - **自指定义（必须按此实现）**：`identitySha256` = 「把本字段的值置为空串 `""`，对整个 JSON 做规范化序列化（键排序、无多余空白）」后的 SHA256。清单文件保存该哈希，程序常量保存同一个期望值；校验时先按上述规则重算再与常量比对。**不得**对「包含该字段当前值的原始文本」求哈希——那样写入即改变内容，哈希永远不相等；
- 清单里**没有**登记的版本 → 一律拒绝（不联网兜底、不猜、不使用上游哈希）。

### 9.2 缺失自动获取（必需工具）

- 触发：启动自检发现必需工具缺失（`aria2c` / `7z` / `wimlib-imagex`）。
- 行为：按锁定清单下载到 `tools\.download\` → 校验 SHA256 → 解压到 `tools\<name>\` → 原子替换；UI 显示进度，失败给手动获取指引（含 URL 与哈希）。
- 失败即阻断任务（`TOOL_MISSING`，退出码 4），**不静默降级**。
- `oscdimg` **不自动获取**（ADK 许可不允许再分发，且需安装程序）：只提示安装 ADK。
- **转换器不自动获取**：随包分发，见 §9.4。

### 9.3 工具版本对齐（「自动更新」，默认关闭）

> **语义澄清（重要）**：在 D4 的信任模型下，本功能**不追上游新版本**，而是把本地工具**对齐到随包清单登记的版本**。它解决的问题是：工具被用户手工替换、被杀软删除、文件损坏、或从旧版程序目录升级上来导致版本不匹配。真正升级工具版本 = **程序发新版本**（清单随包更新）。

| 项 | 规定 |
|---|---|
| 开关 | 设置页「工具与依赖」→ **工具自动更新（按清单对齐版本）**，默认**关闭**；状态持久化到 `config\settings.json` |
| 检查时机 | 仅在启动后、任务开始前；运行中不检查、不替换 |
| 判定方式 | 逐工具比对「本地文件 SHA256」与「清单登记哈希」：缺失/不一致/版本不符 → 需要对齐；**不查询网络是否有新版** |
| 对齐流程 | 按清单 URL 下载 → SHA256 校验 → 旧版改名 `*.bak` → 原子落位 → 记 `event=tool_aligned name=<t> from=<本地版本> to=<清单版本>` |
| 版本高于清单 | 本地版本比清单新（用户手工换过）→ **不回退**，记 `WARN tool_version_ahead`，继续使用并提示「非受支持版本，行为可能不同」 |
| 失败回滚 | 校验失败/占用/权限 → 保留当前文件，记 `WARN tool_align_failed`，**任务继续用现有版本** |
| 保留策略 | 仅保留 1 个 `.bak`，超出按最新覆盖 |
| 网络失败 | 不阻断任务（已可用即继续）；记 `WARN tool_align_offline` |

### 9.4 工具与转换器升级流程

- 工具升级（**唯一合法路径**）：上游发版 → 我们在干净环境下载、计算 SHA256、跑冒烟用例 → 更新 `tools.lock.json` 与 `identitySha256` → 发布新程序版本 → 客户端下次启动（开启对齐时）自动落位。
- 转换器升级：版本变化会改变产物，除上述流程外，**必须**额外跑 §6.5 等价性校验并更新 CHANGELOG；转换器永不参与「对齐」自动替换（清单中标记 `managed: false`）。
- 转换器目录保留 `version.txt` 与调用入口路径映射，便于多版本并存试跑。

## 10. 错误语义

| 类型 | 触发 | 可重试 | 用户可见提示 |
|---|---|---|---|
| `INPUT_INVALID` | 非独立/损坏映像、清单哈希不符 | 否 | 指出具体文件与原因 |
| `UNSUPPORTED_FORMAT` | 加密 ESD、SWM、非 Windows 映像 | 否 | 明确「不支持」并给替代路径 |
| `MOUNT_BUSY` / `MOUNT_RESIDUAL` | 目录已挂载、残留挂载 | 是（清理后） | 提供「清理残留挂载」 |
| `DISK_FULL` | 余量不足 | 是（清理/换盘） | 给出所需空间 |
| `COMPONENT_MISSING` | 聚合缺件、`exit 55` | 否（改路线） | 指向转换器日志与缺失资源 |
| `CONVERTER_FAILED` | 转换器非 0 | 按阶段策略 | 附退出码与最后 20 行 |
| `EXPORT_FAILED` | 导出/转 ESD 失败 | 是（换压缩类型） | 建议降级 LZX |
| `SKELETON_INCOMPLETE` | 骨架文件缺失 | 是（重新 apply） | 列出缺失文件 |
| `TOOL_MISSING` | 必需工具缺失且获取失败 | 否 | 手动获取指引 |

所有错误对象必须包含：阶段、涉及文件、工具与原始退出码、`hresult`（若输出含 `0x...`）、最后 20 条日志行（脱敏）——与进程规范 §9.2 一致。

## 11. 日志联动

- 每次引擎调用由 `ProcessRunner` 写 `event=start` / `event=finish`（含 `tool`、`exit`、`duration`、`out`、`size`）；
- 本规范新增事件：`capability_degraded`、`converter_fallback_full`、`equivalence_check`、`tool_aligned`、`tool_installed`、`tool_align_failed`、`tool_version_ahead`、`tool_align_offline`、`manifest_tampered`、`mount_residual_detected`；
- 进度不落盘；`wimlib` 百分比、`DISM` 百分比、`oscdimg` 百分比只进进度通道。

## 12. 验收标准

1. 固定样本（`转换路线验证.md` 的 list id）以 `wim_only` 跑通：产出 `install.wim`，`wimlib info` 可读且 edition 与预期一致。
2. `SkipISO=1` 行为已实测确认（保留骨架 / 回退 `full` 二选一），日志有明确记录。
3. 媒体骨架四个引导文件齐全（`etfsboot.com` / `efisys.bin` / `bootmgr` / `bootmgr.efi`），`sources\boot.wim` 可读。
4. 等价性校验通过：与转换器原生跑批相比，index/名称/压缩类型/包名集合一致。
5. 人为把 `wimlib` 版本伪装为未知：LZMS/`--ref`/引导刷新三项灰显，且有 `capability_degraded` 记录；其余基础操作仍可完成转换。
6. 删除 `aria2c` 后启动：按随包清单获取并通过 SHA256，日志有 `tool_aligned`（首次安装记 `tool_installed`）。
7. 自动更新默认关闭：即使本地工具哈希与清单不符，启动也不替换任何文件。
8. 开启对齐后：把 `wimlib` 手工替换为其他版本 → 启动时被对齐回清单版本并留下 `.bak`；把本地文件改成损坏字节 → 同样被对齐。
9. 清单篡改：手工修改 `tools.lock.json` 的 `identitySha256` 或条目 → 判定清单失效，回退内置只读副本，记 `manifest_tampered`，不按被篡改内容下载。
10. 本地版本**高于**清单登记版本 → **不回退**，记 `tool_version_ahead` 并在 UI 标注「非受支持版本」。
11. 网络不可用且工具已存在 → 记 `tool_align_offline`，任务继续；工具缺失且网络不可用 → `TOOL_MISSING` 阻断并给手动指引。
12. 清单中查询不到某工具版本时，**不联网寻找、不使用上游哈希**，直接拒绝并说明「该版本未随本程序发布」。
13. 加密 ESD / SWM 输入：明确拒绝并给出替代路径，不尝试解密、不产出半成品。
14. 强杀进程后重启：检测到残留挂载并提示清理；清理后转换可正常继续（`--resume`）。
