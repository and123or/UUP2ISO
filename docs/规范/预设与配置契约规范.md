> 版本：v0.3
> 分类：规范（领域规范） ｜ 目录：`docs/规范/`
> 依据：`需求分析.md` FR9.1（任务配置存取）、FR9.2（最小 CLI）、FR4.4/FR5.6（预设复用）、FR10.4（全局设置）

## 1. 目的与四条总则

本文定义 `TaskConfig`（任务配置）与四类预设的**数据契约**，以及它的版本迁移、路径语义与校验规则。

| 总则 | 含义 |
|---|---|
| **唯一业务契约** | 所有业务选项只存在于 `TaskConfig`；GUI 保存的配置即 CLI 的输入，CLI 不做字段级覆盖（FR9.2） |
| **可复现优先** | 同一份配置在任意机器上应产出等价结果；因此预设以**快照内联**，运行时不读预设文件 |
| **显式优于兜底** | 不在配置里写的东西就用文档规定的默认值；不猜测、不从其他任务继承 |
| **向前兼容** | 未知字段不阻断（除非显式开启严格模式）；版本不兼容才拒绝 |

## 2. 文件布局

```
{程序目录}\
  tasks\<taskId>.json          # 任务配置（含预设快照）
  tasks\<taskId>.bak           # 迁移前备份（同目录）
  presets\
    slim\<presetId>.json       # 精简预设
    optimize\<presetId>.json   # 优化预设
    integrate\<presetId>.json  # 集成预设
    unattend\<presetId>.json   # 无人值守预设
  config\settings.json         # 全局设置（不属于 TaskConfig）
  schemas\taskconfig.schema.json   # 权威 Schema（随包发布）
```

- `taskId` 为 8 位十六进制短 id，创建时生成，终身不变（日志、诊断包、输出 readme 都用它关联）。
- 权威 Schema 文件与本文必须一致；CI 用本文示例做 `jsonschema` 校验，防止文档与实现漂移。

> **落地状态（v0.3，M0 / WP0-T6）**：`taskconfig.schema.json` 的**唯一来源**在包内
> `src/uup2iso/schemas/taskconfig.schema.json`，由 `scripts/gen_schema.py` 从 `TaskConfig` 模型生成
> （`--check` 可检测漂移，`tests/test_config_schema.py` 已设为门禁）；打包时复制到 `程序目录\schemas\`
> （WP11-T3）。加载器默认读包内副本，可用 `schema_path` 参数覆盖。
> 这样避免「仓库根 schemas/ 与包内副本两份、互相漂移」的问题。

## 3. TaskConfig 结构

### 3.1 顶层

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schemaVersion` | string | ✅ | 配置格式版本，形如 `1.0` |
| `meta` | object | ✅ | `id`/`name`/`createdAt`/`updatedAt`/`appVersion`/`notes` |
| `input` | object | ✅ | 输入与起始阶段（见 3.2） |
| `source` | object | 条件 | 入口 A 必填：`baseUrl`/`build`/`revision`/`language`/`edition`/`channel` |
| `fetch` | object | ❌ | 下载参数：`split`/`maxOverallDownloadLimit`/`proxy`/`timeoutSeconds` |
| `convert` | object | 条件 | 需要转换/物化时必填：`mode`/`compression`/`editions`/`keepIntermediate` + FR3 各选项（见 3.3） |
| `slim` | object | ❌ | 精简预设快照（见 §4） |
| `optimize` | object | ❌ | 优化预设快照 |
| `integrate` | object | ❌ | 集成预设快照 |
| `unattend` | object | ❌ | 无人值守预设快照 |
| `output` | object | ✅ | 输出（见 3.4） |
| `execution` | object | ❌ | 运行控制：`dryRun`/`resume`/`hangWarnMinutes`/`validation.strictUnknownFields` |

### 3.2 `input`

```json
{
  "mode": "online",                     // online | uupFolder | image
  "startStage": "Convert",              // Prepare | Convert | Slim | Optimize | Integrate | Unattend | Output
  "image": { "path": "D:\\ISO\\win11.iso", "type": "iso", "editions": [1] },
  "uupFolder": { "path": "D:\\UUP\\26100.6508_x64_zh-cn" }
}
```

- `mode=image` 时 `image.path`/`image.type` 必填；`image.editions` 为 `probe.json` 的索引号数组，至少 1 个且在探测到的索引表内（`输入识别与映像准备规范.md` §5）。
- `mode=uupFolder` 时 `uupFolder.path` 必填，且该目录通过 UUP 文件夹特征判定。
- `startStage` 取值为**编排规范的 8 阶段名**（编排 §2），必须 ≥ 输入支持的最早阶段（输入规范 §6），否则 `STAGE_TOO_EARLY`。
- `startStage` 只决定「从哪一步开始做业务」，**不取消 `Prepare`**：任何输入在进入用户所选阶段前都要完成 `Prepare.probe` 与 `Prepare.materialize|extract`（编排 §3），`Prepare` 因此不会被 `skipped`，只可能被标记为「由起始阶段隐含执行」。
- 选择 `startStage=Slim` 时：`Fetch`/`Convert` 记 `skipped reason=input_satisfied`（入口 C）或 `reason=user_start_stage`，`Prepare` 正常执行。

### 3.3 `convert`（FR3 全部选项的承载）

`convert` 必须能表达 `FR3-FR5详细需求.md` §2 的 CV-01…CV-29，**不存在「详设有选项、配置无字段」的情况**：

```json
{
  "mode": "wim_only",              // wim_only | full
  "compression": "LZX",            // none | XPRESS | LZX | LZMS
  "editions": ["professional"],
  "keepIntermediate": false,
  "updates":  { "integrate": true, "mode": "in_image" },
  "cleanup":  { "componentCleanup": true, "resetBase": false },
  "features": { "netfx3": false },
  "winre":    { "skip": false, "update": false },
  "boot":     { "updateBootFiles": false },
  "drivers":  { "enabled": false, "sourceDir": "", "scope": "all" },
  "apps":     { "skip": false, "level": 0, "stubFull": false, "customList": "" },
  "volumeLabel": "",
  "virtualEdition": { "enabled": false, "editions": [] },
  "esdDecrypt": { "enabled": false }
}
```

| CV | 字段 | 说明 |
|---|---|---|
| CV-01 | `mode` | `full` = 转换器直接产 ISO；`wim_only` = 只产 `install.wim`，ISO 由 Output 阶段封装 |
| CV-02 | `updates.integrate` / `updates.mode` | `in_image` 集成进 wim；`external` 随 ISO 投放由安装程序应用 |
| CV-03 / CV-04 | `cleanup.componentCleanup` / `cleanup.resetBase` | `resetBase` 依赖 `componentCleanup=true`；执行前二次确认 |
| CV-05 | `features.netfx3` | 源 `sxs` 缺失时跳过并告警 |
| CV-06 / CV-P1…P8 | `virtualEdition.{enabled,editions}` | **实验性**：`enabled=true` 直接语义校验失败（`CONFIG_SEMANTIC_INVALID`），MVP 不开放 |
| CV-07 / CV-08 / CV-09 | **不在 convert 内** | 「出 ESD / 出 SWM / 只出映像」统一由 `output.type` 表达（§3.4），避免同一结果两处开关 |
| CV-10 / CV-11 | `winre.skip` / `winre.update` | — |
| CV-12 / CV-13 / CV-15 / CV-16 / CV-17 | **不开放为字段** | 由转换器按构建号自动判定（详设 §2.3），固定为「自动」 |
| CV-14 | `boot.updateBootFiles` | 保守模式禁用（引擎 §5） |
| CV-18 | **不在 convert 内** | 由精简预设（`SL-P`/`SL-A`）表达，避免两套开关 |
| CV-20 / CV-21 | `drivers.{enabled,sourceDir,scope}` | `scope`：`all`/`os`/`winpe`。与 `integrate.drivers` **职责不同**：这里在转换阶段交给转换器，`integrate.drivers` 在集成阶段用 DISM；两者都配时以 `integrate` 为准并记 `WARN convert_driver_ignored` |
| CV-22…CV-25 | `apps.{skip,level,stubFull,customList}` | 与精简预设冲突时以预设为准并记 `WARN convert_apps_ignored` |
| CV-26 | `compression` | 映射见引擎规范 §8.1 |
| CV-27 | `editions` | 目标 edition 名称列表（与 `input.image.editions` 的索引号是两套取值，见 §3.2） |
| CV-28 | `volumeLabel` | 空 = 按构建号与语言派生 |
| CV-29 | `esdDecrypt.enabled` | **实验性**：`true` 即语义校验失败，MVP 不开放 |

- `compression=LZMS` 且处于保守模式 → 语义校验失败（`CONFIG_SEMANTIC_INVALID`），与引擎规范 §5 一致。
- 入口 C 且输出 WIM 时可省略 `convert`（只需导出选中 edition）。
- 表中标「不开放为字段」的项，其取值由转换器内建规则决定；GUI 只读展示，CLI 无法覆盖。

### 3.4 `output`

```json
{
  "dir": "",                                  // 空 = 用全局设置中的默认输出目录
  "nameTemplate": "{edition}_{build}_{arch}_{lang}",
  "type": "iso",                              // iso | wim | esd | swm
  "collision": "suffix",                      // suffix | ask | overwrite
  "verifyLevel": 2,                           // 1 | 2 | 3
  "sidecar": { "sha256": true, "readme": true, "manifest": false }
}
```

- `type` 是「最终产物形态」的**唯一开关**：`iso`/`wim`/`esd`/`swm`。FR3 的 CV-07（转 ESD）、CV-08（拆分）、CV-09（跳过 ISO）都用本字段表达，不在 `convert` 内重复定义。
- `type=esd` 且保守模式 → 语义校验失败（同 `OUTPUT_TYPE_UNSUPPORTED`）。
- `type=swm` 属于**后置能力**：契约保留该取值以保证枚举完整，但本期未验证，选它一律 `OUTPUT_TYPE_UNSUPPORTED`，文案「SWM 分卷输出尚未验证，请改用 ISO 或 WIM」。GUI 该项灰显并给出原因。
- `verifyLevel` 与输出规范 §6 的分级一一对应；默认 2。
- `collision=overwrite` 需在 GUI 二次确认；CLI 下若未显式设为 `overwrite`，一律按 `suffix` 处理。

### 3.5 `execution`

```json
{
  "dryRun": false,
  "resume": true,
  "hangWarnMinutes": 10,
  "validation": { "strictUnknownFields": false }
}
```

- `dryRun` 与 CLI `--dry-run` 语义一致：**参数优先**（命令行置 true 时不回写配置）。
- **严格开关的唯一归属是本对象**（`validation.strictUnknownFields`，以及 `slim.strictContext` / `slim.strictFail`）。GUI 设置页中的同名开关只是「新建任务时的默认值」，落在 `settings.defaults.*`，由 GUI 预填进新任务的 TaskConfig；**运行时一律以 TaskConfig 为准**（`TaskConfig > settings.defaults`）。
- `hangWarnMinutes` 覆盖进程规范 §7.2 的默认 10 分钟（范围 1–120）。同理：`settings.process.hang_warn_minutes` 只是默认值，本字段显式给出时以本字段为准。
- `validation.strictUnknownFields=true` 时，未知字段按错误处理（默认 false，见 §7）。

## 4. 预设：快照内联（已决策 D1）

### 4.1 预设文件结构（四类统一骨架）

四类预设共用同一骨架，**只有 `items` 的形态按类别分两种**。`items` 的形态必须与《精简与优化规则规范》§9 一致，不允许出现第二种表达：

| 类别 `kind` | `items` 形态 | 理由 |
|---|---|---|
| `slim` / `optimize` | `{ "ruleIds": [...], "params": {...} }` | 规则按 `ruleId` 绑定，才能做未知规则拒绝、`verify` 与可逆性追溯（规则 §9） |
| `integrate` / `unattend` | 对应 `TaskConfig` 片段的深拷贝 | 这两类不是「规则集合」，而是配置对象（集成 §2 / 无人值守 §4） |

```json
{
  "schemaVersion": "1.0",
  "kind": "slim",
  "id": "slim-safe",
  "version": "1.2",
  "name": "安全精简",
  "createdAt": "2026-10-20T10:00:00+08:00",
  "appVersion": "0.1.0",
  "items": {
    "ruleIds": ["FR4-SL-A01", "FR4-SL-A07", "FR4-SL-C03", "FR4-SL-H01"],
    "params":  { "FR5-OP-C12": { "keepDays": 7 } }
  }
}
```

```json
{
  "schemaVersion": "1.0",
  "kind": "integrate",
  "id": "lab-updates",
  "version": "1.0",
  "name": "实验室更新集",
  "createdAt": "2026-10-20T10:00:00+08:00",
  "appVersion": "0.1.0",
  "items": {
    "updates":  { "paths": ["D:\\Updates"], "recursive": true, "order": "auto" },
    "drivers":  { "paths": [], "recursive": true, "requireSignature": true, "conflict": "newerVersion" },
    "language": { "add": [], "remove": [], "fod": [] },
    "registry": { "imports": [] }
  }
}
```

> 历史写法说明：早期草案把 `slim.items` 写成 `appx.remove[] / packages.remove[] / capabilities.remove[] / bypass{}` 的分类清单。该写法**已废弃**——它无法表达 `ruleId` 绑定，会导致「未知规则无法拒绝」和「规则库升级后预设静默失效」。迁移器把每个裸名称解析为对应 `ruleId`，解析不到的项按未知规则处理（拒绝导入并列出）。

### 4.2 引用与快照规则

- 在 GUI 里选一个预设 → 保存任务时把预设的 `items` **完整内联**进 `TaskConfig` 对应节点，并记录 `origin`。
- 规则类预设内联后，`TaskConfig.slim` / `TaskConfig.optimize` 的形状为 `{ "origin": {...}, "ruleIds": [...], "params": {...} }`；配置类预设内联后直接展开为 `TaskConfig.integrate` / `TaskConfig.unattend` 的字段。
- **运行时只读 `TaskConfig`**，不再打开 `presets\` 目录。理由：预设被改动后，历史任务的结果不应悄悄变化。
- `origin` 结构：`{"presetId": "...", "presetVersion": "1.2", "snapshottedAt": "..."}`，便于追溯与「检查预设是否有更新」提示（仅提示，不自动更新）。
- 未知 `ruleId`（规则库中不存在）：**拒绝导入预设**并列出缺失项。不允许「静默丢项」，否则用户以为删了其实没删。
- `kind=integrate|unattend` 的预设不做 `ruleId` 校验，但必须通过对应片段的 V1+V2 校验。

## 5. 取值约束与默认值

| 字段 | 取值 | 默认 |
|---|---|---|
| `input.mode` | `online`/`uupFolder`/`image` | 由入口决定，无默认 |
| `input.startStage` | `Prepare`/`Convert`/`Slim`/`Optimize`/`Integrate`/`Unattend`/`Output` | 按输入类型推断（输入规范 §6） |
| `fetch.split` | 1–16 | 8 |
| `fetch.timeoutSeconds` | 10–300 | 30 |
| `convert.mode` | `wim_only`/`full` | `wim_only` |
| `convert.compression` | `none`/`XPRESS`/`LZX`/`LZMS` | `LZX` |
| `convert.updates.mode` | `in_image`/`external` | `in_image` |
| `convert.drivers.scope` | `all`/`os`/`winpe` | `all` |
| `convert.apps.level` | 0–4 | 0 |
| `output.type` | `iso`/`wim`/`esd`/`swm`（`swm` 本期拒绝） | `iso` |
| `output.collision` | `suffix`/`ask`/`overwrite` | `suffix` |
| `output.verifyLevel` | 1/2/3 | 2 |
| `execution.hangWarnMinutes` | 1–120 | 10 |
| `execution.resume` | bool | `true` |

- 超出范围即 `CONFIG_SEMANTIC_INVALID`，不做「静默夹紧」（避免用户以为设了 32 连接实际只有 16）。

## 6. 路径语义（已决策 D4）

| 写法 | 解释 | 可移植性 |
|---|---|---|
| `relative/path` | 相对**配置文件所在目录** | ✅ 整个目录搬走仍有效 |
| `D:\abs\path` | 绝对路径，原样使用 | ⚠ 换机器通常失效 |
| `""`（仅 `output.dir`） | 使用全局设置的默认输出目录 | ✅ |

- **不展开环境变量**（`%TEMP%`、`$HOME` 一律当字面量）：避免注入与跨机歧义。
- 加载时对绝对路径做「本机存在性」提示：不存在记 `WARN path_not_portable field=<...>`，**不阻断**（用户可能马上要插移动硬盘）。
- 配置指纹（§8）**排除路径字段**，因此同一任务在不同机器上的指纹相同。

## 7. 未知字段（已决策 D3）

| 模式 | 行为 |
|---|---|
| 默认（`strictUnknownFields=false`） | 忽略未知字段，收集到 `unknownFields[]`，记 `WARN config_unknown_fields count=<n>`；GUI 在配置详情页提示「有 N 个未知字段被忽略（可能来自更新版本）」；诊断包 `manifest.json` 记录字段路径 |
| 严格（`strictUnknownFields=true`） | 任一未知字段即 `CONFIG_SCHEMA_INVALID`，并列出字段路径 |

- `schemaVersion` **主版本**不匹配 → 直接拒绝（`CONFIG_VERSION_UNSUPPORTED`），不进入未知字段逻辑。

## 8. 校验分层与配置指纹

### 8.1 三层校验（加载时执行）

| 层 | 内容 | 失败错误 |
|---|---|---|
| V0 语法 | JSON 可解析、UTF-8、无 BOM | `CONFIG_PARSE_ERROR` |
| V1 Schema | 对照 `schemas/taskconfig.schema.json`（draft-07）、必填与类型、枚举 | `CONFIG_SCHEMA_INVALID` |
| V2 语义 | 交叉校验：`startStage` 与 `input.mode`、`editions` 在探测表内、`compression` 与保守模式、`output.type` 与 `compression`、`collision` 与 CLI 场景、阈值范围 | `CONFIG_SEMANTIC_INVALID` |

- V2 中「路径是否存在」「磁盘是否够」**不在加载时校验**，留到对应阶段前（避免移动硬盘未插就报错）。

### 8.2 配置指纹

- `configFingerprint = sha256(canonical_json)`，其中 **排除** `meta`、`input.*.path`、`output.dir`、`fetch.proxy`。
- 指纹写入：任务日志（`config_fingerprint=<hash>`）、产物 `readme.txt`、诊断包 `manifest.json`。
- 用途：核对「两次构建是否用了同一套业务选项」；跨机比较时以指纹相等为准（路径差异不影响）。

## 9. 版本与迁移（已决策 D2）

| 变更类型 | 处理 |
|---|---|
| 次版本（`1.0 → 1.1`，仅新增可选字段） | 直接兼容，无需迁移；缺字段用默认值 |
| 主版本（`1.x → 2.0`） | 必须经迁移器；无迁移器则拒绝并提示「请用新版本重新创建」 |
| 迁移执行 | 读取 → 迁移 → 重新校验（V1+V2）→ 备份原文件为 `<taskId>.bak` → 写回 |
| 迁移失败 | 不写回、保留原文件、报 `CONFIG_MIGRATION_FAILED`（含失败字段） |
| 幂等性 | 每个迁移器必须幂等且有单元测试；重复迁移不产生二次变化 |
| 记录 | `event=config_migrated from=1.0 to=2.0 backup=<path>` |

- 迁移**不修改** `meta.id` 与 `meta.createdAt`；更新 `meta.updatedAt` 与 `meta.appVersion`。
- 未来若出现「无法自动迁移」的结构变化（如预设从引用改为快照），必须在 CHANGELOG 的「已知限制」中显式声明，不允许静默丢字段。

## 10. 导入导出与跨机复现

- 导出 = 单个 `TaskConfig` 文件（自包含，含预设快照）；不打包 `settings.json`（全局设置属本机）。
- 导入校验顺序：V0 → V1 → V2 → **资源可用性提示**（输入路径不存在、输出目录不存在 → 提示但不阻断）。
- 跨机复现判据：`configFingerprint` 相同 + 输入映像哈希相同 + 工具版本相同 → 视为「同一构建条件」；任一不同则在产物 readme 中标注差异项。

## 11. 与 GUI / CLI 的关系

| 场景 | 规则 |
|---|---|
| GUI 保存 | 写出完整 `TaskConfig`（含快照），不写空字段（缺省即默认值） |
| CLI 读取 | 只读 `--config` 指定的文件；不合并 `settings.json` 之外的任何来源 |
| CLI 覆盖 | 仅 `--dry-run` / `--resume` / `--debug` 三个运行开关，**不写回配置** |
| 默认值冲突 | 以 `TaskConfig` 为准；`output.dir` 为空时才用全局设置 |
| GUI 改动全局设置 | 不影响已保存任务（除 `output.dir` 为空的情况） |

## 13. 验收标准

1. **唯一契约**：同一份 `TaskConfig` 分别由 GUI 执行与 CLI 执行 → `configFingerprint` 相同、产物等价（index/压缩/包集合一致）。
2. **快照隔离**：修改预设文件后再运行旧任务 → 行为不变（仍按快照执行），日志有 `preset_snapshotted` 记录原 `presetVersion`。
3. **未知字段**：向配置注入 `"foo": 1` → 默认模式继续并记 `config_unknown_fields`，GUI 显示「1 个未知字段被忽略」；`strictUnknownFields=true` 时报错并指出 `foo`。
4. **主版本拒绝**：把 `schemaVersion` 改为 `9.0` → `CONFIG_VERSION_UNSUPPORTED`，不尝试解析其余字段。
5. **迁移**：提供 1.0 样本 → 迁移到当前版本，生成 `.bak`，`meta.id` 与 `createdAt` 不变；伪造一个无法迁移的字段 → `CONFIG_MIGRATION_FAILED` 且原文件未被改写。
6. **未知规则**：预设引用规则库中不存在的 `ruleId` → 导入被拒绝并列出缺失项（不静默丢项）。
7. **路径语义**：配置放在 `D:\Cfg\`，`input.image.path="iso\win11.iso"` → 解析为 `D:\Cfg\iso\win11.iso`；绝对路径在另一台机器不存在 → `WARN path_not_portable` 但不阻断加载。
8. **指纹稳定**：仅改动 `output.dir` 与 `meta.notes` → 指纹不变；改动 `slim.ruleIds` → 指纹变化。
9. **CLI 不覆盖**：配置文件里 `dryRun=false`，命令行加 `--dry-run` → 本次按 dry-run 执行，配置文件中仍为 `false`。
10. **Schema 同步**：CI 用本文示例跑 `jsonschema` 校验通过；故意让示例与 `schemas/taskconfig.schema.json` 不一致时 CI 失败。
11. **CV 覆盖性**：对 `FR3-FR5详细需求.md` §2.1 的 CV-01…CV-29 逐条查表，每条要么有 `convert.*` 字段承载，要么在本规范 §3.3 表里显式标注「不开放为字段」；出现「既无字段也无说明」的 CV 即判文档不合格。
12. **预设单一形态**：把 `slim.items` 写成 `appx.remove[]` 的分类清单 → V1 Schema 校验失败并提示「请按 ruleIds 表达」；按 `ruleIds` 写的预设在规则库缺该 id 时拒绝导入。
13. **SWM 后置**：`output.type=swm` → `OUTPUT_TYPE_UNSUPPORTED`，不创建暂存区、不调用 DISM 拆分。
14. **起始阶段**：`startStage=Slim` 时 `Prepare` 仍执行（日志有 `stage_started stage=Prepare`），`Fetch`/`Convert` 记 `skipped`。

## 14. 开放问题

- [ ] 是否需要在 `TaskConfig` 内嵌「工具版本锁定」（当前依赖 `tools.lock.json`），以便复现时核对工具差异。
- [ ] 预设是否需要「组合预设」（多个预设叠加与优先级），当前只支持单预设快照。
- [ ] `output.dir` 为空时用全局设置，是否会让「跨机复现」产生歧义（不同机器默认目录不同，但指纹不受影响）。
- [ ] 配置是否需要加密或签名（涉及产品密钥等敏感项时）。
