# UUP2ISO 数据源与下载规范

> 版本：v0.1
> 依据：`需求分析.md` FR1（数据源）、FR2（下载）、FR1.4（地址可配）、FR2.2（aria2c 获取）、FR9.1（清单与续跑）
> 配套：`外部工具与进程执行规范.md`（进程契约）、`输出校验与原子性规范.md`（产物原子性）、`日志规范.md`
> 优先级：本文与其它文档中关于「怎么取清单、怎么下文件、下坏了怎么办」的描述冲突时，**以本文为准**。

---

## 1. 目的与边界

本文定义三件事：**从数据源取到什么、怎么落成可校验的清单、怎么把文件下完并证明它是好的**。

| 在范围内 | 不在范围内 |
|---|---|
| 构建列表/详情的获取与解析、字段兼容 | 转换与映像处理（见 `映像引擎与转换规范.md`） |
| 文件清单（manifest）生成与自校验 | 精简/优化/集成规则（见 FR3-FR5 详细需求） |
| aria2c 调用契约、续传、进度 | ISO 封装与输出校验（见 `输出校验与原子性规范.md`） |
| 逐文件 SHA1 校验与失败重试 | 工具自身的安装与更新（见引擎规范 §9） |

**术语**：*构建（build）* 指一个 Windows 版本号；*修订（revision）* 指同一构建的更新批次；*清单（manifest）* 指本次任务需要的全部文件及其大小与哈希；*数据源* 指提供构建信息与文件地址的站点。

## 2. 数据源契约

### 2.1 抽象与地址可配（FR1.4）

- 统一抽象 `DataSource`：两个能力——`list_builds()`、`get_manifest(build, revision, language, edition)`。
- **地址模板化**：默认 `https://uupdump.net/`，可配镜像或自建；实现不得把路径硬编码在业务代码里，统一走 `{base_url}` + 路径模板。
- 支持**备用地址列表**：按顺序尝试，当前地址连续失败（不可达/超时 3 次）则切换下一个，切换记 `WARN source_failover from→to`；全部失败才报 `SOURCE_UNAVAILABLE`。
- 请求礼貌约束：同一数据源并发请求 ≤ 1，请求间隔 ≥ 300 ms；请求头带产品标识与版本（便于对方识别与限流）。

> 具体端点路径与响应结构以**站点实际响应**为准，在 M0 用固定样本录制成夹具（§11），不在文档中固化易变的 URL 细节。

### 2.2 字段兼容策略（已决策 D1：区分必需/可选）

| 类别 | 字段示例 | 缺失/异常处理 |
|---|---|---|
| **必需** | 构建号、修订号、语言、edition 标识、文件名、文件大小、SHA1、下载 URL | **任一缺失即失败**（`SOURCE_SCHEMA_INVALID`），不使用默认值兜底 |
| **可选** | 显示名、更新时间、文件分类、备注、镜像校验值（如 SHA256） | 缺失记 `WARN field_missing field=<name>`，功能继续 |
| **未知** | 站点新增字段 | 忽略并记录到 `manifest.json` 的 `unknownFields[]`，便于后续适配 |

- 类型不符（如大小为字符串 `"123"`）按可转换处理（记 `WARN`）；无法转换视为缺失。
- 解析器版本随清单落盘（`parserVersion`），便于定位「同一构建不同时间解析结果不同」。

### 2.3 缓存（已决策 D2：短缓存 + 过期容错）

| 项 | 规定 |
|---|---|
| 缓存对象 | 构建列表、构建详情（含文件清单） |
| TTL | **10 分钟** |
| 位置 | `{程序目录}\cache\source\<host>\<key>.json`（便携目录内） |
| 键 | `host + build + revision + language + edition` 的哈希 |
| 过期行为 | 联网刷新；刷新成功即覆盖 |
| **过期容错** | 刷新失败（网络/站点异常）但存在过期缓存 → **允许使用**，记 `WARN manifest_stale_used age_minutes=<n>`，并在 UI 标注「数据可能不是最新」 |
| 失效 | 用户手动刷新、切换数据源、任务配置中的构建/语言变更 |

- 缓存文件只读展示，不参与产物校验（产物校验看清单与本地产物哈希）。
- 缓存**不缓存文件内容**，只缓存元数据。

### 2.4 错误分类

| 类型 | 触发 | 可重试 | 提示 |
|---|---|---|---|
| `SOURCE_UNAVAILABLE` | 所有地址均不可达/超时 | 是（用户重试） | 给出已尝试的地址与最后错误 |
| `SOURCE_RATE_LIMITED` | 429 / 明确限流 | 是（退避后） | 提示「数据源限流，稍后重试」 |
| `SOURCE_SCHEMA_INVALID` | 必需字段缺失、结构不符 | 否 | 指出缺失字段与解析器版本 |
| `BUILD_NOT_FOUND` | 构建/修订不存在 | 否 | 提示检查构建号与修订号 |
| `BUILD_WITHDRAWN` | 站点标记已下架 | 否 | 提示改用其他构建 |

## 3. 清单（manifest）

### 3.1 结构

```json
{
  "schemaVersion": "1.0",
  "parserVersion": "1.0.0",
  "source": { "baseUrl": "https://uupdump.net/", "fetchedAt": "2026-10-25T14:00:00+08:00", "fromCache": false },
  "build": "26100.6508",
  "revision": "6508",
  "language": "zh-cn",
  "edition": "professional",
  "totalBytes": 4823412736,
  "files": [
    { "name": "Microsoft-Windows-...cab", "size": 12345678, "sha1": "<40 hex>", "url": "https://...", "required": true }
  ],
  "unknownFields": []
}
```

### 3.2 自校验（生成后立即执行）

1. `files` 非空，且每条含 `name/size/sha1/url`；
2. `name` 唯一（重复即 `MANIFEST_INVALID`，说明数据源异常）；
3. `totalBytes` 等于各文件 `size` 之和；
4. `sha1` 格式为 40 位十六进制；`url` 为 https 且域名在白名单内（防被塞入非预期下载源）；
5. 必需文件（`required=true`）数量 ≥ 1。

- 自校验失败 → **不进入下载**，报 `MANIFEST_INVALID` 并保留原始响应到 `{work}\<task>\debug\source-response.json` 供排查（脱敏后）。

### 3.3 落盘

- 位置：`{程序目录}\work\<task_id>\manifest.json`；
- 与任务配置中的选择（build/revision/language/edition）不一致时，以**本次生成**为准并记 `WARN manifest_mismatch`（防止用户改了配置但复用了旧清单）。

## 4. 下载执行（aria2c）

### 4.1 输入列表

- 生成 `{work}\<task>\download\aria2-input.txt`，每行：`<url>` + 换行 + `  dir=<目标目录>` + 换行 + `  out=<文件名>`。
- 转义规则：文件名含空格/中文/`#` 时按 aria2c 输入文件语法处理（`#` 开头会被当注释，需避免行首出现）。
- **不使用 shell 拼接**，列表文件由程序生成、路径使用绝对路径（进程规范 §3）。

### 4.2 参数契约

| 参数 | 值 | 说明 |
|---|---|---|
| `--input-file` | 见 §4.1 | 唯一任务来源 |
| `--continue=true` | 开 | 断点续传（`.aria2` 控制文件） |
| `--max-concurrent-downloads` | **1** | 与进程规范「下载并发固定 1」一致（多连接不等于多文件） |
| `--split` / `-x` | 默认 8，可配 1–16 | 单文件连接数 |
| `--min-split-size` | 20M | 避免小文件过度分片 |
| `--max-tries` | **3** | 网络层重试（超时/5xx/断流）交给 aria2c |
| `--retry-wait` | 2 | 秒；与 `max-tries` 配合 |
| `--max-file-not-found` | 1 | 404 不反复重试 |
| `--max-overall-download-limit` | 空（不限） | 用户可配（FR2.5） |
| `--all-proxy` | 空 | 用户可配；**凭据不写入日志**（日志规范 §5.5） |
| `--summary-interval` | 1 | 保证有进度行（用于进度模型，不落日志） |
| `--console-log-level` | `warn` | 减少噪声；错误仍可见 |
| `--check-certificate` | true | 不提供关闭入口 |

- 重试分层：**网络层** 由 aria2c 负责（`max-tries=3`）；**校验层**（SHA1 不符）由编排层负责（§5.2），两者不叠加放大。
- 不改动 aria2c 的默认磁盘分配策略；不使用 `--file-allocation=falloc`（部分文件系统不支持）。

### 4.3 进度

- 解析 `[#gid 1.2GiB/3.4GiB(35%) CN:8 DL:12MB]` 类行 → `progress`（不落日志，进程规范 §5）；
- 总进度按**文件大小加权**（不是简单按文件数），完成文件计入其全部字节；
- 校验阶段单独上报 `Verify` 子阶段进度（按已校验字节）。

## 5. 校验

### 5.1 顺序（快速失败优先）

```
① 文件存在           → 缺失记为 pending
② 大小 == 清单 size  → 不符直接判坏（无需算哈希）
③ SHA1 流式计算      → 按 1 MB 分块，不整文件读入内存
```

### 5.2 SHA1 不符处置（已决策 D4：重下一次，仍失败则报错）

| 步骤 | 行为 |
|---|---|
| 1 | 删除坏文件（含 `.aria2` 控制文件），记 `event=download_verify_failed file=<n> expected=<sha1> actual=<sha1>` |
| 2 | 重新加入下载队列（同一会话内），退避 2 秒 |
| 3 | 最多重下 **2 次**（合计 3 次机会，含首次） |
| 4 | 仍不符 → 任务失败（`DOWNLOAD_CORRUPT`），**列出文件清单**（名称/期望 SHA1/实际 SHA1/重试次数），保留 `download.state.json` 供排查 |

- **绝不忽略哈希**：宁可失败，也不把损坏组件带进镜像。
- 若清单同时提供 SHA256，则以 SHA1 为主（站点主用），SHA256 作为附加校验（可选执行）。

### 5.3 额外与缺失

| 情况 | 处理 |
|---|---|
| 清单有、磁盘无 | 记为 `pending` 并补下 |
| 磁盘有、清单无 | **不删除**（可能是用户放入的其他文件），记 `WARN extra_file_ignored`，且在后续阶段不参与 |
| 同名文件大小不符 | 视为坏文件，按 §5.2 处理 |

### 5.4 下载状态文件

`{work}\<task>\download\download.state.json`：

```json
{
  "taskId": "7f3a",
  "updatedAt": "2026-10-25T14:10:00+08:00",
  "files": [
    { "name": "a.cab", "state": "verified", "retries": 0, "verifiedAt": "..." }
  ]
}
```

`state` 取值：`pending` / `downloading` / `downloaded` / `verified` / `failed`。

- 该文件是**续跑依据**：`--resume` 时 `verified` 文件直接跳过（仍以 SHA1 复核一次，防止磁盘损坏）；
- 状态文件本身不是产物，不参与 `manifest` 校验。

## 6. 目录结构

```
{程序目录}\work\<task_id>\
  manifest.json
  download\
    aria2-input.txt
    download.state.json
    <文件...>          # 与清单 name 一致，平铺
  debug\               # 仅在异常时生成（脱敏）
    source-response.json
```

- 下载文件**平铺**存放（UUP 文件之间无目录层级），与后续转换器的输入期望一致；
- 不使用系统临时目录（便携原则，见引擎规范/架构图部署章节）。

## 7. 失败与重试矩阵

| 错误 | 层 | 可重试 | 退避 | 上限 | 用户可见 |
|---|---|---|---|---|---|
| 连接超时 / 5xx / 断流 | 网络 | 是（aria2c） | 2 s | 3 次/文件 | 进度恢复，不打断 |
| 404 / 410 | 网络 | 否 | — | 1 次 | 「文件已不可用，构建可能已下架」 |
| 429 限流 | 网络 | 是 | 5 s | 3 次 | 「数据源限流」 |
| SHA1 不符 | 校验 | 是（重下） | 2 s | 2 次 | 失败后列文件 |
| 磁盘空间不足 | 环境 | 否 | — | — | 写入前预检（输出规范 §4） |
| 清单字段缺失 | 数据源 | 否 | — | — | 指出字段名 |

- 整任务**不自动重跑**（避免地址失效时空转）；由用户或 `--resume` 决定。
- 所有重试必须写日志：`event=download_retry file=<n> attempt=<k> reason=<...>`（重试次数与原因可统计）。

---

## 8. 与续跑的关系

- `verified` 文件复用条件：文件存在 + 大小一致 + SHA1 一致（三者同时满足）；
- `.aria2` 控制文件存在视为「部分下载」，可继续（`--continue=true`），但**不计入** `verified`；
- 清单变更（用户改了 edition/语言）→ 旧 `download.state.json` 不适用，重新生成清单并清空状态（记 `event=download_state_reset reason=manifest_changed`）。

## 9. 日志事件

| 事件 | 关键字段 |
|---|---|
| `source_request` | `host`、`endpoint`、`status`、`duration`、`fromCache` |
| `source_failover` | `from`、`to`、`reason` |
| `manifest_built` | `build`、`revision`、`language`、`edition`、`files`、`totalBytes`、`parserVersion` |
| `manifest_stale_used` | `ageMinutes` |
| `download_start` | `files`、`totalBytes`、`split`、`proxy`（脱敏） |
| `download_finish` | `files`、`bytes`、`duration`、`verified`、`failed` |
| `download_retry` | `file`、`attempt`、`reason` |
| `download_verify_failed` | `file`、`expected`、`actual` |
| `download_abandoned` | `file`、`attempts`、`reason` |

进度行不落盘；`aria2c` 百分比只进进度通道。

## 10. 验收标准

1. **字段兼容**：把夹具中某个可选字段删除 → 任务继续并出现 `WARN field_missing`；删除某个必需字段（如 `sha1`）→ 失败 `SOURCE_SCHEMA_INVALID` 并指出字段名。
2. **缓存时效**：同一构建 10 分钟内二次请求 → `fromCache=true` 且不产生网络请求；把 TTL 调为 0 并断网 → 使用过期缓存并出现 `manifest_stale_used`。
3. **备用地址**：主地址不可达 → 自动切到备用地址并记 `source_failover`；全部不可达 → `SOURCE_UNAVAILABLE` 且列出已尝试地址。
4. **清单自校验**：构造重复文件名 / `totalBytes` 不符 / `sha1` 非 40 位 → 均在下载前失败 `MANIFEST_INVALID`。
5. **下载**：20 个文件（含 1 个中文名、1 个含空格）全部落盘，文件名与清单一致；`aria2-input.txt` 无转义错误。
6. **网络重试**：人为让一个 URL 首次 500、之后正常 → 最终成功，日志有 `download_retry`，且**不**触发校验层重下。
7. **校验自愈**：把一个文件内容改一个字节 → 触发删除并重下一次后成功；连续 3 次损坏 → `DOWNLOAD_CORRUPT` 并列出该文件与期望/实际 SHA1。
8. **额外文件**：在下载目录放入清单外文件 → 不删除、记 `extra_file_ignored`、后续阶段不引用。
9. **续跑**：中断后 `--resume` → `verified` 文件被 SHA1 复核后跳过，仅补 `pending` 文件；改动语言后 → 状态重置并重新生成清单。
10. **日志**：全程日志无进度行（无 `%`/`GiB/s`），`aria2c` 仅 start/finish 两条事件。
11. **夹具可回归**：`tests/fixtures/source/` 中的录制响应可在断网环境重放，解析结果与预期 JSON 一致。

---

## 11. 可测试性

- 录制夹具：`tests/fixtures/source/<case>/response.json` + `expected-manifest.json`；覆盖：正常、可选字段缺失、必需字段缺失、重复名、限流响应、构建下架。
- 下载夹具：本地 HTTP 服务（或 `FakeDownloader`）模拟 404/500/断流/损坏文件，验证重试与自愈，**不依赖真实站点**。

## 12. 开放问题

- [ ] 数据源是否存在稳定的「清单直出」端点（可跳过 HTML 解析），需 M0 实测确认。
- [ ] 备用地址的信任边界：镜像站内容是否必须与主站一致（当前只校验 SHA1，来自镜像自身的清单仍可能被篡改）。
- [ ] 是否支持只下「必需文件子集」（跳过语言包等）以减少体积，属 FR2 增项，需评估对转换的影响。
- [ ] `--split=8` 在高延迟网络下是否反而变慢，需实测后决定是否按网络类型自动调整。
