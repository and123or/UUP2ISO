## 3. 每份的范围与必答决策

### S1 数据源与下载规范（FR1/FR2）
**范围**：数据源 API 契约（构建列表/详情/清单）、字段映射与版本兼容、清单生成与缓存时效、aria2c 调用契约（输入列表、连接数/限速/代理、续传、校验）、逐文件 SHA1 校验与失败重试矩阵、下载目录结构。

**必答决策**：
1. API 兼容策略：严格匹配字段 vs 宽松解析 + 告警。
2. 缓存时效与离线可用性（缓存过期后是否允许继续）。
3. 重试上限与退避策略（单文件 vs 整任务）。
4. 校验失败（SHA1 不符）时：重下一次 vs 直接失败并列出文件。

### S2 输入识别与映像准备规范（FR0.4–0.5）
**范围**：输入类型探测（ISO/WIM/ESD/SWM/UUP 文件夹）、加密 ESD / 多卷 SWM / 分片 ESD 判定、edition 枚举、`PrepareImage` 产物约定、入口 C 的可用子集与拒绝文案。

**必答决策**：
1. 探测优先级与冲突（如目录内既有 ISO 又有 WIM）。
2. 加密 ESD 是否提供「先导出再处理」的引导路径，还是纯拒绝。
3. SWM 是否支持自动合并（调 DISM）还是要求用户先合并。
4. 入口 C 是否允许「只改 WIM 不封 ISO」。

### S3 预设与配置契约规范（FR9.1）
**范围**：`TaskConfig` 完整 JSON Schema、预设片段 schema（精简/优化/集成/无人值守）、`schemaVersion` 与迁移策略、默认值与校验规则、GUI/CLI 一致性校验、导入导出格式。

**必答决策**：
1. 配置粒度：单文件全量 vs 主文件 + 预设引用。
2. 迁移策略：自动升级 vs 拒绝旧版本。
3. 未知字段：忽略 + WARN vs 直接报错。
4. 路径语义：相对任务文件 vs 绝对路径。

### S4 任务编排与续跑规范（FR0/FR9.1）
**范围**：阶段定义表（输入→产物→前置条件）、阶段幂等、检查点字段与状态机、失败边界与重试、取消语义（对齐进程规范 §7）、`--resume` 校验四条件、任务记录格式与保留数量。

**必答决策**：
1. 阶段粒度（Convert 是否拆分 prepare/convert）。
2. 重试上限与「哪些错误可重试」白名单。
3. 取消后是否保留中间产物（与输出规范的暂存区策略对齐）。
4. 任务记录保留数量与清理时机。

### S5 精简与优化规则规范（FR4/FR5）—— 风险最高
**范围**：规则数据模型（在既有 `rules/*.json` schema 上补执行语义）、包/能力/Appx 依赖矩阵、执行上下文（`offline` / `online` / `firstBoot`）、风险分级与确认流程、规则幂等与可逆性记录、规则包版本与校验、冲突检测与阻断。

**必答决策**：
1. 依赖矩阵维护方式：手写清单 vs 从映像实测生成。
2. 上下文不满足时：跳过并记录 vs 直接失败。
3. 可逆性记录范围（仅高风险项 vs 全部项）。
4. 预设与规则的绑定粒度（按项 vs 按组）。

### S6 集成规范（FR6）
**范围**：更新（msu/cab）适用性判定与安装顺序、驱动注入与签名校验、语言包/LIP/FOD 组合、注册表导入、失败与回滚。

**必答决策**：
1. 更新来源：仅用户提供 vs 自动从微软目录检索。
2. 驱动注入递归深度与冲突处理。
3. 语言包组合规则（LP + LIP + FOD 的合法组合）。

### S7 无人值守规范（FR7）
**范围**：unattend 模板与 schema 版本匹配（Win10/11、x64）、XML 生成与 XSD 校验、`FirstLogonCommands`/`RunSynchronous` 注入安全、账户/OOBE/分区设置、产品密钥处理。

**必答决策**：
1. 模板来源：内置模板 vs 用户导入。
2. 脚本注入限制（大小上限、是否禁危险命令）。
3. 产品密钥的存储与日志脱敏（与日志规范 §5.5 对齐）。

### S8 GUI 交互规格（FR10.1）—— 量大，可拆两份
**范围**：11 页字段级规格（控件、默认值、校验、禁用原因）、状态模型（加载/空/错误/进行中）、错误呈现与文案、向导回退与跳步、键盘与无障碍、主题与 i18n。

**必答决策**：
1. 向导形态：单窗口分步 vs 左侧导航跳转。
2. 高级模式暴露程度（哪些项默认隐藏）。
3. 错误呈现：内联 vs 顶部汇总。
4. 是否拆成「向导页规格」+「设置与对话框规格」两份。

### S9 打包与发布规范（WP11）—— 可选
**范围**：PyInstaller spec、依赖 excludes 清单、UAC 清单、代码签名流程、便携包目录结构、版本注入、开源许可清单。

**必答决策**：签名证书来源、是否提供安装器、体积目标。

### S10 一致性收口
**范围**：术语表（阶段名/产物名/事件名/错误码）、FR→规范 映射表（每条 FR 至少落在一份规范）、交叉引用有效性校验、架构图/流程图刷新、WBS 对齐、CHANGELOG 归并。

## 4. 每轮的固定动作（流程纪律）

1. **先提决策点**：每个决策写清「问题 / 影响范围 / 推荐方案」，用户确认后动笔。
2. **写文档**：含范围、契约、拒绝与失败语义、日志事件、验收标准、开放问题。
3. **联动四处**（按需）：`需求分析.md`（需求条目与验收）、`项目计划.md`（WBS）、`GUI与框架设计.md`（涉及界面时）、`软件架构图/流程图`（涉及结构或流程时）。
4. **记账**：递增 `CHANGELOG.md`（新增/变更/已知限制）+ 相关文档版本号。
5. **写记忆**：当日日志 + 长期约定（若产生新约束）。

**完成判据**（每份都要满足）：
- 有可执行的验收标准（能写成测试用例）；
- 明确「拒绝/不支持」的边界与用户可见文案；
- 定义日志事件（可观测）；
- 与既有规范无冲突（冲突则显式声明优先级）。
