# UUP2ISO 无人值守规范

> 版本：v0.1
> 依据：`需求分析.md` FR7（无人值守：XML 生成 / 可视化配置 / 脚本注入 / 模板与 schema 校验）
> 配套：`集成规范.md`（同一挂载与回滚语义）、`输出校验与原子性规范.md`（ISO 根写入）、`预设与配置契约规范.md`（`unattend` 配置）、`日志规范.md`（脱敏）
> 优先级：本文与其它文档中关于「unattend 怎么生成、放哪里、怎么校验」的描述冲突时，**以本文为准**。

---

## 1. 目的与边界

| 在范围内 | 不在范围内 |
|---|---|
| `autounattend.xml` / `unattend.xml` 的生成、放置与校验 | Windows 安装程序本身的行为 |
| 可视化配置项 → XML 的映射 | 精简/优化/集成（FR4–FR6） |
| 模板体系与 schema 版本匹配 | 域控、SCCM 等外部部署系统 |
| 脚本注入的边界与审计 | 脚本内容的安全性审查（仅做静态禁令） |
| 产品密钥的存储与脱敏 | 激活机制本身 |

**风险前提**：unattend 的两类失败最隐蔽——**XML 不合法导致整份被忽略**（安装照跑，设置全丢），以及**脚本卡住导致 OOBE 永久停留**。因此本规范把「校验」和「脚本限制」写成硬约束，而不是建议。

---

## 2. 两类文件与生效时机（FR7.1）

| 文件 | 放置位置 | 生效时机 | 适用 |
|---|---|---|---|
| `autounattend.xml` | **ISO 根目录**（或 U 盘根） | 安装程序启动时按固定顺序扫描并应用 | 全新安装（本项目默认） |
| `unattend.xml` | `%SystemRoot%\Panther\`（或 `C:\Windows\System32\Sysprep\`） | specialize / oobeSystem 等 pass 依次处理 | 通用化部署、已有系统重新封装 |

- **本项目默认只生成 `autounattend.xml` 并写入 ISO 根**（在 Output 阶段的 `assemble` 子步骤完成）。
- 可选「同时注入 wim」（`DISM /Apply-Unattend`）：写入 `install.wim` 对应索引；该操作属于集成阶段的一部分，失败遵循集成规范的阶段级回滚。
- 两份文件同时存在时，安装程序以 `autounattend.xml`（安装介质）优先；本项目**不生成两份**，避免优先级歧义。

## 3. 模板体系（已决策 D1：内置 + 允许导入）

### 3.1 内置模板

| 模板 id | 覆盖场景 | 关键设置 |
|---|---|---|
| `desktop-standard` | 个人/测试机 | 跳过 OOBE 隐私页、本地管理员账户、自动分区（整盘 GPT） |
| `minimal` | 只填最少项 | 仅语言/时区/接受 EULA，其余交人工 |
| `domain-join` | 企业加域 | 域、OU、计算机名规则、域账户自动登录（可选） |
| `custom-partition` | 自定义分区 | GPT/MBR、多分区、保留现有分区 |

- 模板是**生成器**而非静态文件：内置模板由代码按构建号生成 XML 骨架，再填充用户选项（避免为每个 Windows 版本维护一份静态 XML）。

### 3.2 导入自定义模板

- 导入时必须通过 **XSD 校验**（§5），并按 §6 的语义规则复核；
- **危险项扫描**：出现 `Format`（格式化全盘）、`Delete Partition`、`InstallTo` 指向不存在磁盘等操作时，展示明确警告并要求二次确认 + 审计事件（`destructive_op reason=unattend_disk_op`）；
- 导入的模板只作为**骨架**，用户选项仍以 GUI 配置为准（冲突时以 GUI 为准并记 `WARN unattend_template_override`）。

## 4. 可视化配置模型（FR7.2）

每个配置项都对应明确的 XML 路径，避免「界面有开关但 XML 没写」：

| 配置项 | XML 路径（简化） | 约束 |
|---|---|---|
| 语言/区域/键盘 | `Microsoft-Windows-International-Core` 的 `InputLocale`/`SystemLocale`/`UILanguage`/`UserLocale` | 必须与映像已有语言一致（否则需先集成语言包，见集成规范 §5） |
| 时区 | `Microsoft-Windows-Shell-Setup/TimeZone` | 取值需为合法时区名（如 `China Standard Time`） |
| 分区方案 | `Microsoft-Windows-Setup/DiskConfiguration` | 与「保留现有分区」互斥 |
| 计算机名 | `Microsoft-Windows-Shell-Setup/ComputerName` | ≤15 字符，不含 `\ / : * ? " < > |`；支持 `*` 随机 |
| 本地账户 | `Shell-Setup/UserAccounts/LocalAccounts` | 至少 1 个管理员；密码不落明文（§7） |
| 自动登录 | `Shell-Setup/AutoLogon` | 需同时提供账户与密码；仅建议测试机使用 |
| 域加入 | `UnattendedJoin/Identification/Credentials` | 与「本地账户自动登录」互斥 |
| 产品密钥 | `Shell-Setup/ProductKey` | 见 §7 |
| 跳过隐私页 | `OOBE/HideEULAPage`/`ProtectYourPC` | 仅影响 OOBE 展示，不改变隐私策略 |
| 跳过 OOBE | `OOBE/HideOnlineAccountScreens` 等 | 与「域加入」可共存，与 `minimal` 模板互斥 |

**互斥与依赖校验**（生成前执行）：

- 域加入 ⟂ 本地账户自动登录；
- 跳过 OOBE ⟹ 必须提供至少一个账户；
- 自动登录 ⟹ 必须提供密码（否则安装会停在登录页）；
- 自定义分区 ⟹ 不能勾选「保留现有分区」。

## 5. Schema 版本匹配（已决策 D4：按构建号 + XSD 校验）

### 5.1 版本判定

1. 从映像读取构建号（`wimlib info` 的 `Version/Build`，或 `install.wim` 的 `Microsoft-Windows-...` 包版本）；
2. 构建号 → 产品线（见下表）；
3. 选择对应组件版本与 XSD。

| 构建号区间 | 产品 | 组件版本（示例） |
|---|---|---|
| 19041–19045 | Windows 10 2004–22H2 | `10.0.19041.0` |
| 22000 | Windows 11 21H2 | `10.0.22000.0` |
| 22621 | Windows 11 22H2 | `10.0.22621.0` |
| 22631 | Windows 11 23H2 | `10.0.22631.0` |
| 26100 | Windows 11 24H2 | `10.0.26100.0` |
| 其他/未知 | — | **拒绝生成**（`UNATTEND_VERSION_UNKNOWN`），提示手动指定构建号 |

- 组件版本写在 `processorArchitecture`/`version`/`publicKeyToken`/`language` 属性中，版本号必须与构建号一致；写错会导致该组件被静默忽略。
- 构建号可判定但**不在内置 XSD 覆盖范围**（更旧或预览版）→ 用最接近的 XSD 校验并记 `WARN unattend_schema_approximate`，允许继续（与 FR7.4 的「告警」一致）。

### 5.2 校验两道关

| 关 | 内容 | 失败 |
|---|---|---|
| XSD 校验 | 内置对应版本 XSD（离线，不依赖 WSIM 安装） | `UNATTEND_XSD_INVALID`，指出行号与元素 |
| 语义校验 | §4 的互斥/依赖、账户与密码、语言与映像一致 | `UNATTEND_SEMANTIC_INVALID` |

- 可选「外部校验」：检测到本机装有 ADK 时，额外用 `WSIM` 校验一次并记录结果（不作为门槛，避免强制用户装 ADK）。
- **绝不跳过校验直接写入**：无效 XML 会被安装程序整体忽略，用户会误以为设置生效。

## 6. 生成流程

```
读取 TaskConfig.unattend + 模板
  → 判定构建号与组件版本（§5.1）
  → 生成 XML（DOM 或模板填充，不用字符串拼接）
  → XSD 校验 → 语义校验
  → 写入目标（ISO 根 / 可选注入 wim）
  → 记录 SHA256 与摘要
```

- XML 由 DOM 构建（`lxml`），禁止字符串拼接——拼接极易产生未转义字符导致整份无效。
- 编码：UTF-8 with BOM（Windows 安装程序对无 BOM 的 UTF-8 兼容性不佳）。
- 换行：CRLF。

## 7. 产品密钥与密码（已决策 D3）

| 项 | 规定 |
|---|---|
| 默认行为 | **不写入产品密钥**（`ProductKey` 节点省略），安装时由用户输入 |
| 用户提供密钥 | 通过 DPAPI（`CryptProtectData`，当前用户作用域）加密存于 `{程序目录}\config\secrets.dat`；生成 XML 时解密并写入 |
| 日志与报告 | 仅显示末 5 位（如 `XXXXX-XXXXX-XXXXX-XXXXX-ABCDE`）；**任何日志、诊断包、readme 都不得出现完整密钥** |
| 本地账户密码 | 同样 DPAPI 加密存储；XML 中 `PlainText=false`（仍需注意：unattend 的密码本质可逆，故要求首次登录强制修改） |
| 导出配置 | 导出 `TaskConfig` 时**剥离**密钥与密码字段，改为占位 `"***"`，并在 readme 提示「需重新填写」 |
| 审计 | 设置了密钥时记 `event=unattend_secret_set kind=product_key|account_password`（不含值） |

> 说明：unattend 中的密码即使 `PlainText=false` 也只是编码而非真正加密，能被还原。因此**默认不写密码**，只有在用户明确勾选「自动登录」时才写入，并在界面提示风险。

## 8. 脚本注入（已决策 D2：白名单 + 大小上限 + 审计）

### 8.1 注入点

| 注入点 | XML 位置 | 执行时机 | 权限 |
|---|---|---|---|
| `FirstLogonCommands` | `Shell-Setup/FirstLogonCommands` | 首次登录（管理员） | 高（可改系统） |
| `RunSynchronous` | `Setup/RunSynchronous`（specialize） | 安装过程中 | 最高（SYSTEM） |

### 8.2 硬限制

| 限制 | 值 | 违反时 |
|---|---|---|
| 单脚本大小 | ≤ **64 KB** | 拒绝添加并提示 |
| 脚本总数 | ≤ **3**（两类合计） | 拒绝添加并提示 |
| 交互式命令 | 禁止 `pause`、`Read-Host`、`set /p`、无参数 `timeout`、`choice` | 拒绝并指出行号 |
| 阻塞式重启循环 | 禁止脚本内 `shutdown /r` 结合无条件循环 | 拒绝并提示 |
| 编码 | 统一 UTF-8（PowerShell 脚本带 BOM） | 自动转换并记 `WARN` |

- 这些限制的目的只有一个：**防止无人值守流程卡死**。一条 `pause` 就能让 OOBE 永久停在黑屏。

### 8.3 记录与审计

- 每个脚本记录：文件名、大小、SHA256、注入点、执行顺序；
- 内容**不写入日志**（可能含敏感命令），仅写 SHA256 与摘要；
- 脚本清单写入产物 `readme.txt`（文件名 + SHA256），便于事后核对；
- 注入脚本本身记 `event=unattend_script_added point=<...> sha256=<...>`。

## 9. 写入与失败处理

| 目标 | 写入方式 | 失败处理 |
|---|---|---|
| ISO 根 | Output 阶段的 `assemble` 子步骤写文件 | 属输出阶段，失败即不产出 ISO（输出规范 §3） |
| 注入 wim | `DISM /Apply-Unattend`（挂载状态） | 属集成阶段，失败即 `/Discard`（集成规范 §8） |

- 写入后必须回读校验：文件存在、SHA256 一致、XML 仍可解析（防止写入被截断）。

## 11. 验收标准

1. **放置正确**：生成 `autounattend.xml` 后，ISO 根目录存在该文件，`sources\` 下无重复；产物 `readme.txt` 记录其 SHA256。
2. **版本匹配**：对 26100 映像生成 → 组件版本为 `10.0.26100.0`；对未识别构建号 → `UNATTEND_VERSION_UNKNOWN` 并拒绝生成（不产出任何 XML）。
3. **XSD 校验**：故意把 `<ComputerName>` 写成 `<ComputerNames>` → `UNATTEND_XSD_INVALID` 并指出行号，且不写入任何位置。
4. **语义校验**：勾选「域加入」同时勾选「本地账户自动登录」→ `UNATTEND_SEMANTIC_INVALID` 并说明互斥。
5. **语言一致**：映像只有 `en-US` 时把 UI 语言设为 `zh-CN` → 语义校验失败并提示「需先集成语言包」。
6. **脚本限制**：添加含 `pause` 的脚本 → 被拒绝并指出行号；添加 65 KB 脚本 → 被拒绝；添加第 4 个脚本 → 被拒绝。
7. **脚本审计**：添加合法脚本 → `unattend_script_added` 含 SHA256，日志中**不含**脚本内容。
8. **密钥脱敏**：设置产品密钥后，日志/诊断包/readme 全文检索不到完整密钥；导出配置中该字段为 `***`。
9. **密码策略**：未勾选自动登录时不写入任何密码节点；勾选后写入且界面有风险提示。
10. **注入 wim**：选择注入 `install.wim` → 挂载后应用成功，`Get-WimInfo` 仍可读；应用失败时挂载被丢弃、wim 哈希不变。
11. **回读校验**：写入后人为截断文件 → 回读校验失败并报错，不产出 ISO。
12. **导入自定义模板**：含 `Format` 全盘操作的模板 → 二次确认 + 审计事件后才允许使用。

## 12. 开放问题

- [ ] 是否需要同时生成 `unattend.xml` 并注入 `%SystemRoot%\Panther\`（用于「已有系统重新封装」场景），当前只出 `autounattend.xml`。
- [ ] 内置 XSD 的来源与许可（是否可直接随包分发微软的 unattend XSD 文件）。
- [ ] 域加入凭据的存储方式（当前同产品密钥：DPAPI，但域账号通常涉及策略，是否应禁止存储）。
- [ ] 是否提供「生成后在虚拟机里试装」的辅助流程（超出当前工具边界，但与验收强相关）。
- [ ] 自动登录密码在首次登录后是否强制清除（`AutoLogon` 的 `LogonCount=1` 行为需实测确认）。
