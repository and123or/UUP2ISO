# UUP2ISO 日志规范

> 版本：v0.4
> 依据：`需求分析.md` FR9.3（日志与进度）、FR9.4（单实例运行）、FR9.5（诊断包）、FR10.4（设置）
> 配套：`GUI与框架设计.md` §5.3（LogSink）、§5.6（退出码）、§6.4.11（设置页）；`软件架构图.md` §7（部署目录）
> 优先级：本文件与其它文档中「外部工具原始输出进入日志」的笼统表述冲突时，**以本文件为准**。

---

## 1. 设计目标与硬性边界

| 目标 | 落地规则 |
|---|---|
| 一次运行一个日志，便于整案排查 | 每次启动创建**一个**运行日志文件；进程内所有模块、所有任务写同一文件 |
| 不按功能拆文件 | **禁止** `download.log` / `dism.log` / `slim.log` 之类的按模块、按阶段、按功能分文件 |
| 纯文本 | 不使用 JSON Lines / 二进制 / 数据库；单行单事件，可 `grep` |
| 进度不污染日志 | 进度条与百分比刷新只走界面/终端，**不写入文件**（§5.2） |
| 审计可追溯 | 审计日志独立文件、不同前缀、同一启动时间戳（§5.3） |
| 审计只读 | 审计文件在进程退出后置**只读属性**，用户不能随手改/删；清理时先解除再删除并留痕（§5.3） |
| 可诊断 | GUI 一键打包「日志 + 脱敏配置 + 环境 + 工具版本」为 zip（§7） |
| 同一时刻只有一个写者 | 单实例运行，GUI 与 CLI 互斥（§6） |

## 2. 日志文件模型

### 2.1 命名与位置

| 类别 | 文件名 | 说明 |
|---|---|---|
| 运行日志 | `run_YYYYMMDD-HHmmss.log` | 每次进程启动一个 |
| 审计日志 | `audit_YYYYMMDD-HHmmss.log` | 同一进程的审计事件，独立文件 |

- **时间戳取程序启动时间**（进程启动瞬间），不取首条日志时间；运行日志与审计日志的时间戳**必须一致**，便于配对排查。
- 同一秒内重复启动（前一个实例已退出）时追加序号：`run_20261021-220600_1.log`、`audit_20261021-220600_1.log`（两类序号保持一致）。
- 默认目录：**`{程序目录}\logs\`**（程序采用**便携式分发**：日志、配置、预设、任务与工具均与程序同目录，不写系统用户目录、不写注册表）。
- 目录不存在时启动创建；**目录不可写时启动即报错**并提示「请将程序解压到可写目录（如 D:\Tools\UUP2ISO）」，**不静默回退**到其他路径——避免日志散落导致排查时找不到。
- GUI 与 CLI **写同一目录**，不区分入口子目录。

### 2.2 生命周期

- **创建时机**：单实例校验通过之后。校验失败（已有实例）时**不创建任何日志文件**，避免空文件与命名冲突。
- **写入**：每条记录立即 flush（崩溃时最多丢失最后一行），便于异常退出后排障。
- **关闭**：正常退出 flush + close；被强杀时以最后一次 flush 为准，文件保留可用。
- **一个进程一个文件**：GUI 进程内连续执行多个任务时共用本进程日志，用 `task=<id>` 键区分，**不为每个任务新建文件**。
- `--resume` 续跑属于新进程 → 新文件；通过 `task=<id>` 与历史文件关联。

### 2.3 行格式（纯文本）

```
2026-10-21 22:06:00.123 [INFO ] [Convert] infra.process: wimlib export 完成 | task=7f3a tool=wimlib-imagex exit=0 duration=19.4s size=458.3MB
```

固定结构：

```
<本地时间 yyyy-MM-dd HH:mm:ss.SSS> [<级别>] [<阶段>] <logger>: <消息> | <k=v 键值对…>
```

- **级别固定 5 字符宽**，便于对齐与检索：`[DEBUG]` `[INFO ]` `[WARN ]` `[ERROR]` `[AUDIT]`（`[AUDIT]` 仅出现在审计文件）。
- **阶段**取阶段枚举（`Fetch`/`Convert`/`Slim`/`Optimize`/`Integrate`/`Unattend`/`Output`/`Validate`）；无阶段上下文时写 `[-]`。
- **常用键**：`task`、`stage`、`tool`、`exit`、`duration`、`file`、`size`、`rule`、`risk`、`event`、`channel`（`stdout`/`stderr`）、`encoding`、`sampled`。
- **单行约束**：禁止多行消息；异常栈逐行写，首行以 `EXC` 前缀标注，后续行以 `  | ` 缩进续写。
- 编码 UTF-8（无 BOM），行尾 `\n`。

## 3. 级别与默认值

| 运行方式 | 默认级别 | 判定依据 |
|---|---|---|
| 打包发布产物（从 exe 运行） | **INFO** | `sys.frozen` 为真（PyInstaller 冻结） |
| 调试阶段（从源码脚本运行，GUI） | **DEBUG** | `sys.frozen` 为假 |
| CLI（任何运行方式） | **INFO** | 命令行入口固定为 INFO |
| CLI 且带 `--debug` | **DEBUG**（仅本次） | 参数覆盖 |

- 优先级：`--debug` > CLI 固定 INFO > 冻结判定（GUI）。
- **参数写法统一为双横线**：`--config` / `--dry-run` / `--resume` / `--debug`；**不支持单横线**（`-debug`）或 `/debug` 等写法，传错即按未知参数报错（退出码 4）。
- `--debug` 是**一次性开关**：不写入 `TaskConfig`、不改全局设置、不影响其他行为。
- 级别过滤只作用于「文件 + GUI 面板」；`WARN` / `ERROR` 在任何级别下都必须写入。
- GUI 设置页只**展示**当前生效级别与来源（`INFO（发布版）` / `DEBUG（开发模式）` / `DEBUG（--debug）`），运行中不可切换，避免排查时级别来源不清。

## 4. 清理策略（三项联合）

### 4.1 触发与删除规则

- 三个维度**都是硬上限**：目录总大小（MB）、保留天数、文件数量。
- **触发**：任意一项超出即触发清理。
- **删除**：按文件修改时间**从旧到新**删除，直到三项**同时**满足；跳过当前正在写入的文件（运行日志与审计日志各自的当前文件永不删除）。
- 只处理本工具生成且匹配 `run_*.log` / `audit_*.log` 的文件，不触碰目录内其他文件。
- **审计文件为只读**：删除前先解除只读属性，删除后必须在运行日志记 `event=audit_pruned file=<name> reason=<size|age|count>`（保证「谁删了哪份审计」可查）。
- **诊断包同池**：`diag_*.zip` 与运行日志**共用同一组阈值与统计池**（大小与数量合并计算，天数按各自修改时间），不单独设置；审计日志仍独立统计。
- 两类日志**分别统计、分别清理**（各自一套阈值），但同处 `logs` 目录。

### 4.2 默认阈值

| 维度 | 运行日志（含诊断包） | 审计日志 | GUI 可改 |
|---|---|---|---|
| 目录总大小 | **200 MB** | **20 MB** | 是 |
| 保留天数 | **30 天** | **365 天** | 是 |
| 文件数量 | **100 个** | **200 个** | 是 |

> `diag_*.zip` 计入「运行日志」列（同一池：大小与数量合并统计），便于用户只调一组数字即可同时约束日志与诊断包。

### 4.3 执行时机与失败处理

- **时机**：进程启动、单实例校验通过、日志文件创建后执行一次；运行过程中**不重复扫描**（避免大目录反复 IO）；退出时不清理（不拖慢关闭）。
- **失败不阻断**：清理异常只记 `WARN`，主流程继续。
- **输入下限保护**：总大小 ≥ 10 MB、天数 ≥ 1、文件数 ≥ 5，GUI 校验不通过时不允许保存。

### 4.4 设置入口（FR10.4）

- GUI 设置页新增「日志」页签：当前级别与来源（只读）、日志目录（只读展示 `{程序目录}\logs`，含「打开目录」）、运行日志三项阈值、审计日志三项阈值、「立即清理」与「生成诊断包」按钮。
- **CLI 不提供任何清理相关参数与设置入口**；CLI 启动时按 GUI 设置中的阈值（未设置则用默认值）静默执行清理。即「CLI 不涉及设置」不等于「CLI 不清理」——否则长期用 CLI 会把磁盘写满。

## 5. 内容规范：记什么、不记什么

### 5.1 第三方工具调用：只记头尾

每次调用外部工具（`aria2c` / `7-Zip` / `wimlib-imagex` / `DISM` / `oscdimg`）必须记录两条**结构化事件**：

| 事件 | 必含字段 | 示例 |
|---|---|---|
| 启动 | `tool`、完整命令（敏感参数脱敏）、工作目录、输入文件、`task`、`stage` | `tool=wimlib-imagex event=start cmd="wimlib-imagex export ..." file=D:\UUP\professional_zh-cn.esd` |
| 结束 | `tool`、`exit`、`duration`、产出文件与大小、结论（成功/失败） | `tool=wimlib-imagex event=finish exit=0 duration=19.4s out=D:\ISO\sources\boot.wim size=458.3MB` |

> 例：保存映像只记「开始保存」与「保存结果（成功/失败、耗时、大小）」，中间百分比不写入日志。

### 5.2 进度类输出：只显示、不落盘

- **不记**：进度条、百分比刷新、速度/ETA、计数刷屏。典型如
  - `aria2c`：`[#1a2b 1.2GiB/3.4GiB(35%) CN:8 DL:12MB]`
  - `DISM`：`[==========              45.0% ]`
  - `wimlib-imagex`：`Writing WIM... 78%`
  - `oscdimg`：进度百分比行
- 这些只进入**进度通道**：GUI 更新进度条与状态文本（节流 ≥ 200 ms 刷新一次）、CLI 渲染到终端（stderr）。
- **记**：非进度行——工具抛出的 `WARN`/`ERROR`、摘要/结果行、文件写入路径与大小、返回码。
- **实现要求**：`ProcessRunner` 把每个输出行分类为 `progress` / `line` / `result`；只有 `line` 与 `result` 交给 `LogSink` 落盘，`progress` 只更新进度模型（分类规则见 `外部工具与进程执行规范.md` §5）。
- **兜底采样**：无法分类的同前缀连续行超过 50 行时，只保留第 1 行 + 每 100 行 1 条 + 最后 1 条，并追加 `sampled=true total=<n>`，防止单次转换写出几十万行。

### 5.3 审计日志（独立文件）

- 触发事件（每次都必须落审计文件）：
  - 高风险项（`risk=high`）启用与二次确认（SL-P01/P02、OP-T60/T62/T63/T64 等）；
  - 不可逆操作：移除包/能力/Appx、`ResetBase`、覆盖已有输出文件；
  - 规则包导入、全局设置变更（数据源地址、外部工具路径、日志阈值）。
- 行内固定带 `event`：`high_risk_enabled` / `destructive_op` / `settings_changed` / `rule_pack_imported`。
- 审计行**必须带 `task=<id>`**（诊断包按任务过滤依赖该字段）；无任务归属的全局事件（如设置变更）写 `task=none`。
- 示例：

  ```
  2026-10-21 22:11:07.402 [AUDIT] [-] app.audit: 启用高风险优化项 | task=7f3a event=high_risk_enabled rule=OP-T64 risk=high confirmed=true user=ZQR host=PC-01
  ```

- 审计条目只写文件，不依赖 UI 是否打开；**审计写入失败时阻断高风险操作**并报 `ERROR`（不做「静默放行」）。

### 5.4 审计日志只读

- **写入期**：本次进程对 `audit_<启动时间戳>.log` 独占追加；文件句柄在进程内保持，其他进程不可写。
- **只读化时机**：
  1. 进程正常退出（含失败退出）时，将本次 `audit_*.log` 置为 **`FILE_ATTRIBUTE_READONLY`**；
  2. 每次**启动时只检查最近 3 个** `audit_*.log`（按修改时间降序）并**幂等补设**只读属性。异常退出只可能漏设上一次运行的文件，因此**不做全量扫描**：目录枚举仅取文件名排序，属性读写只对最近 3 个执行，日志文件累积到上万时启动耗时为常数级。
- 若用户手工清除了更早文件的只读属性，程序**不主动修复**（避免每次启动做 O(n) 属性操作）；需要时可手动「立即清理」或重新生成。
- **只读的表现**：GUI「日志」页以只读模式打开（无编辑按钮）；资源管理器/命令行不能直接覆盖写入；删除需先清除属性。
- **清理例外**：日志清理被授权解除只读并删除（见 §4.1），且必须留痕；除清理逻辑外，程序任何模块**不得**解除审计只读属性。
- **边界说明**：只读属性用于**防误改**，不是安全边界（管理员仍可改回）。更强的不可篡改需 ACL/只读归档，列入 §10 开放问题。

### 5.5 脱敏（强制）

| 内容 | 处理 |
|---|---|
| 代理账号/密码 | `user=*** password=***` |
| 产品密钥 | 仅保留最后 5 位（最后一组），其余置为 `XXXXX`：`XXXXX-XXXXX-XXXXX-XXXXX-ABCDE` |
| URL 中的签名/token | 删除 query 中的 `sig` / `token` / `skoid` 等参数，仅保留 host+path |
| 用户目录路径 | 保留原样（排查需要）；如需匿名化由设置项另行开关 |

## 6. 单实例运行与日志归属

### 6.1 互斥规则

- 程序（GUI 与 CLI **整体**）同一时刻只允许一个实例；GUI 与 CLI 之间也不能并行。

- 实现：Windows 命名互斥量 `Local\UUP2ISO.SingleInstance`（同用户会话级；跨用户互斥不在本期范围，日志目录本身按用户隔离）。
- 冲突行为：
  - **GUI 启动**：检测到已有实例 → 通过本地 IPC 请求已有窗口置前（`QLocalServer`/`WM_COPYDATA`），提示「程序已在运行」，本次进程退出，退出码 `0`。
  - **CLI 启动**：输出 JSON 错误（`{"error":"already_running", "code":5}`）到 stdout/stderr，退出码 **5**。
- 冲突实例**不创建日志文件**、不执行清理、不写审计。

### 6.2 为什么单实例与日志强相关

- 保证 `run_*.log` 在同一时刻只有一个写者，避免两进程交错写入同一目录、时间戳撞名；
- 保证审计序列完整（不会出现两个进程各写一份审计、时序无法拼接）。

## 7. 一键打包诊断（FR9.5）

### 7.1 入口与交互

- **GUI**：日志页与设置页「日志」页签各放一个「生成诊断包」按钮；执行失败的错误卡片上也提供「打包诊断」快捷入口。**单击即完成**：收集 → 脱敏 → 压缩 → 提示保存路径（附「打开所在文件夹」）。
- **CLI 不提供该命令**（保持最小命令集）；需要时手工压缩 `logs` 目录即可。
- 打包前弹一次确认，列出将包含的敏感类别（日志、配置、任务、环境信息）。

### 7.2 包内容（`diag_YYYYMMDD-HHmmss.zip`）

| 内容 | 说明 |
|---|---|
| `manifest.json` | 生成时间、程序版本、OS 版本与构建、是否 frozen、任务 id、`resumed` 标记、日志来源清单与逐文件 SHA256、匹配行数、缺失文件、脱敏声明 |
| `logs/task_<id>.log` | **按任务过滤合并**的运行日志（范围见 §7.3） |
| `logs/task_<id>_audit.log` | **按任务过滤合并**的审计日志（只读方式复制，含 `user`/`host`，manifest 中声明） |
| `config/settings.json` | 脱敏后的全局设置 |
| `task.json` | 当前任务的 `TaskConfig` 与 `PipelineContext`（脱敏；含检查点信息，便于复现） |
| `env.txt` | 架构、管理员状态、Python 版本、程序目录、磁盘剩余空间、单实例状态 |
| `tools.txt` | 外部工具路径与版本（`aria2c` / `wimlib-imagex` / `7-Zip` / `DISM` / `oscdimg`） |

- **默认保存位置**：`{程序目录}\logs\`（与日志同目录，自动纳入 §4 的清理池，共用运行日志阈值）；用户改选其他目录时该包**不受清理策略管理**（manifest 与 UI 均提示）。
- **排除**：ISO / WIM / ESD、UUP 原始文件、驱动目录、`tools\` 二进制本身。

### 7.3 打包范围：按任务精确取日志（不漏、不多）

**判定依据**：读取 `{程序目录}\tasks\{task_id}.json` 中的日志索引与 `resumed` 标记。

| 场景 | 纳入范围 |
|---|---|
| **单次任务（非延续）** | 仅当前进程的 `run_*.log` 与 `audit_*.log` |
| **延续任务**（`--resume` / 从检查点恢复 / `resumed=true`） | 索引中**全部** `log_files` 与 `audit_files`（跨多次运行），逐文件过滤后合并 |

**日志索引**（保证「不漏」的基础）：

- `TaskSession` 在 `tasks\{task_id}.json` 中维护 `log_files: []` 与 `audit_files: []`；
- 任务在本进程**首次写日志时**把当前 `run_*.log` / `audit_*.log` 文件名追加进索引并立即 flush（崩溃前已完成落盘，不依赖退出钩子）；
- 索引去重、保序（按首次接触顺序）；`resumed` 由加载检查点时置位。

**过滤规则**（保证「不多」）：

- 逐文件只保留 `task=<task_id>` 的行；审计同理（故 §5.3 要求审计行必须带 `task`）；
- 过滤后的行**按时间顺序合并**为 `logs/task_<id>.log` / `logs/task_<id>_audit.log`，每个来源文件前插入一行注释 `# source=<原文件名>`（便于回溯，不参与行数校验）；
- **不扫描 `logs` 目录**猜测范围——只按索引取文件，避免把无关任务或他人日志带进包。

**完整性校验**（可验收）：

- 打包时逐文件统计 `task=<id>` 匹配行数，`manifest.json` 记 `sources[] = {file, matched_lines, sha256}`；
- 合并后总行数必须等于各来源匹配行数之和，否则中止并报错（不生成残缺包）；
- 索引中列出的文件已不存在（被清理/手工删除）→ 包内 `manifest.missing[]` 记录，`exact=false`，UI 提示「部分历史日志已被清理，包内为不完整历史」；
- 索引缺失（旧版本任务或文件被删）→ 回退为「当前运行文件整份纳入」，`exact=false`，并在 UI 明示**不要**当作完整历史。

### 7.4 约束

- **纯本地**：不联网、不上传；生成后完全由用户处置。
- 脱敏复用 §5.5；审计日志按原样包含（合规排查需要），但必须在 manifest 中显式声明。
- 生成失败（磁盘不足/权限/文件被占用）只提示原因，**不影响主流程与正在运行的任务**。
- 打包过程不得解除审计只读属性（以只读方式复制）。

### 7.5 验收

- 断网环境可生成；`manifest.json` 内 SHA256 与实际文件一致；包内检索不到明文代理密码与完整产品密钥。
- 5 GB 工作目录下生成诊断包，体积 ≤ 30 MB（排除大文件生效）。
- **延续任务**（续跑 3 次 = 4 个运行日志）打包后：合并文件行数 = 4 个来源文件 `task=<id>` 行数之和；包内不含其他 `task` 的行。
- 删除其中一个历史日志后再打包：`manifest.missing` 列出该文件、`exact=false`，UI 有提示，包仍可生成。

## 9. 验收标准（可测）

1. 连续启动 3 次 → `{程序目录}\logs` 下出现 3 个 `run_*.log`（外加每进程 1 个 `audit_*.log`），**不存在**按模块/阶段命名的日志文件。
2. 程序目录移至 `D:\Tools\UUP2ISO` 后运行，日志仍落在该目录 `logs\`；程序目录设为只读时启动即报错并给出提示，不静默改路径。
3. 级别：exe 运行默认 `INFO`；源码 GUI 默认 `DEBUG`；CLI 默认 `INFO`；CLI 加 `--debug` 本次为 `DEBUG`；`-debug`（单横线）按未知参数报错并返回退出码 4。
4. 跑一次完整转换后，日志内**不含任何**百分比、`GiB/s`、进度条字符；包含每次工具调用的 `event=start` 与 `event=finish`（含 `exit` 与 `duration`）。
5. 启用任一 `risk=high` 项 → `audit_*.log` 出现 `event=high_risk_enabled`，且与本次 `run_*.log` 时间戳前缀一致。
6. 进程退出后 `audit_*.log` 属性为只读（`attrib +R` 可见）；手工覆盖写入失败；GUI 打开审计文件为只读视图。
7. **启动补设只读只作用于最近 3 个审计文件**：构造 500 个历史 `audit_*.log`，启动耗时与 3 个时同级（不随文件数线性增长）。
8. 构造任一维度超限（大小/天数/数量）→ 下次启动后自动删至三项达标，被删审计在运行日志有 `event=audit_pruned`，当前文件保留。
9. `diag_*.zip` 与 `run_*.log` 共用阈值：构造「日志 180 MB + 诊断包 40 MB」→ 触发清理并按最旧删除至 200 MB 以内。
10. 已有实例运行时启动 CLI → 退出码 `5`，`logs` 目录不新增文件；启动 GUI → 已有窗口置前，本次进程退出。
11. 日志全文检索不到明文代理密码与完整产品密钥。
12. 一次 20 GB 转换产生的日志 ≤ 5 MB（采样兜底生效）。
13. 一键诊断包：断网可生成，`manifest.json` 的 SHA256 与文件一致，包内无明文凭据，且不含 ISO/WIM/ESD。
14. **延续任务范围**：续跑 3 次（共 4 个运行日志）后打包，合并文件行数 = 4 个来源文件 `task=<id>` 行数之和，且不含其他 `task` 的行。
15. 删除一个历史日志再打包：`manifest.missing` 列出该文件、`exact=false`，UI 提示不完整，包仍可生成。
