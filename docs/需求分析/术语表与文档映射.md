## 2. 术语表

### 2.1 编排与状态

| 术语 | 定义 | 出处 |
|---|---|---|
| **阶段（Stage）** | 8 个固定执行单元：`Prepare`/`Fetch`/`Convert`/`Slim`/`Optimize`/`Integrate`/`Unattend`/`Output` | 编排 §2 |
| **子步骤（Substep）** | 阶段内部的执行单元，完成即写检查点（如 `Convert.aggregate`） | 编排 §3 |
| **检查点（Checkpoint）** | `work\<task>\checkpoint.json`，记录阶段/子步骤状态与产物哈希 | 编排 §5 |
| **任务记录（TaskRecord）** | `tasks\<taskId>.json`，含配置与 runtime 段，保留最近 50 个 | 编排 §10 |
| **起始阶段（startStage）** | 用户选择的起点，必须 ≥ 输入支持的最早阶段 | 输入 §6 |
| **配置指纹** | `sha256(canonical_json)`，排除 `meta`/路径/代理，用于判断"同一套业务选项" | 配置 §8.2 |
| **输入指纹** | 输入映像 SHA256 或清单总哈希，变化则从 `Prepare` 重做 | 编排 §6 |

### 2.2 状态取值（唯一写法）

| 对象 | 取值 |
|---|---|
| 任务 | `draft` / `queued` / `running` / `succeeded` / `failed` / `cancelled` / `interrupted` |
| 阶段 | `pending` / `running` / `succeeded` / `failed` / `skipped` / `cancelled` |
| 子步骤 | `pending` / `running` / `done` / `failed` / `skipped` |
| 下载文件 | `pending` / `downloading` / `downloaded` / `verified` / `failed` |
| 日志级别 | `DEBUG` / `INFO` / `WARN` / `ERROR` / `AUDIT` |

> 禁止使用同义词（如 `success`、`complete`、`error` 作为状态值），事件名中的 `result=success|failed` 除外。

### 2.3 产物与目录

| 术语 | 定义 |
|---|---|
| **中间产物** | 下载文件、解包树、`install.wim`、挂载展开目录等，位于 `work\<taskId>\` |
| **暂存区（staging）** | `{输出目录}\.uup2iso-tmp\<taskId>\`，与发布点同卷 |
| **发布点** | 输出目录中的最终文件名，只在校验通过后出现 |
| **伴生文件** | `<name>.sha256` / `.readme.txt` / 可选 `.manifest.json` |
| **媒体骨架** | ISO 中的 `boot\`、`efi\`、`bootmgr`、`setup.exe` 等文件树 |
| **install 映像** | `sources\install.wim|esd`，或工作区 `image\install.wim` |

### 2.4 映像与集成

| 术语 | 定义 |
|---|---|
| **WIM / ESD / SWM** | Windows 映像格式 / 高压缩（LZMS）映像 / 多卷拆分映像 |
| **LP / LIP / FOD** | 语言包 / 语言界面包 / 按需功能 |
| **LCU / SSU** | 累积更新 / 服务堆栈更新（SSU 须先于 LCU） |
| **聚合** | 以基础映像为落点，按映射规则顺序应用 CBS 组件增量，产出 `install.wim` |
| **转换器** | `uup-converter-wimlib`，路线 A 中唯一负责聚合的外部组件（版本锁定） |
| **保守模式** | 工具版本未知时禁用高风险能力（`--ref`、LZMS、引导刷新、未登记 DISM 参数） |
| **能力探测** | 读取工具版本并对照 `rules/engine_caps.yaml` 判定可用能力 |
| **引擎路由** | 按操作查静态表决定主/备引擎（不由运行时能力随机选择） |

### 2.5 规则与工具链

| 术语 | 定义 |
|---|---|
| **规则（rule）** | 一条带 `id`/`level`/`actions`/`verify` 的最小执行单元 |
| **规则库 / 规则包** | `rules/*.json`；`schemaVersion` 描述结构，`packVersion` 描述内容批次 |
| **执行上下文** | `offline`（挂载映像）/ `firstBoot`（首次登录）/ `online`（本工具不支持） |
| **依赖矩阵** | 包/能力/功能的必需关系（手写硬约束 + 实测观测），含 `blockedCombos` |
| **可逆性（reversible）** | 规则执行后能否仅靠丢弃挂载还原；不可逆项必须写 `recovery` |
| **锁定清单** | `tools\tools.lock.json`，唯一哈希信任根，随包发布 |
| **版本对齐** | 原「工具自动更新」：把本地工具对齐到清单登记的版本，**不追上游新版** |
| **四信号看门狗** | 无输出 + CPU 静默 + 进程读写静默 + （网络类工具）网络静默，持续 10 分钟才告警 |

### 2.6 GUI

| 术语 | 定义 |
|---|---|
| **三档模式** | 简单 / 标准 / 专家，持久化到全局设置，不写入 `TaskConfig` |
| **步骤条** | 向导顶部的 10 步导航，已完成步骤可回跳 |
| **内联错误** | 字段下方的就地错误提示 |
| **汇总区** | 向导底部列出跨字段冲突，可点击定位 |
| **草稿** | 进入向导即生成的 `status=draft` 任务记录，单独保留 10 个 |
| **执行页** | 展示阶段串、进度、日志面板的页面（配置只读） |

## 4. 交叉引用校验

### 4.1 方法与结果

- 方法：扫描全部 `*.md` 中形如 `文件名.md §N[.M]` 的引用，比对目标文件的实际标题层级（`##`–`####`）。
- 结果（2026-10-30）：**21 份 Markdown，0 处失效引用**。
- 局限：短名引用（如「引擎 §7」）不在自动检查范围内，已按 §1 的权威短名表逐条人工核对。

### 4.2 维护要求

- 调整章节编号后，必须重跑同一检查（脚本要点：正则 `([\w\-.\u4e00-\u9fa5]+\.md)\`?\s*§\s*(\d+(?:\.\d+)?)`，目标文件标题集合取 `^#{2,4}\s*(\d+)(?:\.(\d+))?`）。
- 新增规范时，必须同时更新本文件 §1 与 §3，否则视为文档未完成。
