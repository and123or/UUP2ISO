# UUP2ISO 输出校验与原子性规范

> 版本：v0.1
> 依据：`需求分析.md` FR8（输出与校验）、FR8.1（命名）、FR8.2（哈希与伴生）、FR8.3（可用性校验）
> 配套：`映像引擎与转换规范.md` §6.4（产物盘点）、`外部工具与进程执行规范.md`（取消与错误码）、`日志规范.md`
> 优先级：本文与其它文档中关于「输出到哪里、什么时候算成功、失败留什么」的笼统描述冲突时，**以本文为准**。

---

## 1. 目的

把「不产出半成品 ISO」从一句要求，变成可验证的机制。本文回答四个问题：

1. 产物**先写到哪里**，怎么变成正式文件；
2. **校验到什么程度**才算通过；
3. 崩溃、取消、校验失败后**留下什么**、怎么清理、怎么续；
4. 输出目录**需要多少空间**，什么时候提前失败。

**核心原则：最终路径上出现的文件，必须是完整且已校验的。** 任何中间状态都不得出现在最终文件名上。

---

## 2. 术语与目录模型

| 术语 | 定义 |
|---|---|
| **中间产物** | 下载的 UUP 文件、解包结果、`install.wim`、挂载展开目录等 |
| **暂存区（staging）** | 与最终产物**同一卷**的临时目录，产物先写在这里 |
| **发布点** | 用户输出目录下的最终文件名，只在校验通过后出现 |
| **伴生文件** | 与产物同名的 `.sha256` / `.readme.txt` / 可选 `.manifest.json` |
| **提交（commit）** | 暂存文件通过同卷 rename 落位到发布点的动作 |

```
{程序目录}\work\<task_id>\            # 中间产物（下载/解包/mount/convert）
{输出目录}\.uup2iso-tmp\<task_id>\    # 暂存区（必然与发布点同卷）
{输出目录}\<name>.iso                 # 发布点（仅校验通过后出现）
```

- **暂存区永远建在输出目录下的 `.uup2iso-tmp\`**，因此提交只能是同卷 rename——这是原子性的前提（已决策，见 §3）。
- 输出目录可以是任意用户目录；启动输出阶段前校验「可写」，不可写即 `OUTPUT_NOT_WRITABLE`（退出码 4），不进入写入。

## 3. 原子提交（已决策：暂存在输出卷）

### 3.1 提交流程（唯一合法路径）

```
① 写入暂存区：<name>.iso.part（写的同时可增量计算 SHA256）
② flush + os.fsync（保证字节落盘，而非留在系统缓存）
③ 校验 L1（+L2，按配置）+ 必要时 L3 → 全部通过才继续
④ 解析最终文件名（模板 + 重名策略，见 §5）
⑤ os.replace(staging_file, final_path)      # 同卷原子替换
⑥ 伴生文件走同一流程（先写 staging/sidecar，再 rename）
⑦ 记 event=output_committed
```

- **禁止**先写最终文件名再校验；
- **禁止** `shutil.move` / `copy` 作为提交手段（跨卷时会退化为复制，非原子）；
- rename 前一刻再判定重名，避免 TOCTOU；
- Windows 上目录项无 `fsync` 语义：提交后以「文件存在 + 大小 + SHA256 复核」代替（提交后立即复核一次）。

### 3.2 同卷校验

- 比较 `Path(staging).drive` 与 `Path(output_dir).drive`；不同即 `OUTPUT_CROSS_VOLUME`（退出码 4），并提示「暂存区与输出目录必须在同一磁盘」。
- 正常路径下不会触发（暂存区就在输出目录内）；该检查用于防止用户手工改动暂存位置或未来重构引入跨卷行为。

### 3.3 为什么不用「直接写最终名 + 失败删除」

直接写最终名的窗口期内，文件既没有校验也带着正式后缀：用户可能拷走、杀软可能扫描上报、`--resume` 可能误判为已完成。暂存区把「未完成」与「已完成」在**文件系统层面**区分开，而不是靠约定。

## 4. 空间预算与预检

| 位置 | 需求 |
|---|---|
| 程序目录（work） | 下载总量 + 解包展开 + `install.wim` + 挂载展开（单 edition 约 15 GB）+ 20% 余量 |
| 输出卷 | **暂存产物大小 × 1.05**（提交后同一份字节改名，峰值即暂存文件本体；伴生文件可忽略） |

- 参考量级（单 edition、zh-cn、wim 输出）：work ≈ 35 GB，建议 ≥ 50 GB 空闲；输出卷按 ISO 大小 + 5%。
- 预检分两次：**Fetch 开始前**（按清单总字节）与 **Convert/Output 开始前**（按实际产物大小）；不足即失败并给出「需要 X GB / 可用 Y GB」，不允许跑到 90% 才报错。
- 预检失败退出码 4；不创建暂存区。

## 5. 命名与重名（已决策：默认加后缀）

### 5.1 命名模板

- 模板变量：`{edition}_{build}_{arch}_{lang}`（可配置，FR8.1）；扩展名按产物类型（`.iso` / `.wim` / `.esd` / `.swm`）。
- 非法字符（`\ / : * ? " < > |`、控制字符、首尾空格）替换为 `_`；连续下划线合并。
- 总路径长度上限 200 字符（为 260 上限留余量）：超限时截断 `{edition}` 并记 `WARN name_truncated`。
- 变量缺失（如无 edition）按 `unknown` 填充并记 `WARN`，不得产出空名。

### 5.2 重名策略

| 策略 | 行为 | 适用 |
|---|---|---|
| `suffix`（**默认**） | `name.iso` → `name_1.iso` → `name_2.iso` …；999 后追加 `_YYYYMMDDHHmmss` | 全部场景，CLI 无人值守安全 |
| `ask` | GUI 弹窗（覆盖 / 改名 / 取消）；**CLI 下视同 `suffix`** 并记 `WARN` | 交互场景 |
| `overwrite` | 直接覆盖；必须显式配置 + GUI 二次确认；写审计 `event=destructive_op`（覆盖已有输出） | 高级用户 |

- 任何策略下都**不会**产出 `name (1).iso` 这类含空格括号的名字（避免脚本处理麻烦）。
- 重名解析结果记 `event=output_name_collision strategy=<...> final=<...>`。

## 6. 校验分级（已决策：默认结构+内容，深度可选）

| 级别 | 内容 | 耗时量级 | 默认 |
|---|---|---|---|
| **L1 结构** | 文件存在且大小 > 0；ISO 可只读挂载（或 `7z l` 能列出）；卷标符合请求；引导文件齐备；`setup.exe` 与 `sources\install.*` 存在 | 秒级 | **开** |
| **L2 内容** | `wimlib info` 可解析；`Image Count ≥ 1`；索引名称唯一且与预期一致；压缩类型与请求一致；自算 SHA256 并写伴生；若已集成则比对包名集合 | 秒–分钟 | **开** |
| **L3 深度** | `wimlib verify` 全文件校验；可选 `DISM /Cleanup-Image /ScanHealth` | 10–30 分钟 | **关**（设置/任务配置可勾选） |

- L3 勾选后在日志记 `output_validated level=3 duration=...`；未勾选时**不得**调用 `verify`（验收可查）。
- 任一级失败即判输出失败：不 rename、不写伴生、保留暂存、退出码 2。
- 校验必须以**只读**方式打开产物；挂载校验用完立即卸载（引擎规范 §7）。

### 6.1 逐产物清单

| 产物 | L1 | L2 |
|---|---|---|
| ISO | 可挂载；`boot\etfsboot.com`、`efi\microsoft\boot\efisys.bin`、`bootmgr`、`bootmgr.efi`、`setup.exe`、`sources\install.wim\|esd\|swm` 均存在；卷标一致 | 内部 install 映像可读、edition 与预期一致 |
| WIM | 存在、非零 | `wimlib info` 可解析；索引名唯一；压缩类型一致 |
| ESD | 同上 | 压缩类型为 LZMS；索引可读 |
| SWM | 分卷齐全（`install.swm` + `install2..N.swm`），无缺号 | 首卷 `wimlib info` 可读；分卷数与预期一致 |

## 7. 失败、中断与续跑（已决策：保留并提示）

### 7.1 暂存区结构

```
{输出}\.uup2iso-tmp\<task_id>\
  staging.json        # 状态：task_id / stage / output_name / expected_size / written / state / started_at
  <name>.iso.part     # 正在写入的产物
  sidecar\            # 伴生文件暂存
```

`state` 取值：`writing` → `validated` → `committing` → （提交后目录删除）。

### 7.2 启动时的残留检测（不全盘扫描）

- 任务记录（`tasks\{task_id}.json`）保存 `output_dir` 与 `staging_dir`；启动时只检查**最近 10 个**有记录的任务目录（与日志规范「只补最近」同一思路，避免遍历大磁盘）。
- 发现残留 → 记 `event=staging_residual_detected state=<...>`，GUI 提示三选：**继续 / 保留 / 删除**；CLI 打印提示与手工处理命令（不交互）。
- `state=committing` 的残留特殊处理：检查最终文件是否存在且 SHA256 与记录一致 → 一致则视为已提交，补写伴生并清理；不一致则判半提交，保留并提示。

### 7.3 续跑复用规则（防「半成品被当真」）

中间产物可复用必须**同时**满足：

1. 检查点记录该阶段 `completed=true`；
2. 文件存在；
3. 大小与记录一致；
4. SHA256 与记录一致。

任一不满足 → **重做该阶段**（不猜、不跳过）。暂存区里的 `.part` 文件**永不参与复用**（它未经校验）。

### 7.4 退出码与留痕

| 情形 | 退出码 | 最终目录 | 暂存区 |
|---|---|---|---|
| 校验通过并提交 | 0 | 有产物 + 伴生 | 已清理 |
| 校验失败 | 2 | **无产物** | 保留（`state=writing/validated`） |
| 用户取消 | 3 | 无产物 | 保留 |
| 空间/权限预检失败 | 4 | 无产物 | 不创建 |
| 崩溃 | — | 无产物 | 保留 |

## 8. 伴生文件

| 文件 | 格式 | 内容 |
|---|---|---|
| `<name>.iso.sha256` | 单行文本：`<hex> *<name>.iso` | 兼容 `sha256sum` 校验（两空格 + 星号 binmode） |
| `<name>.readme.txt` | UTF-8 纯文本 | build/revision/语言/edition、关键选项摘要、工具与转换器版本、生成时间、任务 id |
| `<name>.manifest.json`（可选） | JSON | 文件清单（路径/大小/SHA256），用户在输出页勾选时生成 |

- 伴生文件与产物**同一提交语义**：先写 `sidecar\`，再逐个 rename；产物 rename 成功但伴生失败 → 记 `WARN sidecar_failed`，不阻断（产物本身有效），并在 UI 提示「哈希文件生成失败」。
- 多分卷 SWM：为每个分卷各生成一个 `.sha256`，并在 readme 中列出全部分卷。

## 9. 日志联动

新增事件（均按 `日志规范.md` 行格式，键值对形式）：

| 事件 | 关键字段 |
|---|---|
| `output_staged` | `task`、`stage`、`output_name`、`expected_size` |
| `output_validated` | `level`（1/2/3）、`result`、`duration`、`sha256` |
| `output_committed` | `final`（最终路径）、`size`、`duration`、`sha256` |
| `output_aborted` | `reason`、`residual`（暂存路径）、`exit` |
| `output_name_collision` | `strategy`、`final` |
| `output_cross_volume_rejected` | `staging`、`output` |
| `staging_residual_detected` | `state`、`path`、`age_hours` |
| `staging_cleaned` | `reason`（`user`/`resolved`）、`path` |

进度不落盘；`oscdimg` 百分比、`wimlib verify` 百分比只进进度通道。

## 10. 验收标准

1. 正常流程结束后：输出目录只有最终产物与伴生文件，`.uup2iso-tmp\<task_id>` 已不存在。
2. **校验失败**（故意把 `install.wim` 截断）：最终目录**无**产物、无伴生；暂存保留；退出码 2；日志有 `output_aborted`。
3. **写入中强杀**：重启后只检查最近 10 个任务即可发现残留并提示三选；选「删除」后目录清空并记 `staging_cleaned`。
4. **rename 后强杀**（`state=committing`）：重启检测到最终文件 SHA256 与记录一致 → 自动补伴生并清理，不重复提交、不产生第二份产物。
5. **同名**：连续两次相同配置输出 → `name.iso`、`name_1.iso`；`overwrite` 策略下必须二次确认并留下审计事件。
6. **空间预检**：输出卷仅剩 1 GB 时启动 → 在写入前失败，退出码 4，提示「需要 X GB / 可用 1 GB」，且不创建暂存区。
7. **ISO 校验**：可挂载、四个引导文件与 `setup.exe` 齐全、`sources\install.*` 存在、卷标与请求一致。
8. **SWM**：缺任一分卷即判 L1 失败；全卷齐全时 L2 能读出分卷数。
9. **深度校验**：未勾选 L3 时日志中不出现 `wimlib verify` 调用；勾选后出现且记录耗时。
10. **`--dry-run`**：不创建暂存区、不写伴生、不动输出目录。
11. **跨卷防护**：把暂存目录手工指到另一块盘 → 输出阶段前拒绝并报 `OUTPUT_CROSS_VOLUME`。
12. **续跑**：篡改已完成阶段的中间产物（改一个字节）→ 该阶段被判重做，而不是复用。

## 11. 开放问题

- [ ] 输出卷空间系数 1.05 需实测校准（`oscdimg` 可能先写临时文件再落盘，峰值高于最终大小）。
- [ ] 提交成功后是否自动打开输出目录（GUI 便利性 vs 打扰）。
- [ ] 多分卷 SWM 是否额外生成一个汇总清单文件（当前为每卷一个 `.sha256` + readme 列举）。
- [ ] `readme.txt` 是否记录完整的精简/优化项列表（利于复现，但可能过长）。
- [ ] 暂存区是否需要设总量上限（防止多次中断累积占用输出盘）。
