# UUP2ISO 集成规范

> 版本：v0.1
> 依据：`需求分析.md` FR6（集成：离线更新 / 驱动 / 语言包 / 注册表）
> 配套：`精简与优化规则规范.md`（同一挂载与失败语义）、`预设与配置契约规范.md`（`integrate` 配置）、`映像引擎与转换规范.md`（DISM 挂载与错误码）、`输出校验与原子性规范.md`
> 优先级：本文与其它文档中关于「更新怎么排序、驱动怎么冲突、语言包怎么搭配、失败怎么回滚」的描述冲突时，**以本文为准**。

---

## 1. 目的与边界

| 在范围内 | 不在范围内 |
|---|---|
| 离线更新（msu/cab）的识别、排序、适用性判定 | 从网络检索更新（本工具不做，见 §3） |
| 驱动扫描、签名校验、冲突处理 | 驱动开发与数字签名本身 |
| 语言包 / LIP / FOD 的组合校验 | 无人值守设置（见 S7） |
| 注册表导入（离线 hive） | 优化规则库的注册表写入（见 S5） |
| 集成失败的回滚粒度 | 精简与优化（FR4/FR5） |

**风险前提**：集成直接修改映像的成分结构（包、驱动库、语言资源），一旦「集成了一半」，系统可能在安装或首次启动时失败。因此本阶段的可接受失败模式是**整体丢弃**，不是部分保留。

## 2. 集成项模型

`TaskConfig.integrate`（结构对齐 S3 的配置契约）：

```json
{
  "updates":  { "paths": ["D:\\Updates"], "recursive": true, "order": "auto" },
  "drivers":  { "paths": ["D:\\Drivers"],  "recursive": true, "requireSignature": true,
                "conflict": "newerVersion" },
  "language": { "add": ["zh-CN"], "remove": [], "fod": ["Language.Basic~~~zh-CN~0.0.1.0"] },
  "registry": { "imports": ["D:\\Tweaks\\lab.reg"] }
}
```

| 子项 | 必填 | 说明 |
|---|---|---|
| `updates.paths` | 否 | 目录或单个文件；目录按 `recursive` 扫描 `.msu`/`.cab` |
| `updates.order` | 否 | `auto`（按 §3.2 分类排序，默认）/ `user`（按用户给定顺序） |
| `drivers.paths` | 否 | 目录集合；`requireSignature=true` 时跳过未签名驱动 |
| `drivers.conflict` | 否 | `newerVersion`（默认，按 DriverVer 新者优先）/ `lastWins`（按扫描顺序后者覆盖） |
| `language.add` / `remove` / `fod` | 否 | 语言代码与能力名；组合校验见 §5 |
| `registry.imports` | 否 | `.reg` 文件；目标 hive 由内容推断（见 §6） |

- 全部子项为空 → 阶段 `skipped reason=no_options`。
- 路径解析遵循配置规范 §6（相对配置文件目录）。

## 3. 离线更新（已决策 D1：仅用户提供）

### 3.1 输入与前置

- 只接受本地 `.msu` / `.cab`（及解包后的包目录）；**不联网检索、不自动下载**。
- 扫描时排除：`Windows10*.exe` 等安装器、`.psf` 伴随文件（随 msu 处理，不单独集成）。
- 前置检查（挂载前尽可能完成）：
  1. 文件可读、扩展名与魔数一致（msu 为 CAB 容器）；
  2. 架构匹配（包名或元数据含 `amd64`/`arm64` 与映像一致）；
  3. 与映像构建号的可适用性（无法离线判定时留到挂载后按错误码处理，见 §3.4）；
  4. 重复项（同名同大小）去重并记 `WARN update_duplicate`。

### 3.2 排序（`order=auto`）

| 优先级 | 类别 | 识别依据 | 说明 |
|---|---|---|---|
| 1 | **SSU**（服务堆栈） | 包名含 `ServicingStack` | 必须先于 LCU，否则 LCU 可能报依赖缺失 |
| 2 | **LCU**（累积更新） | 包名含 `Cumulative Update` 或 KB 号 | 同批次多个 LCU 按 KB 号升序 |
| 3 | .NET / 其他功能包 | 其余 | 按包名字典序 |
| 4 | 用户显式顺序（`order=user`） | — | 完全按给定顺序，仍做 §3.3 的依赖提示 |

- 排序结果写入报告，用户可在执行前查看（GUI 集成页展示顺序）。

### 3.3 依赖与冲突

- 若同一 KB 的 LCU 与 SSU 同时提供 → 按 SSU → LCU 顺序，不视为冲突。
- 若提供了比映像更新的 SSU 与旧 LCU → 允许（DISM 会判定），失败按 §3.4 处理并提示「可能需更新 SSU」。
- 同一 KB 的 msu 与解包 cab 同时存在 → 去重（保留 msu），记 `WARN update_duplicate_kind`。

### 3.4 失败与错误码映射

| DISM/工具返回 | 含义 | 处理 |
|---|---|---|
| `0x800f081e` | 包不适用于该映像 | 记 `ERROR` 并**判阶段失败**（用户需换包） |
| `0x800f081f` | 缺少源文件/依赖 | 阶段失败，提示检查 SSU 或包完整性 |
| `0x800f0906` | 无法下载所需文件（离线环境下常见） | 阶段失败，提示「该更新需要联网组件，当前离线集成不支持」 |
| `0x80070490` | 未找到元素（包已存在/已集成） | 视为成功（`already_present`），记 `WARN` |
| `0x800f0922` | 空间不足 | 阶段失败，给出所需空间 |
| 其他非 0 | 未知 | 阶段失败，保留原始码与最后 20 行输出 |

## 4. 驱动注入（已决策 D2：递归 + 签名校验 + 冲突提示）

### 4.1 扫描

- 递归遍历 `drivers.paths`，收集 `*.inf`（不区分目录层级）。
- 排除：`*.inf` 位于 `WinPE`/`WinRE` 专用子目录且 `applicable` 不匹配的，记 `WARN driver_skipped_scope`。
- 每个 INF 解析：`Provider`、`DriverVer`、`HardwareID`（`Models` 段）、`Class`、`CatalogFile`。

### 4.2 签名校验（`requireSignature=true` 默认）

- 使用 WinVerifyTrust 校验 `.cat`/`.sys` 签名链；无 `.cat` 或无签名 → **跳过该驱动包**并列入报告（`skipped reason=unsigned`），**不阻断阶段**。
- 签名有效但证书已吊销 → 跳过并列入报告（`reason=revoked`）。
- 用户显式设 `requireSignature=false` 时允许注入未签名驱动，但必须二次确认 + 审计事件（`destructive_op reason=unsigned_driver`）。

### 4.3 冲突处理（`conflict=newerVersion` 默认）

- 同一 `HardwareID` 出现多个驱动 → 比较 `DriverVer`：**较新者优先**；版本相同时按扫描顺序后者覆盖，记 `WARN driver_conflict hardwareId=<id> kept=<inf> dropped=<inf>`。
- `conflict=lastWins` 时完全按扫描顺序，仅提示不比较版本。
- 冲突结果写入报告，GUI 驱动页展示「N 个硬件存在多驱动，已选 X」。

### 4.4 注入与验证

- 注入：`DISM /Add-Driver /Driver:<dir> /Recurse`（目录方式）或逐 INF（需要精细控制时）。
- 验证：`DISM /Get-Drivers` 中存在对应 `Published Name`/`Original Name`；抽样校验 3 个硬件 ID 的驱动已注册。
- 引导关键驱动（存储/键盘/网卡）单独标记，报告中标 `bootCritical=true`，便于排查「装完找不到硬盘」。

## 5. 语言包 / LIP / FOD（已决策 D3：严格校验组合）

### 5.1 三类资源的关系

| 类型 | 形态 | 依赖 |
|---|---|---|
| **LP**（语言包） | `.cab`，`/Add-Package` | 无（基础） |
| **LIP**（语言界面包） | `.cab`，`/Add-Package` | **必须先有对应 LP** |
| **FOD**（按需功能） | 能力包，`/Add-Capability` | 通常需要对应语言的 LP |

### 5.2 合法组合校验（挂载前执行）

| 操作 | 前提 | 不满足时 |
|---|---|---|
| 添加 LIP `xx-YY` | 已添加或映像自带 `xx-YY` 的 LP | **阻断**：`INTEGRATE_LANG_INVALID`，提示「缺少基础语言包」 |
| 添加 FOD | 对应语言 LP 存在 | 阻断并说明 |
| 移除 LP | 该语言**不是**当前 UI 语言、不是默认语言，且移除后至少保留 1 个 LP | 阻断并说明原因（当前 UI 语言不可移除） |
| 移除 LIP/FOD | 无额外前提 | 允许，记 `WARN` |

- 当前 UI 语言判定：读取离线映像的 `UILanguage`（`HKLM\SYSTEM\CurrentControlSet\Control\Nls\Language` 与 `intlcfg` 结果），与用户请求对比。
- 校验失败在**挂载前**完成，避免挂载后才发现不可行（节省 10+ 分钟）。

### 5.3 验证

- `DISM /Get-Intl` 的语言列表包含新增语言；
- `DISM /Get-Capabilities` 包含新增 FOD；
- 抽样校验：`intlcfg` 输出中默认 UI 语言符合预期。

## 6. 注册表导入

- 输入：`.reg` 文件（UTF-16LE 带 BOM 或 ANSI；按 BOM/首字节判定编码，无法判定按 ANSI 并记 `WARN reg_encoding_assumed`）。
- 目标 hive 由键路径推断：`HKLM\SOFTWARE` → 离线 `SOFTWARE`；`HKLM\SYSTEM` → `SYSTEM`；`HKCU`/`NTUSER` → `Users\Default\NTUSER.DAT`；无法映射 → **拒绝该文件**并说明。
- 与规则引擎的写入冲突：执行顺序为 **精简/优化规则（S5）→ 集成注册表（本节）**，后者覆盖前者并记 `WARN reg_override rule=<id> file=<reg>`（用户显式导入优先，但必须可见）。
- 验证：`reg query`（加载离线 hive 后）确认关键值存在且类型正确。

## 7. 执行顺序与挂载契约

```
挂载（ReadOnly=false）
  → updates（按 §3.2 顺序）
  → drivers（§4）
  → language（§5）
  → registry（§6）
  → verify（各类验证）
  → 卸载并提交（全部通过） / 丢弃（任一失败）
```

- 挂载、卸载、残留清理遵循引擎规范 §7；取消遵循编排规范 §8。
- 每类子步骤完成即写检查点（`updates` / `drivers` / `language` / `registry`），续跑按子步骤跳过（编排规范 §3）。

## 8. 失败与回滚（已决策 D4：阶段级整体回滚）

| 情形 | 处理 |
|---|---|
| 更新失败（不可恢复码） | 记 `ERROR` → **丢弃挂载**，阶段失败，退出码 2 |
| 更新「已存在」 | 视为成功（`already_present`），继续 |
| 驱动未签名 | **跳过**该驱动（不失败），列入报告；阶段继续 |
| 驱动注入失败（有效签名但 DISM 报错） | 阶段失败并丢弃（可能影响启动） |
| 语言组合不合法 | 挂载前阻断（阶段未开始），退出码 4 |
| 注册表映射失败 | 跳过该文件并列入报告；若用户要求严格（`integrate.registry.strict=true`）则阶段失败 |
| 验证失败 | 按对应子项处理；`updates`/`drivers` 验证失败 → 阶段失败 |

- 丢弃语义：`DISM /Unmount-Image /Discard`，映像回到挂载前状态；镜像文件的修改时间不变（可用哈希核对）。
- **不做部分提交**：集成属于结构性修改，「一半成功」比「完全失败」更难排查。

## 9. 报告：`integrate-report.json`

```json
{
  "taskId": "7f3a1c02",
  "stage": "Integrate",
  "updates": [
    { "file": "windows11.0-kb5043080-x64.msu", "class": "LCU", "status": "applied", "verify": "pass" },
    { "file": "ssu-26100-1.msu", "class": "SSU", "status": "applied" }
  ],
  "drivers": { "scanned": 128, "injected": 121, "skipped": 7,
               "skippedReasons": { "unsigned": 6, "revoked": 1 },
               "conflicts": 3 },
  "language": { "added": ["zh-CN"], "removed": [], "fod": ["Language.Basic~~~zh-CN~0.0.1.0"] },
  "registry": [ { "file": "lab.reg", "hive": "SOFTWARE", "status": "applied" } ],
  "result": "succeeded"
}
```

- 驱动跳过清单必须含文件名与原因（用户最常问「为什么我的驱动没进去」）。
- 报告随任务保留，直到任务记录被清理。

## 11. 验收标准

1. **更新排序**：同时提供 SSU 与 LCU（文件名顺序打乱）→ 实际执行顺序为 SSU → LCU，`integrate-report.json` 的 `class` 正确。
2. **不适用包**：放入一个不适用于该构建的 LCU → 阶段失败并报 `0x800f081e`，挂载被丢弃（镜像哈希不变）。
3. **已存在包**：重复集成同一 LCU → 第二次 `already_present`，阶段不失败。
4. **离线依赖**：使用需要联网组件的更新 → 报 `0x800f0906` 并提示「当前离线集成不支持」，阶段失败。
5. **驱动递归**：多层目录（`Drivers\Net\Intel\x64\*.inf`）→ 全部扫描到，`scanned` 计数与目录内 INF 数一致。
6. **未签名驱动**：放入一个未签名 INF → 被跳过并列入 `skippedReasons.unsigned`，阶段**成功**。
7. **驱动冲突**：同一 HardwareID 两个不同版本的驱动 → 保留版本较新者，`conflicts=1` 且报告含 `kept`/`dropped`。
8. **语言组合**：只加 LIP 不加 LP → **挂载前**阻断 `INTEGRATE_LANG_INVALID`，退出码 4，未发生挂载。
9. **移除当前 UI 语言**：请求移除 `zh-CN` 且当前 UI 为 `zh-CN` → 阻断并说明原因。
10. **注册表映射**：提供含 `HKCU` 的 `.reg` → 目标为 `Users\Default\NTUSER.DAT`；提供 `HKCR` 等无法映射的键 → 该文件被拒绝并说明。
11. **注册表覆盖可见**：优化规则写入 `DisableSR=1`，集成 `.reg` 写 `DisableSR=0` → 最终为 0 且日志有 `reg_override`。
12. **阶段级回滚**：集成到一半时人为让驱动注入失败 → 挂载丢弃，`install.wim` 哈希与集成前一致，退出码 2。
13. **续跑**：驱动子步骤完成后强杀 → 续跑从 `language` 开始，`drivers` 标 `reused`，不重复注入。
14. **空配置**：`integrate` 全空 → 阶段 `skipped reason=no_options`，不挂载。

## 12. 开放问题

- [ ] 是否需要「更新包适用性预检」（不挂载就判断 KB 是否适用于该构建），可省一次挂载。
- [ ] 驱动 `bootCritical` 的判定依据（Class 白名单 vs 实测），以及是否需要在报告里强制突出。
- [ ] 语言包移除后是否需同步清理 `intlcfg` 与 WinRE 语言资源（当前只做 LP/LIP 层面）。
- [ ] 注册表导入是否支持 `.inf` 形式的 `AddReg`（当前仅 `.reg`）。
- [ ] 是否需要「集成预演」：只解析并列出将发生的变更（包/驱动/语言/注册表条数），不实际修改。
