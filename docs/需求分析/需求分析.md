# UUP2ISO 需求分析

> 版本：v0.18（草案）
> 技术栈：Python 3.12+（PySide6 GUI / PyInstaller 打包），仅 Windows 10/11 x64
> 映像内核：DISM + wimlib-imagex 混合（均为外部进程调用，与语言无关）

---

## 1. 项目背景与目标

### 1.1 背景

从微软 UUP（Unified Update Platform）渠道获取 Windows 安装文件并转换成 ISO，目前需要组合多款工具：

- **UUP dump** 负责获取构建清单与生成下载/转换脚本（内含 `uup-converter-wimlib`）；
- **UUP Media Creator** 负责下载与构建 ISO；
- **Tiny11 Builder / MSMG Toolkit / NTLite** 负责镜像精简、集成与无人值守定制；
- **DISM++** 负责离线空间回收、系统优化（tweak）与映像管理。

流程割裂、依赖大量脚本与手工步骤，普通用户门槛高。

### 1.2 目标

打造一体化工具 **UUP2ISO**：从 UUP 下载 → 解包/转换 → 组装 ISO → 精简/优化/集成/无人值守定制，形成一条可配置、可复用、可脚本化的流水线。

核心价值：**从微软原始 UUP 文件直接产出可定制、可直接安装的 ISO**，无需手工分步执行多个脚本。

---

## 2. 参考工具与实现原理对比

| 工具 | 定位 | 核心实现原理 | 借鉴点 |
|---|---|---|---|
| **UUP dump** | Web 服务 + 下载脚本生成器 | 调用 `api.uupdump.net` 获取构建/语言/版本清单；生成含 `files` 清单（sha1/size/url）、`ConvertConfig.ini`、`aria2c` 下载脚本、`uup-converter-wimlib` 转换包的 zip | 数据源 API、下载清单格式、转换参数模型 |
| **UUP Media Creator** | .NET 下载 + 构建器（GUI/CLI） | 直接调用微软 UUP API，内置解压与 PSF 差分应用逻辑，构建 `install.wim/esd` 与 ISO，可跨平台 | 不依赖完整 ADK、模块化构建流程、.NET 实现参考 |
| **Tiny11 Builder** | PowerShell 精简脚本 | 基于官方 ISO 挂载 `install.wim`（DISM），移除 Appx/Edge/Teams/OneDrive/WinRE，绕过 TPM/SecureBoot/RAM 检查，`oscdimg` 重新封装 | 精简清单、绕过硬件检查策略 |
| **MSMG Toolkit** | 批处理工具箱 | DISM 按包名移除组件、集成更新/驱动/语言包、定制、打包 ISO | 组件移除模型、集成流水线、包依赖矩阵 |
| **DISM++** | 免费 GUI 映像工具 | 离线挂载映像，空间回收（清理 WinSxS/缓存）、系统优化（注册表 tweak 分组）、CompactOS、集成与应答文件编辑 | 优化项分类与交互、空间回收清单、优化项风险提示 |
| **NTLite** | 商业 GUI | 图形化加载 wim/esd，集成/移除/优化/tweak、unattend、压缩、ISO 生成 | 交互设计、功能菜单划分、任务预设 |

### 2.1 共同技术底座

- **WIM/ESD 操作**：DISM 或 wimlib-imagex
- **映像挂载/提交**：DISM 挂载，或 wimlib 直接读写 WIM
- **ISO 封装**：`oscdimg`（ADK）或 `xorriso`
- **UUP 特有**：CAB 解包、PSF 差分（Patch Storage File）、ESD 解密/重建

## 3. 目标用户与使用场景

| 用户 | 场景 |
|---|---|
| 普通用户 | 一键下载最新 Win10/11 并生成 ISO，自动绕过硬件限制 |
| 进阶用户 | 精简预装应用、系统优化（tweak/空间回收）、集成驱动/更新/语言包 |
| 已有镜像用户 | 使用本地 UUP 文件夹或现成 ISO/WIM/ESD，跳过下载，仅做精简/优化/定制 |
| 运维/批量 | 最小 CLI（配置驱动）+ 配置文件夹，批量产出定制镜像与无人值守安装介质 |

## 4. 范围

### 4.1 In Scope（首期）

- 多入口：在线 UUP 构建（全流程）/ 本地 UUP 文件夹（从转换开始）/ 现成 ISO/WIM/ESD（从精简/优化、定制开始）
- UUP 构建发现与下载（数据源地址可配置，默认 `https://uupdump.net/`）
- ESD/WIM 重建与转换（对齐 `uup-converter-wimlib` 流程与选项）
- ISO 组装（UEFI/BIOS 双启动）
- 精简（Appx/组件/硬件检查）
- 系统优化（空间回收/注册表 tweak/CompactOS，对齐 DISM++）
- 集成（更新/驱动/语言包）
- 无人值守文件生成
- 输出校验、配置、设置与日志

### 4.2 Out of Scope

- 在线激活、正版授权校验
- 内置任何绕过授权的逻辑
- 驱动库商业化
- 产品内置虚拟机创建、启动和自动安装编排；开发与发布验收可以使用外部虚拟机环境
- 在线规则库自动更新（后续版本仅支持经过校验的手动规则包导入）

## 5. 功能需求

> 约定：每条需求给出编号、描述、输入/输出、关键约束与验收标准。
> 优先级：**P0** MVP 必须；**P1** 二期必须；**P2** 三期及以后。
> 涉及外部工具的以反引号标注。
> **参考实现**：转换流程与选项对齐 `uup-converter-wimlib`（UUP dump 下载包内置脚本）；系统优化对齐 **DISM++**。
> **逐项细化**：FR3/FR4/FR5 每个选项与项的**描述与实现方式**见 `docs/FR3-FR5详细需求.md`。

### FR0 输入源与流水线入口

**目标**：流水线**不是固定从「在线选择构建」开始**；按输入类型选择起始阶段，并复用后续的定制与输出能力。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR0.1 | 显式选择输入源与起始阶段 | P0 |
| FR0.2 | 入口 A：在线 UUP 构建（全流程） | P0 |
| FR0.3 | 入口 B：本地 UUP 文件夹（从 FR3 转换开始） | P1 |
| FR0.4 | 入口 C：现成映像 ISO/WIM/ESD（先识别/准备，再从 FR4/FR5/FR7 开始） | P1 |
| FR0.5 | 输入识别与兼容校验 | P1 |

| 入口 | 输入 | 起始阶段 | 执行流程 |
|---|---|---|---|
| **A 在线构建** | 数据源构建选择 | FR1 | FR1 → FR2 → FR3 → FR4/FR5 → FR7 → FR8 |
| **B 本地 UUP 文件夹** | 已下载的 UUP 文件目录（含清单 / `ConvertConfig.ini`） | FR3 | FR3 → FR4/FR5 → FR7 → FR8 |
| **C 现成映像** | `.iso` / `.wim` / `.esd` | FR4/FR5/FR7 | FR4/FR5 → FR7 → FR8（必要时先解包/挂载） |

- **FR0.1**：GUI 向导首页须先声明输入源（CLI 通过 `TaskConfig` 声明，见 FR9.2）；起始阶段由输入类型自动推断，也可手动指定更靠后的阶段（如仅对现有 ISO 做定制）。
- **FR0.2 入口 A**：等价现有 FR1–FR2，联网获取构建与文件。
- **FR0.3 入口 B**：**跳过 FR1/FR2 从 FR3 开始**，直接读取本地 UUP 文件夹的文件清单与 `ConvertConfig.ini` 进入转换；离线可用；缺文件或哈希不符时明确报错。
- **FR0.4 入口 C**：先执行 `DetectInput` 和 `PrepareImage`。`.iso` 解包并定位其中的 `install.wim/esd`，`.wim`/`.esd` 直接准备；随后按用户选择执行 FR4、FR5、FR6、FR7，再按 FR8 重新封装 ISO（或保留 wim/esd）。不支持的加密 ESD、多分卷 SWM 或第三方封装必须明确拒绝或标记为实验性能力，不得静默处理。
- **FR0.5**：自动识别输入类型与内容（映像 edition 列表、是否加密/多分卷、是否含 `install.wim/esd`）；识别失败给出指引；不支持的输入（非 Windows 映像）拒绝并说明原因。
- **阶段编排与续跑**：8 个固定阶段（Prepare/Fetch/Convert/Slim/Optimize/Integrate/Unattend/Output）+ 阶段内**子步骤检查点**；可重试错误白名单与阶段级 2 次兜底；取消保留中间产物；`--resume` 按「配置指纹 + 输入指纹 + 完成标记 + 产物哈希」四条件复用。详见 **`docs/需求分析/任务编排与续跑规范.md`**。
- **验收标准**：
  - 在已支持的输入样本范围内，三个入口均可走到 FR8 产出可用 ISO；入口 B/C 无需 UUP 网络即可离线完成。
  - 能对现有 `.iso` / `.wim` / `.esd` 仅执行精简/优化/定制后重新打包。
  - 输入类型识别错误或文件缺失时给出明确错误，不产出半成品。

### FR1 数据源与构建发现

**目标**：以统一模型描述可下载的 Windows 构建，并提供稳定、可配置的数据源查询能力。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR1.1 | 按条件枚举构建列表 | P0 |
| FR1.2 | 展示构建详情与可用版本 | P0 |
| FR1.3 | 生成下载文件清单 | P0 |
| FR1.4 | 数据源地址可配置（默认 `https://uupdump.net/`） | P0 |
| FR1.5 | 数据源抽象与备用地址回退 | P1 |
| FR1.6 | 本地清单缓存 | P2 |

- **FR1.1 构建枚举**
  - 输入：通道（retail / beta / dev / canary）、架构（默认 x64）、语言（zh-cn、en-us …）、版本（Home / Pro / Pro for Workstations / Edu / Enterprise …）、关键字。
  - 输出：构建列表，元素含 `build`、`revision`、`channel`、`arch`、发布时间、是否含 `UpdateBuildRevision`。
  - 约束：仅展示可成功生成 ISO 的受支持通道；网络失败需给出可读错误而非空列表。
- **FR1.2 构建详情**：展示 Build 号、发布时间、关联 KB 号、支持结束日期、可用语言集合、可用版本（edition）集合。
- **FR1.3 下载清单**：选定构建 + 语言 + 版本后生成文件清单（`files`：文件名 / 大小 / SHA1 / URL）及转换配置（复用 UUP dump 的 list id 机制），可直接投喂 FR2。
- **FR1.4 数据源地址配置**
  - 在**设置**中提供数据源网址项，默认值 `https://uupdump.net/`；用户可改为自建或兼容 UUP dump API 的镜像地址。
  - 保存前校验地址可用性（探测 API 端点/握手），失败给出提示并允许一键回退默认。
  - 该地址属于全局设置（FR10.4），可被任务配置覆盖；优先级：**任务配置 > 全局设置**（CLI 不提供字段级覆盖，见 FR9.2）。
- **FR1.5 数据源抽象与回退**：经 `IUupSource` 抽象；主地址不可用时按配置的备用地址列表回退；源能力（是否支持 list id）需能力探测。
- **FR1.6 缓存**：构建/清单本地缓存（含 TTL），离线时可复用，避免重复查询。
- **验收标准**：
  - 默认地址下能查询到当前 retail 与 Insider 通道最新构建，并正确列出简体中文、英文版本。
  - 修改数据源地址为镜像站后能正常查询；地址无效时给出明确提示且不崩溃。
  - 断网时给出明确错误；有缓存时可离线展示上次结果。
  - 生成的清单可被 FR2 无人工修改直接下载。

> **字段兼容与缓存（已决策）**：区分必需/可选字段——必需字段（构建号/语言/edition/文件名/大小/SHA1/URL）缺失即失败，可选字段缺失记 WARN，未知字段忽略并记录；构建列表与详情缓存 **10 分钟**，刷新失败时允许使用过期缓存并提示。备用地址按顺序切换。详见 `docs/需求分析/数据源与下载规范.md` §2。

> **输入判定与拒绝（已决策，详见 `docs/需求分析/输入识别与映像准备规范.md`）**：以**文件头嗅探**为主、扩展名为辅（扩展名写错仍按真实类型处理）；同一输入出现多个候选时**不猜**，列出让用户选（`INPUT_AMBIGUOUS`）；**加密 ESD 明确拒绝不解密**、**多卷 SWM 拒绝并给 DISM 合并指引**、**分片/非独立 ESD 拒绝**；入口 C 允许只输出 WIM/ESD 而不封装 ISO；ESD 作为输入时先导出为 LZX WIM 再进入定制阶段。

### FR2 下载（aria2c 专用）

**目标**：**仅**通过 `aria2c` 拉取 FR1.3 生成的清单文件，可靠、可续传、可校验；不再提供内置 HTTP 下载降级路径。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR2.1 | aria2c 专用下载（无降级） | P0 |
| FR2.2 | aria2c 自动获取与校验 | P0 |
| FR2.3 | 断点续传 | P0 |
| FR2.4 | 哈希校验与重试 | P0 |
| FR2.5 | 网络与限速配置 | P1 |
| FR2.6 | 完整性报告 | P1 |

- **FR2.1**：所有 UUP 文件下载**仅**由 `aria2c` 外部进程完成（多连接/分块/续传），不提供自研或 `HttpClient` 的内容下载降级；`aria2c` 缺失或不可用时任务不得开始，交由 FR2.2 获取。
- **FR2.2 aria2c 自动获取**：启动自检（FR10.3）发现缺失时，按设置的下载地址自动获取 Windows x64 版 `aria2c` 到工具目录并做 SHA256 校验；支持指定本地路径/离线内置包；版本可在设置中固定。
- **FR2.3**：断点续传（`aria2c --continue`），中断退出后重启自动续传；下载目录可配。
- **FR2.4**：按清单 SHA1 逐文件校验（先比大小再算哈希）；**网络层**重试交由 `aria2c`（`--max-tries=3 --retry-wait=2`）；**校验层**（SHA1 不符）由编排层删除坏文件并重下，**最多 2 次**；仍失败进入失败清单并阻断后续阶段，列出期望/实际 SHA1。绝不忽略哈希。
- **FR2.5**：代理（HTTP/SOCKS）、备用 URL、限速（`--max-overall-download-limit`）、分片/连接数（`-x` / `-s` / `-k`）、超时与重试策略可配。
- **FR2.6**：产出完整性报告（成功/失败/缺失文件、字节数、耗时）与失败清单，供重跑。
- **说明**：`HttpClient` 仅用于获取 JSON 清单与查询数据源 API，**不用于内容文件下载**。
- **实现契约**：清单结构、aria2c 完整参数、进度加权、校验顺序与失败矩阵见 **`docs/需求分析/数据源与下载规范.md`**（该文件优先级高于本节笼统描述）。
- **验收标准**：
  - 未安装 `aria2c` 的干净机器上，任务能自动完成 `aria2c` 获取并通过哈希校验。
  - 中断（强杀进程）后重启可续传，不重复下载已完成文件。
  - 全部文件 SHA1 与清单一致方可进入 FR3；不一致的必须重试或明确失败。

### FR3 转换与 ISO 组装（对齐 uup-converter-wimlib）

**目标**：以 UUP 转换脚本的等价流程与选项，将原始 UUP 文件重建为可安装的 `install.wim/esd` 并封装成标准 ISO。

> 选项命名与语义对齐 `uup-converter-wimlib` 的 `ConvertConfig.ini`，便于用户从 UUP dump 迁移。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR3.1 | CAB/PSF 解包与差分应用 | P0 |
| FR3.2 | 更新集成（LCU/SSU/.NET，转换内置） | P0 |
| FR3.3 | ESD/WIM 转换与压缩 | P0 |
| FR3.4 | 组件清理与 ResetBase | P1 |
| FR3.5 | edition 保留与裁剪 | P1 |
| FR3.6 | NetFx3 启用 / WinRE 处理 | P1 |
| FR3.7 | ISO 组装（UEFI/BIOS 双启动） | P0 |
| FR3.8 | 非交互式运行 | P1 |
| FR3.9 | 现有 ISO/ESD 二次处理 | P2 |

> **转换路线（已决策）**：`install.wim` 由**已验证转换器**（`uup-converter-wimlib`，路线 A）聚合产出，**不自研聚合算法**；媒体骨架与 `sources\boot.wim` 由本工具按实测路径生成（ESD 索引 1 `apply` / 索引 2 `export`）。引擎按操作路由、能力探测失败进入保守模式、工具缺失自动获取与自动更新（默认关闭）见 **`docs/需求分析/映像引擎与转换规范.md`**。

- **FR3.1**：解包 `.cab`（`cabextract` / `7-Zip`），对 `.psf` 应用差分重建原始文件（对应脚本 `cab/psf` 处理）；差分失败需定位到具体缺失块。
- **FR3.2 更新集成（赋值 `AddUpdates`）**：将清单中的 LCU / SSU / .NET 累积更新集成进映像，按依赖顺序应用；本项为**转换内置**，区别于 FR6 中用户额外提供的更新。
- **FR3.3 转换与压缩**：生成 `install.wim` 或 `install.esd`（`DISM /Export-Image` 或 `wimlib-imagex`）；压缩类型 none / XPRESS / LZX / LZMS(recovery) 可选；支持输出 ESD（`wim2esd`）与拆分 WIM（`wim2swm`，`install.swm`）。
- **FR3.4**：可选执行组件清理（`Cleanup`，`DISM /StartComponentCleanup`）与重置基础（`ResetBase`），缩减体积但会阻止回退旧更新。
- **FR3.5**：可从多版本映像中保留指定 edition（如仅 Pro），剔除其余。虚拟版本创建不属于 MVP；只有在针对固定 Windows 构建完成技术验证后才作为实验性能力开放，不得仅通过修改注册表伪造 edition。
- **FR3.6**：可启用 `.NET 3.5`（`NetFx3`）；可更新、跳过或保留 WinRE（`LCUwinre` / `SkipWinRE`）。
- **FR3.7 ISO 组装**：参数含卷标、`oscdimg` 引导文件（`etfsboot.com` + `efisys.bin`）、UDF/ISO9660 选项、双启动；引导文件缺失时提示安装 ADK。
- **FR3.8**：转换全程非交互（等价 `AutoStart`/`AutoExit`），进度上报 GUI/CLI。
- **FR3.9 二次处理（入口 C）**：允许受支持的本机 `.iso` / `.wim` / `.esd` 作为输入，跳过 FR1–FR3，经过 `DetectInput`/`PrepareImage` 后进入 FR4/FR5/FR7 流水线（见 FR0.4）。

**转换选项与 `ConvertConfig.ini` 对应表**

| 转换选项 | uup-converter 配置 | 说明 |
|---|---|---|
| 集成更新 | `AddUpdates` | LCU / SSU / .NET 累积更新 |
| 组件清理 | `Cleanup` | `StartComponentCleanup` |
| 重置基础 | `ResetBase` | 不可再移除旧组件 |
| 启用 .NET 3.5 | `NetFx3` | 离线启用 |
| 输出 ESD | `wim2esd` | LZMS recovery 压缩 |
| 拆分 WIM | `wim2swm` | 生成 `install.swm` |
| 跳过 ISO | `SkipISO` | 仅输出 wim/esd |
| WinRE 处理 | `SkipWinRE` / `LCUwinre` | 保留 / 更新 / 跳过 |
| 仅升级 | `UpgradeOnly` | 生成升级用映像 |
| 虚拟版本 | `vAutoEditions` | 追加可用 edition |

- **验收标准**：
  - 输出 `install.wim` 可被 `DISM /Get-WimInfo` 正确读取且版本信息完整。
  - 生成的 ISO 可在 UEFI 与 BIOS 两种模式引导并进入安装界面。
  - 相同输入下，选项组合能产出与 `uup-converter-wimlib` 等价的结果（wim 版本、更新集成情况一致）。
  - 二次处理现有 ISO 时能正确挂载并读出其 edition 列表。

### FR9 项目 / 配置 / 日志

**目标**：全流程可复用、可脚本化、可诊断。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR9.1 | 任务配置存取 | P1 |
| FR9.2 | CLI（最小命令集，配置驱动） | P1 |
| FR9.3 | 日志与进度 | P0 |
| FR9.4 | 单实例运行（GUI/CLI 互斥） | P0 |
| FR9.5 | 一键打包诊断 | P1 |

- **FR9.1**：全流程（输入源与起始阶段、数据源地址、下载项、转换选项、精简/优化/集成/无人值守预设、输出规则）保存为「任务配置」（JSON/YAML），可加载复用与版本化。**预设以快照内联**（运行时不读预设文件），保证历史任务结果不因预设改动而漂移；配置含 `schemaVersion`、三层校验（语法/Schema/语义）、主版本迁移与 `.bak` 备份、配置指纹（排除路径字段）。详见 **`docs/需求分析/预设与配置契约规范.md`**。
- **FR9.2（最小 CLI）**：CLI 只提供 `run --config <TaskConfig>`、`--dry-run`、`--resume` 与 `version` 四个动作，另加一次性开关 `--debug`；**不提供字段级参数覆盖**——所有业务选项（输入源、数据源地址、下载/转换/精简/优化/集成/无人值守/输出规则）一律写在 `TaskConfig` 中，GUI 保存的配置即 CLI 的输入，保证**单一配置契约**；输出 JSON 结果；退出码 `0/1/2/3/4/5`（`5` = 已有实例运行）。定位：GUI 是主入口，CLI 仅承担「复用已保存配置 + 批处理/CI」场景。
- **FR9.3**：分级日志（Error/Warn/Info/Debug）、实时进度（下载/转换/精简/优化/集成分阶段百分比）、错误详情含外部工具**关键输出**（启动/结束/返回码/警告与错误；进度条与百分比刷新只显示不落盘）。日志位于 **`{程序目录}\logs\`**（便携分发），每次启动一个运行日志；**审计日志独立且进程退出后置只读**。文件模型、级别默认值、三条件清理、审计只读与脱敏规则见 **`docs/需求分析/日志规范.md`**（该文件优先级高于本文中任何笼统表述）。
- **FR9.4**：程序**单实例运行**，GUI 与 CLI 不能并行；冲突时 GUI 激活已有窗口并退出，CLI 输出错误并返回退出码 `5`；冲突实例不创建日志文件、不执行清理（见日志规范 §6）。
- **FR9.5**：GUI 提供**一键打包诊断**：**默认只打包当前任务的日志**（单次任务 = 本次运行；**延续任务** = 该任务全部历史运行日志，按任务索引取文件并逐文件过滤 `task=<id>` 行，保证不漏、不多），另含脱敏设置与任务配置、环境信息、外部工具版本，压缩为单个 zip（含 `manifest.json` 与 SHA256），**纯本地、不上传**；诊断包与运行日志**共用同一套清理阈值**；CLI 不提供该命令（保持最小命令集）。详见日志规范 §7。
- **验收标准**：
  - 同一配置文件在 GUI 与 CLI 产生一致结果（CLI 仅接受配置文件路径与运行开关，不接受字段级覆盖）。
  - `--dry-run` 能列出将要执行的外部命令与文件操作而不实际改动。
  - 失败时日志可定位到具体阶段、文件与外部工具返回码。
  - 每次启动生成独立运行日志，不按功能分文件；日志清理按文件夹大小/天数/文件数三项联合生效，**诊断包计入运行日志清理池**。
  - 审计日志退出后为只读；启动仅对最近 3 个审计文件补设只读（不全量扫描）；清理删除审计时在运行日志留痕。
  - GUI 可一键生成诊断包（断网可用、manifest 校验通过）：单次任务只含本次运行日志，延续任务含该任务全部历史日志且不掺入其他任务；包内不含明文凭据与映像大文件。

  - **工具自动更新（按清单对齐版本）**：开关，**默认关闭**；开启后仅在启动、任务开始前把本地工具对齐到**随包锁定清单**登记的版本（成功保留 `.bak`，失败保留现状并继续）；**不追上游新版本**，哈希只来自随包清单；转换器不参与；
  - **日志清理阈值**：运行日志与审计日志各自的目录总大小 / 保留天数 / 文件数量（默认值见日志规范 §4.2）；日志目录固定为 `{程序目录}\logs`（只读展示，不可改）；日志级别与来源仅只读展示，运行中不可切换；提供「生成诊断包」入口；
  - 代理、并发/限速、输出目录、界面语言、外部工具路径。
  设置持久化存储，任务配置可覆盖（CLI 通过 `--config` 指向任务配置）。
- **验收标准**：
  - GUI 全流程可完成一次「原味 + 安全精简 + 推荐优化」ISO 产出。
  - CLI 单命令（`run --config`）可完成同等流程并返回正确退出码。
  - GUI/CLI 均可选择入口 A/B/C，并对受支持的现有 ISO/WIM/ESD（入口 C）完成定制后重新打包。
  - 在设置中修改数据源地址后即时生效；缺少 `oscdimg` 时明确提示安装 ADK 而非中途失败。

## 7. 技术架构与模块划分

### 7.1 技术选型

- 运行时：Python 3.12+（x64）；发布采用 **PyInstaller 单目录打包**（**便携式**：zip 解压即用，程序/日志/配置/预设/任务/工具同目录；内嵌 Python 解释器，目标机器无需预装 Python）；**PyInstaller 打包代价（体积增大约 60–120MB、冷启动变慢、杀软误报需代码签名缓解）已评估并明确接受**
- 包分层（Python `src/` 布局）：
  - `uup2iso.core`：业务核心（下载、转换、定制流水线）
  - `uup2iso.cli`：最小命令行入口（配置驱动：`run --config` / `--dry-run` / `--resume` / `--debug` / `version`，见 FR9.2）
  - `uup2iso.gui`：桌面界面（PySide6 + PyQt-Fluent-Widgets）
- **开发与运行环境约定（强制）**：
  - 本仓库**所有脚本（开发、测试、构建、打包、自动化代理）一律在工作空间根目录的虚拟环境 `.venv` 中运行**，不得使用系统 Python 主环境；
  - 首次初始化：`python -m venv .venv`；此后统一以 `.venv\Scripts\python` 执行一切命令（安装：`.venv\Scripts\python -m pip install -e ".[dev]"`；测试：`.venv\Scripts\python -m pytest`；打包：`.venv\Scripts\python -m PyInstaller ...`）；
  - 禁止任何形式的全局 `pip install` 或绕过 `.venv` 直接运行脚本；
  - 依赖统一声明于 `pyproject.toml`，锁定文件随仓库提交，保证跨机复现。
- 映像内核：**DISM + wimlib-imagex 混合**，抽象为 `IImageEngine` 接口，按能力路由
  - 转换/组装 → `wimlib-imagex`
  - 精简/优化/集成/组件移除 → `DISM`
- 下载：**仅** `aria2c`（随包分发，或首次运行按设置获取）；HTTP 客户端（`httpx`）只用于获取清单与调用数据源 API
- ISO 封装：优先使用随包提供的兼容封装器；若采用 ADK `oscdimg`，检测后给出明确提示
- 数据源：UUP dump 兼容 API，**地址可配置**（默认 `https://uupdump.net/`），经 `IUupSource` 抽象
- 转换选项：对齐 `uup-converter-wimlib` 的 `ConvertConfig.ini`
  - 优化引擎：参考 DISM++（空间回收 / 注册表 tweak）；CompactOS 与服务预置按执行上下文隔离

### 7.2 模块分层

```
GUI / CLI (前端)
      │
应用编排层 Orchestrator (任务 / 流水线 / 预设)
      │
┌─────────┬──────────┬──────────┬──────────┬─────────┐
│ UUP源   │ 下载器   │ 转换引擎 │ 定制引擎 │ 输出器  │
│ API/清单│ aria2c   │cab/psf/  │ 精简/优化│ oscdimg │
│ 地址可配│ 校验/续传│esd/wim   │ 集成/无人│         │
│         │          │(uup脚本) │ 值守     │         │
└─────────┴──────────┴──────────┴──────────┴─────────┘
      │
外部工具适配层: wimlib-imagex / DISM / 7-Zip / cabextract / aria2c / oscdimg
      │
配置与日志 (JSON + 设置 + 日志)
```

### 7.3 关键接口（示意）

- `IUupSource`：构建查询、生成下载清单（基址可配置，默认 `https://uupdump.net/`）
- `IDownloader`：走 `aria2c` 下载、校验、续传、aria2c 获取
- `IImageEngine`：挂载/卸载、导出/转换、应用包、移除包、集成
- `IOptimizer`：空间回收、注册表 tweak、CompactOS、服务预置（参考 DISM++）
- `IIsoBuilder`：ISO 封装
- `IPresetStore`：精简/优化/集成/无人值守预设存取
- `ISettings`：全局设置（数据源地址、aria2c 获取、代理、输出目录等）

## 8. 数据流与流水线

任务由「输入源 + 起始阶段 + 各阶段选项」定义（见 FR0）。阶段不是任意组合，必须经过阶段合法性校验。

```
入口 A（在线 UUP 构建，从 FR1 开始）
  选构建 → 生成文件清单 → aria2c 下载并校验
        → 解包 / PSF 差分 → 组装 install.wim（uup 转换选项）──┐
                                                              │
入口 B（本地 UUP 文件夹，从 FR3 开始）                        │
  读取本地清单 / ConvertConfig → 转换 ───────────────────────┤
                                                              ▼
入口 C（现成 ISO/WIM/ESD）
   DetectInput → PrepareImage（解包 / 挂载 install.wim|esd）→ 精简 / 优化 / 集成
                                        → 生成 unattend.xml / autounattend.xml
                                        → 封装 ISO（或保留 wim/esd）→ 校验输出
```

## 9. 关键实现难点

1. **PSF 差分**：UUP 的 `.psf` 需配合 `.cab` 做差分应用，重建 `install.wim` 是转换成败关键；M0 必须先完成技术 Spike 再冻结实现路线。
2. **ESD 处理**：部分 ESD 需解密/转换（`DISM /Export-Image` 或 wimlib）。
3. **oscdimg 依赖**：属 ADK 组件，需检测与提示安装，并抽象封装层。
4. **组件移除依赖**：包之间存在依赖，移除顺序与可移除性需维护兼容矩阵（参考 MSMG 包列表）。
5. **无人值守 schema**：`unattend.xml` 的 schema 需与构建版本匹配，需校验。
6. **DISM / wimlib 能力差异**：两套引擎行为不完全一致，需能力探测与统一错误模型。
7. **转换选项等价性**：需与 `uup-converter-wimlib` 的 `ConvertConfig.ini` 语义对齐，保证相同输入产出等价结果。
8. **aria2c 自动获取**：下载源（GitHub/镜像）可达性与完整性校验，失败时需给出明确的手动获取指引。
9. **优化项生效**：离线注册表只能覆盖部分键值，部分 tweak（如首次登录行为）需结合 `FirstLogonCommands`，需双通道实现与验证。
10. **自定义数据源兼容**：用户自定义地址可能 API 版本不一致，需能力探测与降级。
11. **现成映像兼容**：不同来源的 ISO/WIM/ESD 需能力识别、解包/挂载与明确提示；加密 ESD、多分卷 `swm`、第三方封装在验证前不得承诺通用支持。

## 10. 外部依赖与检测策略

| 依赖 | 用途 | 检测/获取 |
|---|---|---|
| `aria2c` | 唯一内容下载器 | 随包分发或首次运行按设置获取，SHA256 校验 |
| `7-Zip` / `cabextract` | 解包 | 随包分发，版本和许可证随发布物提供 |
| `wimlib-imagex` | WIM/ESD 读写、转换 | 随包分发，版本和许可证随发布物提供 |
| `DISM` | 精简、优化、集成、组件移除 | Windows 内置 |
| `oscdimg` | ISO 封装 | 优先使用随包提供的兼容封装器；若采用 ADK `oscdimg`，缺失时明确提示。不得要求用户预装 Python 或 C++ 运行时 |
| UUP dump 兼容 API | 数据源（地址可配置，默认 `https://uupdump.net/`） | 运行时联网 |

启动时进行依赖自检并给出缺失项与安装指引。产品主程序和随包工具必须开箱即用；允许的外部前置仅包括 Windows 自带 DISM，以及用户明确接受的 C++14 运行库。发布包（PyInstaller 产物）必须内嵌 Python 解释器与全部运行时依赖，并包含 7-Zip/wimlib/aria2c 等随包工具及版本、SHA256 和许可证清单。

> 外部进程的**统一执行契约**（工具定位与白名单、版本/能力探测、双路读取与编码回退、`progress/line/result` 分类、取消与静默看门狗、退出码与错误映射）见 **`docs/需求分析/外部工具与进程执行规范.md`**；任何模块不得绕过 `ProcessRunner` 直接创建进程。

## 11. 风险与合规

| 风险 | 缓解 |
|---|---|
| 微软 API/服务器结构变化 | 数据源抽象 + 地址可配置 + 备用地址回退 |
| 自定义数据源地址不兼容/失效 | 保存前可用性校验 + 一键回退默认 |
| aria2c 自动获取失败 | 支持镜像/本地路径/内置包，提供手动获取指引 |
| 第三方工具版本兼容 | 版本锁定与启动自检 |
| 精简过度导致安装失败 | 预设分档 + 结果校验 |
| 优化项（如关 Defender）导致系统异常 | 风险分级 + 高风险项默认关闭 + 显式确认 + 日志记录 |
| PyInstaller 打包体积大 / 冷启动慢 / 杀软误报 | 打包代价已决策接受；单目录模式 + 依赖精简（excludes）+ 代码签名缓解误报 |
| 依赖污染系统 Python 环境 | 强制工作空间 `.venv` 虚拟环境运行；禁止全局 `pip install`；锁定文件随仓库提交 |
| 法律/合规 | 明确仅本地处理、用户自担授权，不内置绕过逻辑 |
