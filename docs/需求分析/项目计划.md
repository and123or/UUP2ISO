# UUP2ISO 项目计划

> 版本：v0.1（草案）
> 依据：`docs/需求分析.md`（FR0–FR10）、`docs/GUI与框架设计.md`、`docs/软件架构图.md`、`docs/软件流程图.md`、`docs/FR3-FR5详细需求.md`
> 说明：**本计划不含工期/排期**。采用「里程碑（M）→ 工作包（WS/WP）→ 任务（T）」的工作分解结构（WBS），排序体现**依赖关系与优先级**，不含时间估算。

---

## 1. 计划说明

### 1.1 组织方式

| 层级 | 含义 | 编号 |
|---|---|---|
| 里程碑 | 可发布的阶段性成果，对齐需求文档「12. 分期里程碑」 | `M0`–`M4` |
| 工作包 | 相对独立的交付单元（对应一个模块或需求域） | `WS0`–`WS11` |
| 任务 | 可执行、可验收的最小工作项 | `WPn-Tm` |

每个任务包含：**描述 / 交付物 / 依赖 / 关联需求 / 验收要点**。

### 1.2 优先级与依赖约定

- 优先级沿用需求文档：**P0**（MVP 必须）、**P1**（二期必须）、**P2**（三期及以后）。
- 依赖以任务编号表示；未列依赖的任务可并行。
- 「完成」的定义（DoD）见 §7。

### 1.3 与需求文档的对应

- 里程碑 M0–M4 与需求文档 §12「分期里程碑」一致（M0 为工程基线，属 MVP 前置）。
- 功能域与 FR 编号一一映射，见 §6 追溯矩阵。

## 2. 项目范围与交付目标

### 2.1 范围（In Scope）

多入口流水线（A 在线构建 / B 本地 UUP 文件夹 / C 现成 ISO·WIM·ESD）；数据源可配、aria2c 专用下载；转换与 ISO 组装（对齐 `uup-converter-wimlib`）；精简（Appx/组件/硬件检查）；系统优化（空间回收/注册表 tweak/CompactOS，对齐 Dism++）；集成（更新/驱动/语言包/注册表）；无人值守定制；输出校验；配置/日志；GUI 向导 + CLI。

### 2.2 范围外（Out of Scope）

在线激活/授权校验、任何绕过授权逻辑、驱动库商业化、虚拟机内自动安装测试。

### 2.3 最终交付物

| 类别 | 交付物 |
|---|---|
| 代码 | `UUP2ISO.sln`：Core / Application / Infrastructure / Gui / Cli + 测试项目 |
| 应用 | GUI 单文件绿色包（x64）、CLI 可执行（含退出码与 JSON 输出） |
| 数据 | 精简/优化规则库（复用 `docs/rules/*.json` + 全量扩充）、内置外部工具（可选） |
| 文档 | 需求/设计/架构/流程/详设/项目计划/用户手册 |
| 质量 | 单元/集成/端到端测试与兼容性矩阵报告 |

## 3. 里程碑总览

| 里程碑 | 主题 | 目标成果 | 对应 FR | 优先级 |
|---|---|---|---|---|
| **M0** | 工程基线与契约 | 解决方案骨架、核心接口、进程/设置/日志/工具基础设施可运行 | FR0/FR9/FR10 前置 | P0 |
| **M1** | MVP | 三入口 CLI 全流程产出「原味」ISO + 设置 + 数据源可配 + aria2c 自动获取；GUI 最小向导 | FR0/FR1/FR2/FR3/FR8/FR9/FR10.2 | P0 |
| **M2** | 二期 | GUI 完整向导；精简；系统优化；预设 | FR4/FR5/FR10.1 | P1 |
| **M3** | 三期 | 集成；无人值守可视化 | FR6/FR7 | P2 |
| **M4** | 四期 | 批处理/CI；CompactOS/服务预置扩展；规则库在线更新；托盘/后台 | FR5.3/5.4 扩展、FR9 | P2 |

> M1 内部先「CLI 优先」，GUI 仅最小闭环；M2 补齐全部向导页面。

## 7. Definition of Done（任务级）

1. 代码通过编译与 lint/分析器，无新增警告。
2. 有对应的单元或集成测试，且在 CI 通过。
3. 关联需求（FR 条目）的**验收标准**全部满足。
4. 外部工具交互经 `ProcessRunner`，进度与原始输出进入日志。
5. 错误路径有明确错误类型与退出码；不产出半成品。
6. 高风险/删除性操作有二次确认与日志留痕。
7. 相关文档（需求/设计/规则库）同步更新。
